# Складність алгоритмів (O-нотація)

Числові приклади перевірені обчисленням.

## 1. Навіщо
Алгоритми порівнюють не за секундами на конкретному комп'ютері, а за тим, **як росте кількість операцій зі збільшенням входу n**. Це математика росту функцій — та сама, що й у розділі про границі.

## 2. Означення O(·)
f(n) = O(g(n)), якщо існують c > 0 та n₀, такі що f(n) ≤ c·g(n) для всіх n ≥ n₀. Тобто g — **верхня оцінка росту**, з точністю до сталого множника й для великих n. Дрібні члени й сталі відкидаємо: 3n² + 100n + 7 = O(n²).
- **Ω(g)** — нижня оцінка; **Θ(g)** — точна (і те, і те).
- Опис «в гіршому випадку» (worst), «у середньому» (average), амортизований.

## 3. Ієрархія класів (від швидкого до повільного)
| Клас | Назва | Приклад |
|---|---|---|
| O(1) | стала | доступ до масиву за індексом |
| O(log n) | логарифмічна | бінарний пошук |
| O(n) | лінійна | прохід по масиву |
| O(n log n) | лінійно-логарифмічна | merge sort, heap sort |
| O(n²) | квадратична | вкладені цикли, bubble sort |
| O(n³) | кубічна | наївне множення матриць |
| O(2ⁿ) | експоненційна | перебір підмножин |
| O(n!) | факторіальна | перебір перестановок |

Скільки кроків при n = 10⁶: log₂ n ≈ 20; n = 10⁶; n log n ≈ 2·10⁷; n² = 10¹²; 2ⁿ — неможливо. При n = 30: 2ⁿ = 1 073 741 824 ≈ 10⁹.
Практичне правило: ~10⁸–10⁹ елементарних операцій за секунду.

## 4. Як рахувати
- Послідовність операцій: складність — максимум.
- Вкладені цикли: множимо. `for i in n: for j in n` → n².
- Цикл, де змінна подвоюється (`i *= 2`) → log n.
- Цикл, де внутрішній залежить від зовнішнього: 1 + 2 + … + n = n(n + 1)/2 = O(n²) (сума арифметичної прогресії; 1 + … + 100 = 5050).
- Рекурсія: **рекурентне співвідношення**.
  - T(n) = T(n/2) + O(1) → O(log n) (бінарний пошук).
  - T(n) = 2T(n/2) + O(n) → O(n log n) (merge sort).
  - T(n) = T(n − 1) + O(1) → O(n).
  - T(n) = 2T(n − 1) + 1 → O(2ⁿ) (Ханойські вежі).
  - **Основна теорема:** T(n) = aT(n/b) + O(nᵈ): якщо d > log_b a → O(nᵈ); d = log_b a → O(nᵈ log n); d < log_b a → O(n^{log_b a}).
- Геометрична сума: n + n/2 + n/4 + … = 2n = O(n).

## 5. Бінарний пошук — чому log n
Кожен крок вдвічі зменшує діапазон: n → n/2 → n/4 → … → 1 за log₂ n кроків. Для 10⁶ елементів — лише ≈ 20 порівнянь (2²⁰ = 1 048 576). Потрібен відсортований масив.

## 6. Сортування
- Квадратичні: bubble, insertion, selection — O(n²).
- Merge sort, heap sort — O(n log n) завжди; quicksort — O(n log n) у середньому, O(n²) у гіршому.
- Нижня межа для порівняльних сортувань — Ω(n log n) (дерево рішень має n! листків, висота ≥ log₂ n!).
- Лінійні (не порівняльні): counting, radix.

## 7. Класи складності P та NP
- **P** — задачі, розв'язувані за поліноміальний час.
- **NP** — розв'язок можна **перевірити** за поліноміальний час.
- **NP-повні** — «найважчі» в NP (SAT, комівояжер, рюкзак, розфарбування графа). Чи P = NP — відкрите питання (премія в $1 млн).
- Для NP-повних на практиці — наближені алгоритми, евристики, обмеження розміру.

## 8. Пам'ять та компроміси
Складність за пам'яттю (space). Часто «час ↔ пам'ять»: мемоізація жертвує пам'яттю заради часу; геш-таблиця дає O(1) пошуку за O(n) пам'яті.
Амортизований аналіз: динамічний масив — додавання O(1) амортизовано (подвоєння ємності: 1 + 2 + 4 + … ≤ 2n).

## Для програміста
- Перед написанням: оцініть n та ліміт часу → оберіть клас складності.
- Вкладений `.includes()` у цикл — прихований O(n²). Заміна на Set — O(n).
- Часто сталі множники мають значення (кеш, пам'ять), але для великих n перемагає асимптотика.

## Типові помилки
1. Вважати O(n) завжди швидшим за O(n²) при малих n (сталі!).
2. Забути приховану складність вбудованих операцій (конкатенація рядків у циклі).
3. Плутати O (верхня) і Θ (точна) оцінки.
4. Не враховувати гірший випадок (quicksort).
5. Рахувати рекурсію без її гілок (дерево викликів).
