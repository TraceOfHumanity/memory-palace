# Регулярні вирази: що це, як працюють і як ними користуватися

Це загальна нотатка про регулярні вирази (regex), усі приклади якої — на **JavaScript**; у кінці — команди для терміналу (`grep`, `sed`, `awk`, `perl`). Деталі саме JavaScript (прапорці, `lastIndex`, `matchAll`, Unicode) — також у [regexp.md](../js/common/regexp.md); тут — як думає рушій, повний синтаксис, відмінності діалектів і практика на реальних текстах.

---

## 1. Що таке регулярний вираз

**Регулярний вираз** — це рядок-шаблон, який описує **множину рядків**. Рушій регулярних виразів перевіряє, чи містить текст підрядок, що відповідає шаблону, і повертає його (збіг, *match*) разом із позицією та вмістом груп.

Навіщо:
- **перевірка формату** (чи схоже це на email, дату, IP);
- **пошук** у тексті, логах, коді (`grep`, Ctrl+F в редакторі);
- **витягування** частин (номери, URL, дати з журналу);
- **заміна** за шаблоном (перейменування, очищення, реформатування);
- **розбиття** тексту на частини (`split`);
- **лексичний аналіз** (токенізація).

Терміни:
| Термін | Сенс |
|---|---|
| pattern | сам шаблон (`\d{4}-\d{2}`) |
| match | знайдений підрядок |
| group | частина шаблону в дужках, значення якої запам'ятовується |
| flag / modifier | перемикач поведінки (`i` — без урахування регістру) |
| engine | програма, що виконує шаблон (V8 Irregexp, PCRE, RE2) |
| anchor | «умова місця», що не споживає символів (`^`, `$`, `\b`) |
| quantifier | скільки разів повторити (`+`, `{2,5}`) |

Регулярний вираз — це **не** повноцінна мова програмування: вкладені структури довільної глибини (HTML, дужки в виразах, JSON) ним коректно не розібрати (див. розділ 19).

## 2. Усі методи регулярних виразів у JavaScript

Це довідник, до якого варто повертатись: спершу — **де** живуть методи, потім — кожен із них із сигнатурою, результатом і пасткою.

### 2.1. Карта: хто що має

| Де | Що | Скільки |
|---|---|---|
| **`RegExp.prototype`** — методи | `exec`, `test`, `toString`, `compile` | 4 |
| `RegExp.prototype` — «символьні» методи (їх викликають рядкові методи) | `[Symbol.match]`, `[Symbol.matchAll]`, `[Symbol.replace]`, `[Symbol.search]`, `[Symbol.split]` | 5 |
| `RegExp.prototype` — властивості-геттери | `source`, `flags`, `global`, `ignoreCase`, `multiline`, `dotAll`, `unicode`, `unicodeSets`, `sticky`, `hasIndices` | 10 |
| екземпляр | власна властивість `lastIndex` (читання й запис) | 1 |
| **`RegExp`** (статичні) | `RegExp.escape`, `RegExp[Symbol.species]`, застарілі `RegExp.$1…$9`, `lastMatch`, `lastParen`, `leftContext`, `rightContext`, `input` | — |
| **`String.prototype`** | `match`, `matchAll`, `replace`, `replaceAll`, `search`, `split` | 6 |

Виміряно: `Object.getOwnPropertyNames(RegExp.prototype)` → `constructor, exec, dotAll, flags, global, hasIndices, ignoreCase, multiline, source, sticky, unicode, unicodeSets, compile, toString, test`; `Object.getOwnPropertySymbols(RegExp.prototype)` → п'ять символів `match`, `matchAll`, `replace`, `search`, `split`.

**Головне правило вибору:**

| Потрібно | Беріть |
|---|---|
| лише так/ні | `re.test(s)` |
| перший збіг із групами й позицією | `re.exec(s)` або `s.match(re)` без `g` |
| усі збіги як тексти | `s.match(re)` з `g` |
| усі збіги з групами й позиціями | `s.matchAll(re)` |
| лише позиція першого збігу | `s.search(re)` |
| замінити | `s.replace(re, …)` / `s.replaceAll(re, …)` |
| розрізати | `s.split(re)` |
| пройти збіги вручну, керуючи позицією | `re.exec(s)` у циклі з `g` або `y` |

### 2.2. `re.test(str)` → `boolean`

Перевіряє, чи є збіг **будь-де** в рядку. Не повертає ні текст, ні групи.

```js
/a/.test('cat')    → true
/a/.test('dog')    → false
/1/.test(1)        → true
/undefined/.test() → true
```

Аргумент **перетворюється на рядок**: `/1/.test(1)` → `true`, а виклик без аргументу перевіряє рядок `'undefined'`. З `g` і `y` метод **змінює `lastIndex`** (див. 2.13): виклики «через раз» дають різні результати. Для перевірки **цілого** рядка потрібні якорі: `/^\d+$/.test(s)`.

### 2.3. `re.exec(str)` → масив збігу або `null`

Основний метод: шукає **один** збіг, починаючи з `lastIndex` (для `g`/`y`) або з 0.

Виміряно: `/(?<k>\w)(\d)?/d.exec('a')`:

| Поле | Значення | Сенс |
|---|---|---|
| `m[0]` | `'a'` | увесь збіг |
| `m[1]` | `'a'` | група 1 |
| `m[2]` | `undefined` | група, що не брала участі |
| `m.index` | `0` | позиція початку |
| `m.input` | `'a'` | вхідний рядок |
| `m.groups` | `{ k: 'a' }` | іменовані групи (немає груп — `undefined`) |
| `m.indices` | `[0, 1]` для `m.indices[0]` | **лише з прапорцем `d`**: позиції `[початок, кінець)` кожної групи |
| `m.indices.groups` | `{ k: [0, 1] }` | позиції іменованих груп |

Немає збігу — `null` (`/x/.exec('a')` → `null`).

З `g`: кожен виклик продовжує з `lastIndex`. Виміряно на `/a/g` і `'aa'`: після першого виклику `lastIndex = 1`, після другого `2`, третій дає `null` і **скидає `lastIndex` у `0`**. Цикл `while ((m = re.exec(s)) !== null)` на цьому й тримається.

### 2.4. `re.toString()` → `'/source/flags'`

`String(/a\/b/gi)` → `/a\/b/gi`. Для `new RegExp('a/b')` слеш екранується: `/a\/b/`. Порожній шаблон: `String(new RegExp(''))` → `/(?:)/`, бо `//` — це коментар. Перенос рядка в `source` показується як `\n`.

### 2.5. `re.compile(pattern, flags)` → той самий об'єкт (застарілий)

Перекомпілює **наявний** об'єкт: `const r = /a/g; r.compile('b', 'i')` → `r.source === 'b'`, `r.flags === 'i'`. Це спадок Annex B, **у новому коді не використовують**: створюйте новий `RegExp`.

### 2.6. Символьні методи `re[Symbol.match / matchAll / replace / search / split]`

Це справжні реалізації, які рядкові методи **викликають під капотом**: `s.match(re)` = `re[Symbol.match](s)`, `s.replace(re, x)` = `re[Symbol.replace](s, x)` тощо. Виміряно: `/a/[Symbol.match]('cat')` → `['a']`; `/a/g[Symbol.replace]('aa', 'b')` → `bb`; `/,/[Symbol.split]('a,b')` → `['a','b']`.

Практичний сенс — **будь-який об'єкт із таким методом** можна передати в рядковий метод: `'abc'.replace({[Symbol.replace](s, r) { return s.toUpperCase() + r; }}, '!')` → `ABC!`. Ще один наслідок: `/a/[Symbol.match] = false` робить об'єкт «не регулярним виразом» для методів на кшталт `startsWith`; без цього `'/a/'.startsWith(/a/)` кидає `TypeError: First argument to String.prototype.startsWith must not be a regular expression`.

### 2.7. `str.match(re)` → масив або `null`

| Випадок | Результат |
|---|---|
| без `g` | як `re.exec(str)`: `'a1b22'.match(/\d+/)` → `['1']`, `index: 1` |
| з `g` | **масив лише текстів**: `'a1b2'.match(/[a-z]\d/g)` → `['a1','b2']`; без груп, позицій |
| збігів немає | `null` (не порожній масив) |
| аргумент — **рядок** | він стає шаблоном: `'a.b'.match('.')` → `['a']` (крапка — будь-який символ!) |

Пастка: `match` з `g` ховає групи й `index` — для них `matchAll`.

### 2.8. `str.matchAll(re)` → ітератор збігів

- **Вимагає `g`**: без нього `TypeError: String.prototype.matchAll called with a non-global RegExp argument`.
- Повертає **ітератор** (`[object RegExp String Iterator]`); кожен елемент має ту саму форму, що й результат `exec`: `[0]`, групи, `index`, `input`, `groups`. Перетворюють у масив: `[...s.matchAll(re)]`.
- Працює з **копією** регулярного виразу, тому `lastIndex` оригіналу не змінюється. Виміряно: при `r.lastIndex = 1` на `'aaa'` результат — 2 збіги (копія починає з 1), а `r.lastIndex` лишився `1`.
- Рядок як аргумент стає шаблоном з `g`: `[...'a.b.a'.matchAll('a')].map(m => m.index)` → `[0, 4]`.

### 2.9. `str.replace(pattern, replacement)` → новий рядок

Рядок не змінюється, повертається новий. `pattern` — регулярний вираз або рядок; `replacement` — рядок або функція.

| Pattern | Що замінюється |
|---|---|
| регулярний вираз без `g` | **лише перший** збіг |
| регулярний вираз з `g` | усі збіги |
| **рядок** | лише **перше** буквальне входження: `'a.b.c'.replace('.', '-')` → `a-b.c` |

Спеціальні послідовності в рядку заміни (виміряно на `'abc'`):

| Запис | Сенс | Приклад і результат |
|---|---|---|
| `$&` | увесь збіг | `replace(/b/, '[$&]')` → `a[b]c` |
| `` $` `` | текст **перед** збігом | `` replace(/b/, "[$`]") `` → `a[a]c` |
| `$'` | текст **після** збігу | `replace(/b/, "[$']")` → `a[c]c` |
| `$1`…`$99` | група за номером | `replace(/(b)/, '$1$1')` → `abbc` |
| `$<name>` | іменована група | `replace(/(?<x>b)/, '[$<x>]')` → `a[b]c` |
| `$$` | літерал `$` | `replace(/b/, '$$')` → `a$c` |
| `$0`, `$2` без такої групи | **не** спецпослідовність, лишається текстом | `replace(/(b)/, '$2')` → `a$2c` |

**Функція** замість рядка отримує `(match, p1, p2, …, offset, string, groups)`; `groups` додається **останнім** лише коли є іменовані групи. Виміряно: `'a-b'.replace(/(\w)-(\w)/, (m, a, b) => b + a)` → `ba`.

### 2.10. `str.replaceAll(pattern, replacement)` → новий рядок

Те саме, що `replace`, але міняє **всі** входження. Рядок: `'a.b.c'.replaceAll('.', '-')` → `a-b-c` (рядок трактується **буквально**, без регулярного виразу). Регулярний вираз **без `g`** — `TypeError: String.prototype.replaceAll called with a non-global RegExp argument`. З `g` поводиться як `replace`: `'aaa'.replaceAll(/a/g, 'b')` → `bbb`.

### 2.11. `str.search(re)` → індекс або `-1`

Позиція **першого** збігу: `'cat'.search(/a/)` → `1`, немає збігу → `-1`. Ігнорує `g` і **не чіпає `lastIndex`**: виміряно `'bab'.search(r)` з `r = /a/g` і `r.lastIndex = 3` → `1`, `r.lastIndex` лишився `3`. Лише позиція; текст збігу не дає (для нього — `match`).

### 2.12. `str.split(separator, limit)` → масив

| Виклик | Результат |
|---|---|
| `'a1b2c3'.split(/\d/, 2)` | `['a','b']` — `limit` обрізає кількість елементів |
| `'abc'.split('')` | `['a','b','c']` (за code unit) |
| `'abc'.split(/(?:)/u)` | `['a','b','c']` (за code point з `u`) |
| `'a,b'.split(/(,)/)` | `['a', ',', 'b']` — **група повертає роздільники** |
| `''.split(/,/)` | `['']` — порожній рядок дає один порожній елемент |
| `''.split('')` | `[]` |

Прапорець `y` у `split` ігнорується (виміряно: `'a,b'.split(/,/y)` → `['a','b']`).

### 2.13. Властивість `lastIndex` — стан між викликами

`lastIndex` — **єдина змінна властивість екземпляра**: індекс, з якого почнеться наступний пошук. Читається й записується, діє **лише з `g` або `y`**.

| Ситуація | Поведінка (виміряно) |
|---|---|
| успішний `exec`/`test` з `g` | `lastIndex` = кінець збігу |
| невдалий `exec`/`test` | `lastIndex` скидається в `0` |
| без `g` і `y` | ігнорується й не змінюється: `r.lastIndex = 2; r.test('aaa')` → `true`, `lastIndex` лишився `2` |
| ручне встановлення | `const r = /a/g; r.lastIndex = 5; r.test('aaa')` → `false`, `lastIndex = 0` |
| `y` (sticky) | збіг має починатися **саме** з `lastIndex` |

Звідси пастка «через раз»: збережений `/a/g` з `test` на кожному виклику продовжує з місця, де зупинився.

### 2.14. Властивості-геттери (лише читання)

| Властивість | Прапорець | Для `/a/dgimsvy` |
|---|---|---|
| `hasIndices` | `d` | `true` |
| `global` | `g` | `true` |
| `ignoreCase` | `i` | `true` |
| `multiline` | `m` | `true` |
| `dotAll` | `s` | `true` |
| `unicodeSets` | `v` | `true` |
| `sticky` | `y` | `true` |
| `unicode` | `u` | `false` (з `v` не вмикається) |
| `flags` | усі разом, **у фіксованому порядку** `dgimsuvy` | `'dgimsvy'` (`new RegExp('a', 'yvsmigd').flags` теж `dgimsvy`) |
| `source` | текст шаблону | `'a'`; порожній — `'(?:)'` |

`u` і `v` разом — `SyntaxError: Invalid flags supplied to RegExp constructor 'uv'`; невідомий прапорець — той самий `SyntaxError`; помилка в шаблоні — `SyntaxError: Invalid regular expression: /(/: Unterminated group`.

### 2.15. Створення: літерал, `RegExp(...)`, `new RegExp(...)`

| Запис | Результат |
|---|---|
| `/a/g` | літерал, шаблон перевіряється при завантаженні скрипту |
| `new RegExp('a', 'g')` | з рядка (слеші подвоюються) |
| `new RegExp(/a/g)` | копія зі збереженням прапорців (`g`) |
| `new RegExp(/a/g, 'i')` | копія з **новими** прапорцями (`i`, а не `gi`) |
| `RegExp(/a/)` без `new` | повертає **той самий** об'єкт; `RegExp(r) === r` → `true`, але `RegExp(/a/g) === RegExp(/a/g)` → `false` (дві різні літерали) |

`typeof /a/` → `'object'`, `Object.prototype.toString.call(/a/)` → `[object RegExp]`, `/a/ instanceof RegExp` → `true`.

### 2.16. Статичні члени `RegExp`

- **`RegExp.escape(str)`** (Node 24, ES2025): екранує рядок для вставки в шаблон. `RegExp.escape('a.b')` → `\x61\.b` (початкову літеру теж кодує як `\x61`, щоб результат не склеївся з попереднім текстом).
- **`RegExp[Symbol.species]`** → сам `RegExp`; використовується при створенні підкласів.
- **Застарілі статичні властивості** `RegExp.$1`…`$9`, `lastMatch` (`$&`), `lastParen` (`$+`), `leftContext` (`` $` ``), `rightContext` (`$'`), `input` (`$_`) зберігають результат **останнього** успішного збігу в усьому скрипті. Виміряно після `/(\d)(\d)/.exec('x12')`: `RegExp.$1` → `1`, `RegExp.$2` → `2`, `lastMatch` → `12`, `leftContext` → `x`, `rightContext` → `''`, `lastParen` → `2`, `input` → `x12`. Це **глобальний стан**, який перезаписує будь-який інший збіг; користуватись ним не слід.

### 2.17. Зведена таблиця повернених значень

| Виклик | Тип результату | Немає збігу |
|---|---|---|
| `re.test(s)` | `boolean` | `false` |
| `re.exec(s)` | масив з `index`, `input`, `groups` | `null` |
| `s.match(re)` без `g` | як `exec` | `null` |
| `s.match(re)` з `g` | `string[]` | `null` |
| `s.matchAll(re)` | ітератор масивів як у `exec` | порожній ітератор |
| `s.search(re)` | число | `-1` |
| `s.replace(re, x)` / `replaceAll` | рядок | той самий рядок |
| `s.split(re)` | `string[]` | `[s]` |

## 3. Як працює рушій (щоб розуміти результати)

Більшість популярних рушіїв (JavaScript, Perl, PCRE, Java, .NET, Ruby, Python) — **з поверненням (backtracking)**: рухаються по шаблону зліва направо, пробуючи варіанти, а при невдачі повертаються і пробують інші.

Правила, які пояснюють будь-який результат:

1. **Найлівіший збіг.** Рушій пробує початок збігу з позиції 0, потім 1, 2… і бере **першу позицію**, з якої збіг можливий.
2. **Перший успішний варіант, а не найкращий.** При альтернації `a|b` рушій пробує зліва направо й зупиняється на першому, що підійшов. Виміряно (JS):

   | Вираз | Рядок `ab` | Результат |
   |---|---|---|
   | `/a\|ab/` | `ab` | `a` (перша гілка підійшла) |
   | `/ab\|a/` | `ab` | `ab` |
   | `/(?:a\|ab)$/` | `ab` | `ab` (перша гілка не дала збігу з `$`, рушій повернувся і взяв другу) |

3. **Жадібність.** Квантифікатори за замовчуванням беруть **якомога більше**, а при невдачі «віддають» символи назад.
4. **Збіг може бути порожнім.** `x*` збігається з порожнім рядком на кожній позиції. Виміряно: `'abc'.replace(/x*/g, '-')` → `-a-b-c-`; `'abc'.split(/(?:)/)` → `['a','b','c']`.
5. **Збіги не перекриваються.** Після збігу пошук продовжується з його кінця (для глобального пошуку).

**Інша родина рушіїв — автомати без повернення** (DFA/NFA-симуляція): RE2 (Go, Rust `regex`), `grep`/`awk` у POSIX-реалізаціях. Вони гарантують лінійний час, але **не підтримують** зворотні посилання й lookaround. Через це в Go/Rust немає `(?=...)` і `\1`.

Для POSIX-інструментів правило інше: **найлівіший і найдовший** збіг (альтернація вибирає найдовший варіант), а в Perl-подібних — **перший**.

## 4. Символи й метасимволи

Більшість символів у шаблоні означають самі себе: `cat` знайде «cat». Особливий сенс мають **метасимволи**:

```
.  ^  $  *  +  ?  (  )  [  ]  {  }  |  \
```

Щоб знайти метасимвол буквально, його **екранують** зворотною скісною рискою: `\.`, `\*`, `\(`, `\\`. Виміряно (JS): `'a.c'.match(/a\.c/)` → `a.c`, а `'abc'.match(/a\.c/)` → `null`.

Екранування з коду: `str.replace(/[.*+?^${}()|[\]\\]/g, '\\$&')` → `a\.b\*c`; у новому Node є `RegExp.escape` (виміряно: `typeof RegExp.escape === 'function'` у Node 24).

### Крапка `.`
Будь-який символ, **крім** переходу на новий рядок. Виміряно (JS): `'a\nb'.match(/a.b/)` → `null`; з прапорцем `s` (dotAll) → збіг. У JS «будь-який символ включно з новим рядком» можна записати `[^]` або `[\s\S]` (виміряно: обидва збіглись із `a\nb`).

### Літерали-невидимки
`\n` (новий рядок), `\r`, `\t`, `\0`, `\xHH` (код байта), `\uHHHH` (Unicode), `\u{1F600}` (з прапорцем `u` у JS).

## 5. Класи символів

**Клас** `[...]` збігається з **одним** символом із переліку.

```
[abc]      a, b або c
[a-z]      діапазон
[A-Za-z0-9_]
[^abc]     будь-який символ, КРІМ a, b, c   (^ на початку = заперечення)
```

Усередині класу метасимволи майже не потрібно екранувати: `[.*+?]` — це чотири літерали. Спеціальні лише `]`, `\`, `^` (на початку) і `-` (між символами; щоб був літералом — поставити першим/останнім: `[a-z-]`).

Виміряно (JS): `'a1b2'.replace(/[^0-9]/g, '')` → `12`; `'x9'.match(/[a-z]\d/)` → `x9`.

### Скорочення

| Запис | Еквівалент | Сенс |
|---|---|---|
| `\d` | `[0-9]` | цифра |
| `\D` | `[^0-9]` | не цифра |
| `\w` | `[A-Za-z0-9_]` | «символ слова» |
| `\W` | `[^A-Za-z0-9_]` | не символ слова |
| `\s` | пробіл, `\t`, `\n`, `\r`, `\f`, `\v` та ін. | пробільний символ |
| `\S` | протилежне | не пробільний |

**Пастка: що саме вважається літерою/цифрою — залежить від мови.**
- `\d`, `\w` у JavaScript — **лише ASCII** (в інших мовах, наприклад Python 3, — Unicode). Виміряно: `'Привіт'.match(/\w/)` → `null`; `'é'.match(/\w/)` → `null`; `/\d/.test('٣')` → `false`. Для інших мов — `\p{L}` з прапорцем `u`: `'Привіт'.match(/\p{L}+/u)[0]` → `Привіт`.
- `\s` у JS включає нерозривний пробіл і пробіли Unicode (виміряно: ` ` і ` ` збігаються).

### POSIX-класи
У `grep`/`sed`/`awk`: `[[:alpha:]]`, `[[:digit:]]`, `[[:alnum:]]`, `[[:space:]]`, `[[:upper:]]`, `[[:lower:]]`, `[[:punct:]]` — записуються **всередині** дужок. Виміряно: `grep -E '^[[:alpha:]]+ [[:digit:]]+$'` знайшов рядки `cat 123`, `dog 45`, `Cat 6`. У JavaScript їх немає (замість них — `\p{...}`).

### Unicode-властивості
`\p{L}` (будь-яка літера), `\p{Lu}` (велика), `\p{Nd}` (десяткова цифра), `\p{Script=Cyrillic}`, `\p{Emoji}`; заперечення — `\P{...}`. JS: потрібен прапорець `u` (або `v`). Виміряно: `'Привіт, world! 123'.match(/\p{Lu}/gu)` → `['П']`; `'Привіт world'.match(/\p{Script=Cyrillic}+/u)[0]` → `Привіт`; `'a1٣'.match(/\p{Nd}/gu)` → `['1','٣']`.

## 6. Якорі та межі слів

Якорі **не споживають символів** — вони перевіряють місце.

| Запис | Сенс |
|---|---|
| `^` | початок рядка тексту (з прапорцем `m` — початок кожного рядка) |
| `$` | кінець (з `m` — кінець кожного рядка) |
| `\b` | межа слова (між `\w` і `\W`, на початку або в кінці) |
| `\B` | не межа слова |
| `\A`, `\Z`, `\z` | початок / кінець усього тексту (PCRE, Perl; у JS **немає**) |

Виміряно (JS):
- `/^abc$/.test('abc')` → `true`, але `/^abc$/.test('abc\n')` → `false`;
- `/^b/m.test('a\nb')` → `true`, без `m` → `false`; `'a\nb'.match(/^\w$/gm)` → `['a','b']`;
- `'cat concat cat.'.match(/\bcat\b/g).length` → `2` (слово `concat` не рахується).

**`$` і кінцевий перенос рядка.** У JS без `m` `$` збігається лише в самому кінці тексту: `/^abc$/.test('abc\n')` → `false`, з `m` → `true`. У деяких інших мовах (Python, PCRE) `$` збігається ще й перед останнім `\n` — тому там для суворої перевірки потрібен `\Z`. Для JS цього не треба: ставте `^…$` без `m`.

У JS із прапорцем `m` символ `\r` теж вважається кінцем рядка: виміряно `'a\r\nb'.match(/a$/m)` — збіг (до `\r`).

`\b` залежить від визначення `\w`: для кирилиці в JS межі слова **не** працюють (немає `\w`) — замінюйте lookaround із `\p{L}`.

## 7. Квантифікатори

Задають, скільки разів повторити **попередній елемент** (символ, клас, групу).

| Запис | Скільки |
|---|---|
| `*` | 0 або більше |
| `+` | 1 або більше |
| `?` | 0 або 1 |
| `{n}` | рівно n |
| `{n,}` | n або більше |
| `{n,m}` | від n до m |

Виміряно (JS): `'aaa'.match(/a{2}/)` → `aa`; `'aaaa'.match(/a{2,3}/)` → `aaa`; `'aaaa'.match(/a{2,}/)` → `aaaa`; `'color colour'.match(/colou?r/g)` → `['color','colour']`.

### Жадібні, ліниві, посесивні
- **Жадібний** (`*`, `+`, `?`, `{n,m}`) — бере максимум, при невдачі віддає.
- **Лінивий** (`*?`, `+?`, `??`, `{n,m}?`) — бере мінімум, при невдачі додає.
- **Посесивний** (`*+`, `++`, `?+`) — бере максимум і **не віддає** (немає повернення). Є в PCRE/Perl/Java; **не** в JavaScript. Виміряно: `new RegExp('a++')` → `SyntaxError: Nothing to repeat`; у Perl `"aaa" =~ /a++a/` — збігу немає.

Класичний приклад: вилучення тега. Виміряно (JS) на `<b>x</b><b>y</b>`:

| Вираз | Результат |
|---|---|
| `/<.+>/` | весь рядок `<b>x</b><b>y</b>` (жадібно) |
| `/<.+?>/` | `<b>` (лінивий) |
| `/<[^>]+>/g` | `['<b>','</b>','<b>','</b>']` (усі теги; найнадійніше) |

**Правило:** замість `.*?` частіше краще **заперечений клас** `[^>]*` — він швидший і не повертається.

Квантифікатор діє на **один елемент**: `ab+` = `a` + `b` повторене; щоб повторити пару — група `(?:ab)+`.

## 8. Групи

### 8.1. Захоплювальна група `( ... )`
Групує частину шаблону й **запам'ятовує** знайдене (нумерація — за відкритою дужкою, з 1). Виміряно (JS): `'2025-11-15'.match(/(\d{4})-(\d{2})-(\d{2})/)` → `[ '2025-11-15', '2025', '11', '15' ]`, `index: 0`.

### 8.2. Незахоплювальна `(?: ... )`
Групує, але не запам'ятовує: `'2025-11-15'.match(/(?:\d{4})-(\d{2})/).length` → `2` (повний збіг + одна група).

### 8.3. Іменовані групи
Синтаксис JavaScript — `(?<name>...)`; значення — у `match.groups`. Виміряно:
- `'2025-11-15'.match(/(?<y>\d{4})-(?<m>\d{2})-(?<d>\d{2})/).groups` → `{ y: '2025', m: '11', d: '15' }`;
- у заміні: `'2025-11-15'.replace(re, '$<d>.$<m>.$<y>')` → `15.11.2025`;
- однакове ім'я в різних гілках альтернації дозволено (Node 24, ES2025): `/(?<n>x)|(?<n>y)/` на `x1` → `n = 'x'`;
- без збігу групи `match.groups` не містить значення: група, що не брала участі, дає `undefined`.

В інших рушіях запис відрізняється (`(?P<name>...)` у Python): перед перенесенням шаблону перевіряйте діалект (розділ 12).

### 8.4. Посилання назад (backreference)
`\1`, `\2` або `\k<name>` повторює **той самий текст**, що зловила група. Виміряно:
- `'hello wood moon'.match(/(\w)\1/g)` → `['ll','oo','oo']` (подвоєна літера);
- `'abab'.match(/(ab)\1/)[0]` → `abab`;
- парні лапки: `/(["'])(.*?)\1/g` знайшло `"x"` і `'y'`, але не `"z'` (різні лапки);
- іменований варіант: `'abab'.match(/(?<p>ab)\k<p>/)[0]` → `abab`.

Група, що не брала участі в збігу, дає `undefined`: `'a'.match(/(a)|(b)/)` → `['a','a',undefined]`.

### 8.5. Умовний вираз і атомарна група — немає в JS
Умовний вираз `(?(1)...|...)` («якщо група 1 збіглась») і атомарна група `(?>...)` (після успіху не повертається всередину; те саме, що посесивний квантифікатор) є в PCRE/Perl. Виміряно (Perl): `"aaab" =~ /(?>a+)b/` — збіг, `"aaa" =~ /(?>a+)a/` — немає. У JavaScript обидві дають `SyntaxError: Invalid regular expression … Invalid group`. Умовну перевірку парних дужок у JS записують двома кроками: `/^(?:\(\d+\)|\d+)$/`.

## 9. Альтернація `|`

`cat|dog` — «або». Має **найнижчий пріоритет**: `^cat|dog$` — це «починається з cat» **або** «закінчується на dog». Для групування — дужки: `^(cat|dog)$`. Порядок гілок важливий (розділ 3): ставте довшу гілку **першою**, якщо вони мають спільний початок.

## 10. Lookaround — перевірка контексту без споживання

Чотири конструкції; вони перевіряють умову **біля** поточної позиції й не входять у збіг.

| Запис | Сенс |
|---|---|
| `X(?=Y)` | X, за яким **іде** Y (lookahead) |
| `X(?!Y)` | X, за яким **не** йде Y |
| `(?<=Y)X` | X, перед яким **є** Y (lookbehind) |
| `(?<!Y)X` | X, перед яким **немає** Y |

Виміряно (JS):
- `'price: 100USD 200EUR'.match(/\d+(?=USD)/)[0]` → `100`;
- `'a1 b2'.match(/[a-z](?!1)/g)` → `['b']`;
- `'cost $42 and €7'.match(/(?<=\$)\d+/)[0]` → `42`; `(?<!\$)\b\d+` → `7`.
- Перевірка пароля кількома lookahead від початку: `/^(?=.*\d)(?=.*[a-z])(?=.*[A-Z]).{8,}$/` — `Passw0rdX` → `true`, `password` → `false`.

**Відмінність:** довжина lookbehind. У **JS** може бути змінною (виміряно: `'ab12'.match(/(?<=a+b)\d/)[0]` → `1`). У PCRE і Python — лише **фіксованої довжини**, у Go/Rust lookaround **немає**.

Lookahead зручний, коли треба поставити кілька умов до одного місця (пароль), або вирізати тільки частину збігу (число перед одиницею виміру). Тисячні розряди: `'1234567.89'.replace(/\B(?=(\d{3})+(?!\d))/g, ',')` → `1,234,567.89`.

## 11. Прапорці (flags)

| Прапорець | Дія |
|---|---|
| `i` | ігнорувати регістр |
| `g` | усі збіги (інакше `match`/`replace` беруть лише перший) |
| `m` | `^`/`$` на межах рядків |
| `s` | `.` збігається з `\n` |
| `u` | повна підтримка Unicode (`\p{…}`, символи поза BMP) |
| `y` | sticky: збіг лише з `lastIndex` |
| `d` | індекси груп (`match.indices`) |
| `v` | розширені класи (операції над множинами) |

Виміряно (JS): `/a/gimsuyd.flags` → `dgimsuy`; `'aAa'.match(/a/gi).length` → `3`; `'😀'.match(/./)[0].length` → `1`, а з `u` → `2` (емодзі = два code unit, але один символ-«код-поінт»); `'xaby'.match(/a(b)/d).indices[1]` → `[2, 3]`. Прапорець `v`: `'abc'.match(/[\p{L}--[b]]/gv)` → `['a','c']` (віднімання множин).

**Вбудовані (inline) прапорці** на частину шаблону: `(?i:a)b` працює в Node 24 (виміряно: `Ab` → `true`, `AB` → `false`), але це **нова** можливість (ES2025); запис `(?i)abc` на весь шаблон у JS — `SyntaxError`. Регістр у Unicode непередбачуваний: `'İ'.match(/i/i)` → `null`.

## 12. Діалекти: що де працює

Регулярні вирази **не** єдиний стандарт. Основні родини:

- **PCRE / Perl-сумісні**: Perl, PHP, Python, JavaScript (близько), Java, .NET, Ruby — найбагатші.
- **POSIX BRE** (basic): `grep`, `sed` за замовчуванням. **POSIX ERE** (extended): `grep -E`, `sed -E`, `awk`.
- **RE2-подібні**: Go, Rust `regex`, Google RE2 — без backtracking, без lookaround і backreferences.

Порівняння для JS, Perl 5.34, BSD `grep`/`sed` macOS; решта — довідково:

| Можливість | JavaScript | Perl / PCRE | grep/sed (BSD, macOS) |
|---|---|---|---|
| `\d`, `\w`, `\s` | так, ASCII | так | `\d` у `grep -E` — так; у `sed -E` — **ні** |
| `(?:...)` | так | так | `grep -E` — так, `sed -E` — ні (помилка `repetition-operator operand invalid`) |
| Іменовані групи | `(?<n>)` | `(?<n>)`, `(?P<n>)` | ні |
| Lookahead `(?=)` | так | так | ні (`grep -E '(?=a)ab'` — помилка) |
| Lookbehind | так, змінна довжина | переважно фіксована довжина | ні |
| Посесивні, атомарні | ні | так | ні |
| Умовні `(?(1)…)` | ні | так | ні |
| `\p{L}` | так (прапорець `u`) | так | ні |
| Inline `(?i)` на весь шаблон | ні (лише `(?i:..)`) | так | ні |
| `\A \Z \z` | ні | так | ні |
| POSIX `[[:alpha:]]` | ні | так (Perl) | так |

**Пастки macOS-інструментів, які виміряно:**
- `grep -P` **не існує** в BSD grep (`invalid option -- P`) — для lookaround у терміналі використовуйте `perl` (або GNU grep/`ugrep`);
- `sed -E 's/\d+/N/'` у BSD sed **не** розуміє `\d` як цифру: `dog 45` стало `Nog 45` (`\d` сприйнято як літеру d); те саме `\w` — `sed -E 's/(\w+) (\w+)/\2, \1/'` рядок не змінило. Користуйтесь `[0-9]`, `[[:digit:]]`, `[[:alnum:]_]`;
- BSD `grep -E '\d+'` цифри знаходить (розширення BSD) — але покладатись на це не варто;
- у BSD `grep` (BRE) `\+` і `\|` працюють як `+` і «або»; а `+` без слеша — буквальний плюс (виміряно: `grep 'a+'` нічого не знайшов у тексті без `a+`);
- у BSD sed працює прапорець `I` (`s/cat/X/I` замінило і `cat`, і `Cat`).

## 13. Використання: JavaScript

Докладно — [regexp.md](../js/common/regexp.md). Основне:

```js
const re = /(?<y>\d{4})-(?<m>\d{2})/;
re.test('2025-11');                    // true / false
'2025-11'.match(re).groups.y;          // '2025'
[...'a1b22'.matchAll(/(?<l>[a-z])(?<n>\d+)/g)]   // усі збіги з групами (потрібен g)
'a1b2'.replace(/\d/g, '#');            // 'a#b#'
'a, b;c'.split(/[,;]\s*/);             // ['a','b','c']
'abc'.search(/c/);                     // 2 (або -1)
new RegExp('\\d+', 'g');               // з рядка: слеші подвоюються
```

Виміряні нюанси:
- `str.match(/\d/g)` повертає **масив лише збігів** (без груп): `'a1b2'.match(/\d/g)` → `['1','2']`; якщо збігів немає — `null` (не порожній масив).
- **`lastIndex` пастка:** регулярний вираз із `g` або `y` **запам'ятовує позицію**. `const r = /a/g; r.test('a')` → `true` (`lastIndex = 1`), другий `r.test('a')` → `false` (`lastIndex` скинуто в 0). Не зберігайте `/.../g` у змінній для багаторазового `test`.
- `replaceAll` з регулярним виразом без `g` — помилка: `TypeError: String.prototype.replaceAll called with a non-global RegExp argument`.
- `split` із групою в шаблоні **включає роздільники**: `'a1b2c'.split(/(\d)/)` → `['a','1','b','2','c']`; `'a,b,c'.split(/,/, 2)` → `['a','b']`.
- Рядок заміни: `$1`/`$<name>` (група), `$&` (збіг), `` $` `` (перед), `$'` (після), `$$` (знак `$`). Виміряно: `'John Smith'.replace(/(\w+) (\w+)/, '$2, $1')` → `Smith, John`; `'abc'.replace(/b/, '[$&]')` → `a[b]c`; `'abc'.replace(/b/, '$$')` → `a$c`. Контрольний приклад: `$0` у JS **не** означає збіг (виміряно: `a[$0]c`).
- Заміна функцією: `'price 10 and 20'.replace(/\d+/g, m => m * 2)` → `price 20 and 40`.
- Sticky `y` для токенізатора: `/\s*(\d+|[+*\/()-])/y` у циклі `exec` розбило `12 + 3*(4-1)` на `['12','+','3','*','(','4','-','1',')']`.

## 14. Використання: об'єкт RegExp у JavaScript

Розділ 12 дав короткий огляд методів. Тут — як влаштований сам об'єкт `RegExp` і результат збігу.

### Літерал чи конструктор

| Запис | Коли |
|---|---|
| `/\d+/g` | шаблон відомий заздалегідь; компілюється разом зі скриптом |
| `new RegExp('\\d+', 'g')` | шаблон збирається з рядків; **слеші подвоюються** |
| `new RegExp(String.raw`\d+`, 'g')` | те саме без подвоєння слешів |

Виміряно: `new RegExp('\d+').source` → `d+` (`'\d'` у звичайному рядку — це просто `d`), а `new RegExp('\\d+').source` і `new RegExp(String.raw`\d+`).source` → `\d+`.

Шаблон зі змінної треба **екранувати**. Виміряно (Node 24): `RegExp.escape('a.b*c (x)')` → `\x61\.b\*c\x20\(x\)` (екранує й початкову літеру та пробіл — результат коректний, але виглядає незвично); ручний варіант `'a.b*c (x)'.replace(/[.*+?^${}()|[\]\\]/g, '\\$&')` → `a\.b\*c \(x\)`. Без екранування `new RegExp('a.b').test('axb')` → `true`, з екрануванням → `false`.

### Властивості об'єкта

```js
const re = /(?<y>\d{4})-(?<m>\d{2})-(?<d>\d{2})/gi;
re.source
re.flags
re.global
re.lastIndex
String(re)
```

| Властивість | Значення для `/a/gi` |
|---|---|
| `source` | текст шаблону без слешів: `a` |
| `flags` | рядок прапорців: `gi` |
| `global`, `ignoreCase`, `multiline`, `sticky`, `unicode`, `dotAll`, `hasIndices` | `true` / `false` для кожного прапорця (`true,true,false,false,false,false,false`) |
| `lastIndex` | позиція, з якої почнеться наступний пошук (лише для `g` і `y`) |

`String(/a\/b/gi)` → `/a\/b/gi`. Копія з іншими прапорцями: `new RegExp(/a/gi, 'm').flags` → `m` (прапорці **замінюються**, а не додаються).

### `exec` — результат збігу

```js
const m = /(?<y>\d{4})-(?<m>\d{2})-(?<d>\d{2})/.exec('on 2025-11-15 ok');
```

| Поле | Значення |
|---|---|
| `m[0]` | `2025-11-15` — повний збіг |
| `m[1]`, `m[2]`, `m[3]` | `2025`, `11`, `15` — групи |
| `m.index` | `3` — позиція початку |
| `m.input` | `on 2025-11-15 ok` — вхідний рядок |
| `m.groups` | `{ y: '2025', m: '11', d: '15' }` |
| `m.length` | `4` — повний збіг + 3 групи |

Немає збігу — `null`. Група, що не брала участі, — `undefined`: `'a'.match(/(a)|(b)/)` → `['a','a',undefined]`.

### Цикл з `exec` і `lastIndex`

```js
const r = /\d+/g;
let x;
while ((x = r.exec('a1b22c333')) !== null) out.push([x[0], x.index, r.lastIndex]);
```

Результат: `[['1',1,2],['22',3,5],['333',6,9]]`. Після невдачі `exec` повертає `null` і **скидає** `lastIndex` у `0`, тому цикл завершується. Сучасніше й безпечніше — `matchAll`: `[...'a1b22'.matchAll(/(?<l>[a-z])(?<n>\d+)/g)]` дає масив збігів з `index` і `groups` (`['a1', 0, {l:'a', n:'1'}]`, `['b22', 2, {l:'b', n:'22'}]`). Без `g` `matchAll` кидає `TypeError: String.prototype.matchAll called with a non-global RegExp argument`.

### Який метод коли

| Потрібно | Метод | Приклад і результат |
|---|---|---|
| так/ні | `re.test(s)` | `/\d+/.test('a12')` → `true` |
| перший збіг із групами | `s.match(re)` без `g` | `'a1b22'.match(/\d+/)` → `1`, `index: 1` |
| усі збіги (тільки текст) | `s.match(re)` з `g` | `'a1b22c333'.match(/\d+/g)` → `['1','22','333']`; немає збігів → `null` |
| усі збіги з групами й позиціями | `s.matchAll(re)` | див. вище |
| позиція | `s.search(re)` | `'a12'.search(/\d/)` → `1`; немає → `-1` |
| заміна | `s.replace(re, repl)` | `'aaa'.replace(/a/g, 'b')` → `bbb` |
| заміна всіх рядка | `s.replaceAll('.', '-')` | `'a.b.c'` → `a-b-c` (без регулярного виразу; рядок-аргумент у `replace` без `g` міняє лише перший: `a-b.c`) |
| розбиття | `s.split(re)` | `'a, b;c'.split(/[,;]\s*/)` → `['a','b','c']` |

Перевірка **цілого** рядка в JS — це `test` із якорями: `/^\d+$/.test('12')` → `true`, `'12a'` → `false`, а без якорів `/\d+/.test('a12')` → `true`. Окремої функції «fullmatch» немає.

### Заміна функцією

Аргументи колбека: `(match, p1, p2, …, offset, string, groups)`. Виміряно: `'a1'.replace(/([a-z])(\d)/, (m, p1, p2, off, str) => [m, p1, p2, off, str].join('|'))` → `a1|a|1|0|a1`. З іменованими групами **останній** аргумент — `groups`:

```js
'2025-11-15'.replace(re, (...a) => { const g = a.at(-1); return `${g.d}.${g.m}.${g.y}`; })
```

→ `15.11.2025`; той самий результат дає рядок заміни `'$<d>.$<m>.$<y>'`.

### Що в JS відсутнє (порівняно з іншими рушіями)

Виміряно в Node 24 — кожна з цих конструкцій дає `SyntaxError: Invalid regular expression`:

| Конструкція | Помилка |
|---|---|
| умовний вираз `(\()?\d+(?(1)\))` | `Invalid group` |
| вбудований прапорець на весь шаблон `(?i)abc` | `Invalid group` (працює лише `(?i:a)b` → `true` для `Ab`, `false` для `AB`) |
| посесивний `a++` | `Nothing to repeat` |
| атомарна група `(?>a+)b` | `Invalid group` |
| `\A`, `\Z` | не якорі: `/\Aabc/.test('abc')` → `false` |
| POSIX `[[:alpha:]]` | не клас: `/[[:alpha:]]/.test('a')` → `false` |

Натомість у JS є **змінної довжини lookbehind** (`'ab12'.match(/(?<=a+b)\d/)[0]` → `1`), однакові імена груп у різних гілках альтернації й `\p{…}` з `u`.

### Збирання складного шаблону з частин

Довгий шаблон зручно складати з маленьких літералів через `source`:

```js
const parts = [
  /^(?<ip>\S+) \S+ (?<user>\S+) /,
  /\[(?<time>[^\]]+)\] /,
  /"(?<method>[A-Z]+) (?<path>\S+) [^"]*" /,
  /(?<status>\d{3}) (?<size>\d+)$/,
];
const full = new RegExp(parts.map(r => r.source).join(''), 'gm');
```

Виміряно: на двох рядках журналу `[...log.matchAll(full)].map(x => ({...x.groups}))` дає `{ip: '192.168.1.10', user: '-', …, status: '200', size: '5120'}` і `{ip: '10.0.0.7', user: 'alice', …, status: '401', size: '87'}`. Кожну частину можна перевірити окремо.

## 15. Використання в командному рядку

### grep
```bash
grep 'cat' file            # BRE (за замовчуванням)
grep -E '^(cat|dog)' f     # ERE: +, ?, |, () без слешів
grep -i 'cat' f            # без урахування регістру
grep -o -E '[0-9]+' f      # вивести лише збіги (по одному на рядок)
grep -w 'cat' f            # лише ціле слово
grep -v '[0-9]' f          # рядки БЕЗ збігу
grep -c '[0-9]' f          # кількість рядків зі збігом
grep -n -E 'dog|bird' f    # з номерами рядків
```
Виміряно на файлі з рядками `cat 123`, `dog 45`, `Cat 6`, `bird`, `2025-11-15 error: disk full`:
- `grep -E '^(cat|dog)'` → `cat 123`, `dog 45`;
- `grep -oE '[0-9]+'` → `123`, `45`, `6`, `2025`, `11`, `15`;
- `grep -w 'cat'` → `cat 123` (не `Cat 6`, регістр різний);
- `grep -v '[0-9]'` → `bird`;
- `grep -c '[0-9]'` → `4`;
- `grep -nE 'dog|bird'` → `2:dog 45`, `4:bird`.

### sed
```bash
sed -E 's/([a-z]+) ([0-9]+)/\2 \1/' f      # поміняти місцями слово й число
sed -E 's/[0-9]+/[&]/' f                    # & = весь збіг
sed -E 's/[aeiou]/_/g' f                    # g — усі в рядку
sed -nE '/^d/p' f                            # -n + p: лише рядки зі збігом
sed -i '' -E 's/old/new/g' file              # редагувати файл на місці (macOS; GNU: sed -i)
```
Виміряно: `sed -E 's/([a-z]+) ([0-9]+)/\2 \1/'` перетворило `cat 123` на `123 cat`, `dog 45` на `45 dog`; `sed -E 's/[0-9]+/[&]/'` — `cat [123]`.
Заміна в `sed` використовує `\1`, `&`; роздільником може бути будь-який символ (`s|/usr|/opt|`), що зручно для шляхів.

### awk
```bash
awk '/^[0-9]{4}-/ {print $1}' f            # рядки, що починаються з дати
awk '{ if (match($0, /[0-9]+/)) print substr($0, RSTART, RLENGTH) }' f
```
Виміряно: перша команда вивела `2025-11-15`; друга — першу послідовність цифр у кожному рядку (`123`, `45`, `6`, `2025`). `awk` має ERE.

### perl — коли потрібні lookaround і `\d` у терміналі
```bash
perl -nle 'print $1 if /(?<=error: )(\w+)/' f       # → disk
perl -nle 'print "$+{y}/$+{m}" if /(?<y>\d{4})-(?<m>\d\d)/' f   # → 2025/11
perl -pe 's/(\w+) (\d+)/$2 $1/' f                    # → 123 cat, 45 dog …
perl -0pe 's/([^\n]+)\n([a-z])/$1 $2/g' f            # -0: читати весь файл як один рядок
```
Виміряно, усі чотири команди відпрацювали як описано. Прапорці командного рядка Perl: `-n` — цикл по рядках, `-p` — те саме з автодруком, `-l` — додає/знімає `\n`, `-e` — вираз, `-0` — розділювач запису (для багаторядкового тексту).

## 16. Рецепти (перевірені)

### Склеїти розірвані рядки
Рядок, що закінчується без крапки, а наступний починається з малої літери — це один абзац, розірваний переносом (типово для тексту, скопійованого з PDF).

```
([^\n]+)\n([a-z])   →   $1 $2
```

- `([^\n]+)` — захоплює весь рядок до переносу (клас «усе, крім `\n`»);
- `\n` — символ нового рядка;
- `([a-z])` — захоплює першу малу літеру наступного рядка;
- `$1 $2` — повертає перший рядок, пробіл і літеру.

Виміряно (JS): `'First line\nsecond part\nThird.'.replace(/([^\n]+)\n([a-z])/g, '$1 $2')` → `First line second part\nThird.`; те саме в Perl (`s/([^\n]+)\n([a-z])/$1 $2/g` з `-0`). У редакторах із підтримкою regex-заміни (VS Code, JetBrains) шаблон вводиться так само, заміна — `$1 $2`.

### Email (грубо, але практично)
```
^[^\s@]+@[^\s@]+\.[^\s@]+$
```
Виміряно: `a.b+c@example.co.uk` → `true`; `bad@`, `@bad.com`, `x@y` → `false`. Повна відповідність RFC 5322 регулярним виразом **не** потрібна: надійна перевірка — надіслати лист із посиланням.

### Дата `YYYY-MM-DD`
```
^\d{4}-(0[1-9]|1[0-2])-(0[1-9]|[12]\d|3[01])$
```
Виміряно: `2025-11-15` → `true`; `2025-13-45`, `2025-1-5` → `false`. Шаблон не знає про кількість днів у місяці (`2025-02-31` пройде) — для цього парсте в `Date`/`datetime`.

### Колір hex
```
^#(?:[0-9a-f]{3}|[0-9a-f]{6})$     (з прапорцем i)
```
`#fff`, `#FFAA00` → `true`; `#ggg`, `#12345` → `false`.

### IPv4
```
^(?:(?:25[0-5]|2[0-4]\d|1?\d?\d)\.){3}(?:25[0-5]|2[0-4]\d|1?\d?\d)$
```
`192.168.0.1` → `true`; `256.1.1.1`, `1.2.3` → `false`. Порядок гілок `25[0-5]|2[0-4]\d|1?\d?\d` важливий (розділ 3): спочатку вужчі діапазони.

### URL на частини (іменовані групи)
```
^(?<scheme>[a-z][a-z0-9+.-]*):\/\/(?:(?<user>[^@/]+)@)?(?<host>[^:/?#]+)(?::(?<port>\d+))?(?<path>\/[^?#]*)?(?:\?(?<query>[^#]*))?(?:#(?<hash>.*))?$
```
Виміряно на `https://user@example.com:8080/a/b?x=1#h`: `{scheme: 'https', user: 'user', host: 'example.com', port: '8080', path: '/a/b', query: 'x=1', hash: 'h'}`. У коді краще `new URL(...)`; регекс — для логів і швидких задач.

### Прибрати зайві пробіли
`'  a   b  '.replace(/^\s+|\s+$/g, '').replace(/\s+/g, ' ')` → `a b`.

### camelCase → snake_case
`'myVariableName'.replace(/[A-Z]/g, m => '_' + m.toLowerCase())` → `my_variable_name`.

### Тисячні розряди
`'1234567.89'.replace(/\B(?=(\d{3})+(?!\d))/g, ',')` → `1,234,567.89`. Це нестандартний випадок для дробової частини: у реальному коді `Intl.NumberFormat`.

### Усі числа / слова
`'a1b22c333'.match(/\d+/g)` → `['1','22','333']` (JS).

### Подвоєні слова
`/\b(\w+)\s+\1\b/` знаходить «the the» (backreference).

### Перетворення дати
`'2025-11-15'.replace(/(\d{4})-(\d{2})-(\d{2})/, '$3.$2.$1')` → `15.11.2025`.

### Витяг значення з журналу
`2025-11-15 error: disk full` → `perl -nle 'print $1 if /(?<=error: )(\w+)/'` → `disk`.

### Токенізатор
Sticky-цикл з розділу 13.

## 17. Практикум: як шукати в реальних текстах

Усе вище — інструменти. Цей розділ показує **процес**: беремо текст, формулюємо, що шукаємо, будуємо шаблон малими кроками й перевіряємо. Для терміналу — `grep`/`sed`/`awk`/`perl` на тому самому файлі.

### 17.0. Метод: від тексту до шаблону

1. **Подивіться на дані** і виділіть 3–5 рядків-прикладів: що має збігтись, що ні.
2. **Знайдіть сталі частини** (роздільники, ключові слова, лапки, дужки) — вони стають літералами й якорями.
3. **Опишіть змінні частини класом + квантифікатором**: «число» → `\d+`, «слово без пробілів» → `\S+`, «усе до лапки» → `[^"]*`.
4. **Збирайте зліва направо**, після кожного кроку перевіряйте, що збіг не зламався.
5. **Витягуєте — в групи** (краще іменовані); **перевіряєте — з якорями** `^…$`; **шукаєте — без якорів**, але з `\b`.
6. **Перевірте на гірших рядках**: порожній, зайві пробіли, ще один формат, регістр, кирилиця.

Правило вибору інструмента: заміна без контексту — `replace`; контекст без захоплення — lookaround; «усе до роздільника» — **заперечений клас** `[^,]*`, а не `.*`.

### 17.1. Простий текст: слово, а не підрядок

Текст: `The cat sat. Concatenate the Cat, cats and a bobcat.`

| Шаблон | Результат | Зауваження |
|---|---|---|
| `/cat/gi` | `['cat','cat','Cat','cat','cat']` | 5 збігів: знайшло всередині `Concatenate`, `cats`, `bobcat` |
| `/\bcat\b/gi` | `['cat','Cat']` | `\b` — лише ціле слово |
| `/\bcats?\b/gi` | `['cat','Cat','cats']` | `s?` додає множину |

`'…'.replace(/\bcat\b/gi, 'dog')` → `The dog sat. Concatenate the dog, cats and a bobcat.` — заміна не зачепила `Concatenate` і `bobcat`. Висновок: **завжди ставте `\b` навколо слова**, якщо не хочете підрядків.

### 17.2. Телефони в різних форматах

Текст: `Call +380 (67) 123-45-67, or 067-123-45-67; fax 0671234567. Not a phone: 12-34.`

```
(?:\+380|0)[\s-]?\(?\d{2}\)?[\s-]?\d{3}[\s-]?\d{2}[\s-]?\d{2}
```

Розбір по частинах:

| Частина | Сенс |
|---|---|
| `(?:\+380\|0)` | код країни або ведучий нуль |
| `[\s-]?` | необов'язковий пробіл чи дефіс |
| `\(?\d{2}\)?` | код оператора, дужки необов'язкові |
| `\d{3}`, `\d{2}`, `\d{2}` | решта цифр, між групами `[\s-]?` |

З прапорцем `g` знаходить `['+380 (67) 123-45-67','067-123-45-67','0671234567']`; `12-34` не збігається. Нормалізація до одного формату: `m.replace(/\D/g, '').replace(/^0/, '380')` → `380671234567` для всіх трьох.

Принцип: **необов'язкові роздільники** (`[\s-]?`) дозволяють один шаблон на всі написання.

### 17.3. Журнал веб-сервера: розбір рядка

Файл `access.log`:

```
192.168.1.10 - - [15/Nov/2025:10:15:32 +0200] "GET /index.html HTTP/1.1" 200 5120
10.0.0.7 - alice [15/Nov/2025:10:15:40 +0200] "POST /api/login HTTP/1.1" 401 87
172.16.5.3 - - [15/Nov/2025:10:16:01 +0200] "GET /img/logo.png HTTP/1.1" 304 0
10.0.0.7 - alice [15/Nov/2025:10:16:09 +0200] "GET /api/orders?id=42 HTTP/1.1" 500 1024
```

Повний розбір іменованими групами (JS, з `m` і `g`):

```
^(?<ip>\S+) \S+ (?<user>\S+) \[(?<time>[^\]]+)\] "(?<method>[A-Z]+) (?<path>\S+) [^"]*" (?<status>\d{3}) (?<size>\d+)$
```

Для першого рядка `m.groups` → `{ip: '192.168.1.10', user: '-', time: '15/Nov/2025:10:15:32 +0200', method: 'GET', path: '/index.html', status: '200', size: '5120'}`; для четвертого — `user: 'alice'`, `path: '/api/orders?id=42'`, `status: '500'`.

Чому саме так:
- `\S+` для IP і шляху — «усе до пробілу»;
- `\[(?<time>[^\]]+)\]` — **заперечений клас** «усе до `]`» швидший і точніший за `.*?`;
- `"[^"]*"` — «усе до лапки»;
- `\d{3}` — статус завжди три цифри;
- `^…$` разом з `m` прив'язує шаблон до кожного рядка, тож «сміття» в рядку дає не збіг, а пропуск.

Складений із частин шаблон (розділ 14) дає ті самі групи: `new RegExp(parts.map(r => r.source).join(''), 'gm')`, де `parts` — чотири літерали: IP і користувач, час у `[ ]`, запит у `" "`, статус із розміром. Перевіряйте кожну частину окремо, потім склеюйте.

Окремі запити до того самого файлу:

| Задача | Рішення | Результат |
|---|---|---|
| рядки з помилками 5xx (JS) | `/^.* "[A-Z]+ \S+ [^"]*" 5\d\d .*$/gm` | тільки рядок з `/api/orders?id=42` |
| лише IP | `/^\S+/gm` | `['192.168.1.10','10.0.0.7','172.16.5.3','10.0.0.7']` |
| шляхи без параметрів | `/"(?:GET\|POST) (\S+?)(?:\?\S*)? HTTP/g` | `['/index.html','/api/login','/img/logo.png','/api/orders']` |
| коди 4xx/5xx | `/\b(?:4\|5)\d\d(?= \d+$)/gm` | `['401','500']` |
| `grep` помилки | `grep -E '" [45][0-9]{2} ' access.log` | рядки з 401 і 500 |
| `grep` унікальні IP | `grep -oE '^[0-9.]+' access.log \| sort \| uniq -c` | `10.0.0.7` — 2, решта по 1 |
| `sed` стислий вигляд | `sed -E 's/^([0-9.]+) .*"(GET\|POST) ([^ ]+) .*" ([0-9]{3}) .*/\1 \2 \3 \4/' access.log` | `10.0.0.7 POST /api/login 401` |
| `awk` статус 5xx | `awk '$9 ~ /^5/ {print $1, $7, $9}' access.log` | `10.0.0.7 /api/orders?id=42 500` |
| `perl` іменовані групи | `perl -nle 'print "$+{m} $+{p}" if /"(?<m>GET\|POST) (?<p>\S+)/' access.log` | метод і шлях кожного рядка |

Урок: якщо дані **розділені пробілами й стовпцями**, `awk` часто простіший за regex; якщо структура складна (дужки, лапки) — regex з групами.

### 17.4. Журнал застосунку: рівні, повідомлення, пари `ключ=значення`

```
2025-11-15 10:00:01 INFO  server started on port 8080
2025-11-15 10:00:05 WARN  slow query (1200 ms)
2025-11-15 10:01:12 ERROR db timeout: host=db1 retry=3
2025-11-15 10:02:40 ERROR disk full: /var/log
```

| Задача | Шаблон | Результат |
|---|---|---|
| лише помилки | `/^.* ERROR .*$/gm` | 2 рядки |
| рівень + повідомлення | `/^(?<date>\S+) (?<time>\S+) (?<lvl>[A-Z]+)\s+(?<msg>.*)$/gm` | `['INFO','server started on port 8080']`, … |
| пари `k=v` | `/(\w+)=(\w+)/g` | `[['host','db1'],['retry','3']]` |
| об'єкт з пар | `Object.fromEntries([...s.matchAll(/(\w+)=(\w+)/g)].map(m => [m[1], m[2]]))` | `{host: 'db1', retry: '3'}` |
| число перед `ms` | `/\d+(?= ms)/g` | `['1200']` |

Зверніть увагу: `(?<lvl>[A-Z]+)\s+` — рівень має різну довжину (`INFO` і `ERROR`), тому вирівнювальні пробіли беремо `\s+`, а не жорстким `\s`.

### 17.5. CSV: кома всередині лапок

Рядок: `1,"Smith, John","said ""hi"""`

| Спосіб | Результат |
|---|---|
| `line.split(',')` | `['1','"Smith','John"','"said ""hi"""']` — зламано: 4 поля замість 3 |
| `line.split(/,(?=(?:[^"]*"[^"]*")*[^"]*$)/)` | `['1','"Smith, John"','"said ""hi"""']` |
| `matchAll(/("(?:[^"]\|"")*"\|[^,]*)(?:,\|$)/g)` | ті самі 3 поля |

Перший вираз ділить по комі **лише якщо після неї парна кількість лапок** до кінця рядка (lookahead). Працює, але для справжнього CSV (переноси рядків усередині лапок, екранування) використовуйте парсер (наприклад, пакет `csv-parse`) дасть `['1', 'Smith, John', 'said "hi"']` і зніме лапки, чого regex не робить. Це межа застосування з розділу 19.

### 17.6. Ціни й валюти в тексті

Текст: `Laptop $1,299.99, phone €450, cable 12.50 USD, case 300 UAH, tax 15%.`

Число з тисячними розрядами: `\d{1,3}(?:,\d{3})+(?:\.\d+)?|\d+(?:\.\d+)?` — спочатку варіант із комами, потім звичайний (порядок гілок, розділ 3). Шаблон цілком (збираємо з частин через `new RegExp`):

```
[$€](?:NUM)|(?:NUM)\s?(?:USD|UAH|EUR)
```

Результат: `['$1,299.99','€450','12.50 USD','300 UAH']`; `15%` не зачеплено. Іменованими групами: `{cur: '$', amt: '1,299.99'}`, `{cur: '€', amt: '450'}`. Відсоток окремо: `/\d+(?:\.\d+)?(?=%)/g` → `['15']`.

Типова помилка: спрощений клас `[\d,]*` для числа **з'їдає кому після ціни** (`€450,`). Тисячі треба описувати **структурою** `(?:,\d{3})+`, а не набором символів.

### 17.7. Markdown: заголовки, посилання, виділення

```
# Title
Intro with [docs](https://a.dev/docs) and [site](http://b.org).
## Part 1
Text **bold** and *it*.
### Sub
```

| Задача | Шаблон | Результат |
|---|---|---|
| заголовки | `/^#{1,6}\s+.+$/gm` | `['# Title','## Part 1','### Sub']` |
| рівень і текст | `/^(#{1,6})\s+(.+)$/gm` | `[1,'Title']`, `[2,'Part 1']`, `[3,'Sub']` |
| посилання | `/\[([^\]]+)\]\(([^)]+)\)/g` | `[['docs','https://a.dev/docs'],['site','http://b.org']]` |
| жирний → HTML | `.replace(/\*\*(.+?)\*\*/g, '<b>$1</b>')` | `Text <b>bold</b> and *it*.` |

Тут працюють два прийоми: `^…$` з `m` для рядків і **заперечений клас** `[^\]]+` для вмісту дужок. Ліниве `.+?` в жирному потрібне, щоб не злити два виділення в одне.

### 17.8. Вихідний код: коментарі, `TODO`, `console.log`

```
const a = 1; // TODO: rename
console.log(a);
function f() { /* TODO fix */ return a; }
console.log("x", f());
// done
```

| Задача | Шаблон | Результат |
|---|---|---|
| однорядкові коментарі | `/\/\/.*$/gm` | `['// TODO: rename','// done']` |
| слово після `TODO` | `/TODO:?\s*(\w+)/g` | `['rename','fix']` |
| блокові коментарі | `/\/\*[\s\S]*?\*\//g` | `['/* TODO fix */']` |
| те саме з `s` | `/\/\*.*?\*\//gs` | `['/* TODO fix */']` |
| видалити рядки `console.log` | `.replace(/^\s*console\.log\(.*\);\n/gm, '')` | залишаються `const a…`, `function f…`, `// done` |

`[\s\S]` — «будь-який символ, включно з `\n`» (рівнозначно прапорцю `s`). Ліниве `*?` зупиняється на **першому** `*/`; жадібне `*` злило б усі блокові коментарі файлу в один. Застереження: regex не відрізнить `//` у рядку-літералі `"http://…"` від коментаря — для цього потрібен лексер (розділ 19).

### 17.9. Маскування чутливих даних

| Задача | Шаблон і заміна | Результат |
|---|---|---|
| картка: усе, крім 4 останніх цифр | `.replace(/\d(?=(?:\D*\d){4})/g, '*')` на `4111 1111 1111 1234` | `**** **** **** 1234` |
| те саме, групами | `.replace(/\d{4}(?= \d{4} \d{4} \d{4})/, '****')` | `**** 1111 1111 1234` (лише перша група) |
| email: усе перед `@`, крім першої літери | `.replace(/(?<=.).(?=[^@]*@)/g, '*')` на `john.smith@example.com` | `j*********@example.com` |

Перший шаблон читається так: «цифра, після якої (через будь-які нецифри) стоїть ще **рівно 4 цифри до кінця**» — lookahead рахує цифри праворуч, нічого не споживаючи.

### 17.10. HTML: що можна, а що ні

Текст: `<a class="x" href="/a">A</a> <a href='/b'>B</a> <img src="i.png"> <A HREF="/c">C</A>`

| Задача | Шаблон | Результат |
|---|---|---|
| адреси посилань | `/<a\s[^>]*?href=["']([^"']*)["']/gi` | `['/a','/b','/c']` |
| прибрати теги | `.replace(/<[^>]+>/g, '')` | `A B  C` |

Для **швидкого одноразового** витягу з відомого, простого HTML це працює (регістр, різні лапки враховано). Але вкладені теги, коментарі, `>` в атрибутах, `<script>` ламають будь-який шаблон; для постійного коду — `DOMParser`, `cheerio`, `BeautifulSoup`.

### 17.11. Кирилиця й Unicode

Текст: `Привіт, світе! Це м'яч — і ґанок. Test-case 42.`

| Шаблон | Результат |
|---|---|
| `/\w+/g` | `['Test','case','42']` — **кирилиця не збігається** (у JS `\w` — лише ASCII) |
| `/\p{L}+/gu` | `['Привіт','світе','Це','м','яч','і','ґанок','Test','case']` — апостроф і дефіс розбили слова |
| `/[\p{L}'’-]+/gu` | `['Привіт','світе','Це',"м'яч",'і','ґанок','Test-case']` |
| `/\p{Script=Cyrillic}+/gu` | лише кириличні фрагменти (без `Test`, `case`) |
| `/\p{Lu}\p{Ll}*/gu` | `['Привіт','Це','Test']` — слова з великої літери |

Правило: **для нелатинського тексту в JS — `\p{…}` з `u`**, а не `\w` і не `[а-я]`: виміряно `'ґєїі'.match(/[а-я]/g)` → `null` (діапазон `а-я` не містить `ґ`, `є`, `ї`, `і`).

### 17.12. Багаторядкові блоки

Текст:

```
BEGIN
a=1
END
noise
BEGIN
b=2
c=3
END
```

| Шаблон | Результат |
|---|---|
| `/BEGIN\n([\s\S]*?)\nEND/g` | 2 блоки; групи `['a=1','b=2\nc=3']` |
| `/BEGIN[\s\S]*END/g` | **1** збіг — жадібний, від першого `BEGIN` до останнього `END` |
| `/^BEGIN$[\s\S]*?^END$/gm` | 2 збіги — з якорями рядків |

Для блоків між маркерами завжди **ліниве** `*?` і **`s`** (або `[\s\S]`).

### 17.13. Дрібні, але частіші задачі

| Задача | Рішення | Результат |
|---|---|---|
| дати в різних записах | `/\b\d{1,2}[./]\d{1,2}[./]\d{4}\b\|\b\d{4}-\d{2}-\d{2}\b/g` на `15.11.2025, 1.2.2024, 31/12/2023, 2025-11-15` | усі 4 дати |
| розділити по пробільних | `'a  b\t\tc\n\nd'.split(/\s+/)` | `['a','b','c','d']` |
| кілька роздільників | `'one, two;three  four'.split(/[,;\s]+/)` | `['one','two','three','four']` |
| поміняти слова місцями | `'Hello World'.replace(/(?<first>\w+) (?<second>\w+)/, '$<second> $<first>')` | `World Hello` |
| snake → camel | `'snake_case_name'.replace(/_(\w)/g, (_, c) => c.toUpperCase())` | `snakeCaseName` |
| розрізати camelCase | `'HelloWorldFooBar'.split(/(?=[A-Z])/)` | `['Hello','World','Foo','Bar']` |

`split` із **порожнім збігом** (lookahead без символів) ріже між символами, не втрачаючи їх.

### 17.14. Як діяти, коли шаблон «не працює»

| Симптом | Найімовірніша причина | Що зробити |
|---|---|---|
| збігів немає | не екрановано метасимвол; зайві якорі; не той регістр | вимкніть якорі, додайте `i`, екрануйте `.`, `(`, `?` |
| збіг занадто довгий | жадібне `.*` | `[^x]*` або `.*?` |
| збіг один замість багатьох | немає `g` | додайте `g` (для групи в кожному збігу — `matchAll`) |
| зайві збіги всередині слів | немає `\b` | оточіть `\b…\b` |
| `^`/`$` бачать лише початок і кінець тексту | немає `m` | додайте `m` |
| `.` не збігається з переносом | немає `s` | додайте `s` або `[\s\S]` |
| кирилиця не збігається | `\w` / `[a-z]` | `\p{L}` з `u` (JS) |
| `match` з `g` не дає груп | `g` повертає лише тексти збігів | `matchAll` або `exec` у циклі |
| повільно на «майже збігах» | вкладені квантифікатори | розділ 18 |

Робочий прийом: **розбирайте шаблон на частини й перевіряйте кожну окремо** (`/\[[^\]]+\]/` — чи знаходить дужки з часом?), потім склеюйте. У JS частини збирають через `new RegExp(a.source + b.source)`.

## 18. Продуктивність і ReDoS

### Катастрофічний backtracking
Вкладені квантифікатори над перекривними варіантами (`(a+)+`, `(a|aa)+`, `(.*)*`) можуть дати **експоненційний** час на рядку, який майже збігається. Виміряно (шаблон `^(a+)+$` на рядку з n літер `a` і `b` в кінці):

| n | JS (Node 24) |
|---|---|
| 20 | 35 мс |
| 24 | 110 мс |
| 26 | 434 мс |

Кожні **два** додаткові символи ≈ ×4 часу (час подвоюється з кожним). Для n = 40 це були б години. Безпечний шаблон `^a+$` на тому ж рядку з 100 000 символів — **0,37 мс** (JS).

Така вразливість називається **ReDoS** (regular expression denial of service): зловмисник надсилає «отруєний» рядок, і один запит блокує процес.

Як уникнути:
1. не вкладайте квантифікатори над однаковим набором символів (`(a+)+`);
2. робіть гілки альтернації **взаємовиключними** (`(?:a|b)`, а не `(?:a|a?)`);
3. використовуйте **заперечені класи** замість `.*` (`[^"]*` для вмісту лапок);
4. обмежуйте довжину вхідного тексту до перевірки;
5. для недовіреного вводу — рушій без backtracking (RE2, Rust `regex`, Go);
6. посесивні квантифікатори й атомарні групи там, де вони є (виміряно в Perl: `(?>a+)` і `a++` не повертаються);
7. таймаут (у JS стандартного немає — виконуйте перевірку недовіреного вводу в окремому воркері; у .NET є `matchTimeout`).

### Інші поради
- Анкеруйте шаблон (`^`, `\b`), якщо це можливо: рушій швидше відкидає позиції.
- Виносьте скомпільований шаблон із циклу (JS-літерал поза циклом — але уважно з `g`/`lastIndex`).
- Ліниві `.*?` — не обов'язково швидші: порівняйте з `[^x]*`.
- Для простого «містить підрядок» `str.includes`/`in` швидші й зрозуміліші, ніж регекс.

## 19. Безпека та межі застосування

- **Користувацький ввід як шаблон** — завжди екранувати (`RegExp.escape` / ручне екранування), інакше користувач може зламати шаблон або викликати ReDoS.
- **HTML, XML, JSON, вкладені дужки** регулярним виразом не розібрати: вони мають довільну вкладеність. Використовуйте парсер. Регекс допустимий для швидкої екстракції з відомого, вузького формату.
- **Валідація ≠ повна коректність.** Шаблон для email/дати/телефону перевіряє форму, а не реальне існування.
- Не покладайтесь на регекс як на **санітизацію** безпеки (XSS, SQL-ін'єкції): блокуйте екрануванням і параметризованими запитами.

## 20. Налагодження

- Дозволяйте собі розбивати шаблон: збирайте його з частин через `.source` (розділ 14).
- Перевіряйте шаблон інтерактивними інструментами (regex101.com, regexr.com, вбудований пошук редактора) — вони показують розбір на групи і кроки.
- У JS прапорець `d` дає позиції груп: `'xaby'.match(/a(b)/d).indices[1]` → `[2, 3]`.
- Виводьте не лише «збіглось/ні», а **що** збіглось і яке `index`: майже всі помилки — у межах збігу або жадібності.
- Пишіть **негативні тести**: рядки, які НЕ повинні збігатися (`2025-13-45`, `256.1.1.1`).

## 21. Типові помилки

1. Забути екранувати `.` у `a.c`, і шаблон збігається з `abc`.
2. Жадібне `.*` там, де потрібне ліниве або `[^x]*`.
3. Забути якорі `^…$` при валідації (без них `/\d+/` «підходить» для `a1b`).
4. `match` без `g` бере лише перший збіг, а з `g` — лише тексти без груп; для груп усіх збігів потрібен `matchAll`.
5. `matchAll` або `replaceAll` з регулярним виразом без `g` — `TypeError`.
6. `\d`/`\w` для кирилиці в JS (ASCII); `\p{L}` з `u`.
7. Рядок JS `new RegExp('\\d')`: пропустили подвоєння слеша (`'\d'` = `'d'`).
8. Забути `u` для емодзі й символів поза BMP: `'😀'.match(/./)[0].length` → `1` (половина символа), з `u` → `2`.
9. `g`-регекс як змінна з `.test()` → «через раз».
10. `split` із групою в шаблоні додає роздільники до результату.
11. Нумерація груп збивається при додаванні нових дужок — іменовані або `(?:...)`.
12. Нескінченні/порожні збіги: `x*` у `replace` дає вставки між символами.
13. Альтернація без дужок: `^cat|dog$`.
14. `\d` у `sed -E` на macOS — це літера d; використовуйте `[0-9]`.
15. `grep -P` на macOS не існує.
16. Вкладені квантифікатори над перекривними варіантами → ReDoS.
17. Валідація email «ідеальним» регексом на 500 символів.
18. Парсити HTML регулярними виразами.
19. Не екранувати користувацький ввід у шаблоні.
20. Не тестувати негативні приклади.

## 22. Алгоритм побудови регулярного виразу

1. Зберіть **позитивні й негативні** приклади (що має збігатись, що ні).
2. Визначте, що саме потрібно: перевірка всього рядка (`^…$`), пошук (без якорів), витяг (групи), заміна (групи + шаблон заміни).
3. Опишіть структуру словами: «4 цифри, дефіс, 2 цифри…».
4. Перекладіть частини в класи й квантифікатори; **заперечений клас** замість `.*`.
5. Згрупуйте повторювані частини `(?:...)`; те, що треба витягти, — в **іменовані** групи.
6. Для контексту без захоплення — lookaround (де підтримує діалект).
7. Додайте якорі й прапорці (`i`, `m`, `u`).
8. Перевірте на всіх прикладах, особливо на **негативних і крайніх** (порожній рядок, дуже довгий, Unicode, переноси рядків).
9. Перевірте на ReDoS: чи немає вкладених квантифікаторів, спробуйте «майже збіг» довжиною 30–50 символів.
10. Якщо шаблон > ~80 символів — розбийте (verbose / частини), додайте коментарі, або використайте парсер.

## 23. Шпаргалка

| Потрібно | Запис |
|---|---|
| будь-який символ (без `\n`) | `.` |
| цифра / не цифра | `\d` / `\D` |
| літера-цифра-підкреслення | `\w` |
| пробіл-подібний | `\s` |
| один із | `[abc]` |
| діапазон | `[a-z]` |
| ні один із | `[^abc]` |
| не `\w` / не `\s` | `\W` / `\S` |
| POSIX-клас (grep, sed, awk) | `[[:alpha:]]`, `[[:digit:]]`, `[[:space:]]` |
| літера будь-якої мови (JS з `u`) | `\p{L}` |
| 0 або більше / 1 або більше / 0 або 1 | `*` / `+` / `?` |
| рівно n / n і більше / від n до m | `{n}` / `{n,}` / `{n,m}` |
| лінивий | `+?` `*?` `??` `{n,m}?` |
| посесивний (Perl, PCRE, Java) | `*+` `++` `?+` |
| або | `a\|b` |
| початок / кінець | `^` / `$` |
| початок / кінець усього тексту (PCRE, Perl; у JS немає) | `\A` / `\Z` |
| межа слова / не межа | `\b` / `\B` |
| новий рядок, табуляція, `\r` | `\n`, `\t`, `\r` |

## Підсумок

- Регулярний вираз — шаблон, що описує множину рядків; рушій з backtracking шукає **найлівіший** збіг і бере **перший успішний** варіант, а не найкращий.
- Базові блоки: літерали, класи, скорочення, якорі, квантифікатори (жадібні/ліниві), групи, альтернація, lookaround, backreference.
- Діалекти відрізняються: довжина lookbehind, `\d`/`\w` (ASCII у JS), `\p{…}`, посесивні й атомарні групи, умовні вирази (у JS немає), а BSD `sed`/`grep` мають ще менше можливостей.
- JS: `lastIndex` у `g`/`y`, `match` / `matchAll` / `exec`, `$1`/`$<n>` у заміні, `\p{…}` з `u`, збирання з частин через `source`.
- Командний рядок: `grep -E`, `sed -E`, `awk`; для lookaround — `perl`; на macOS `\d`/`\w` у `sed` не працюють.
- Продуктивність: уникайте вкладених квантифікаторів; `^(a+)+$` на 24 символах — 110 мс, на безпечному шаблоні — менше мілісекунди.
- Не парсьте HTML регексами, екрануйте користувацький ввід, тестуйте негативні приклади.
