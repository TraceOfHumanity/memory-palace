# Math — вбудований об'єкт для математичних операцій

## 1. Що таке Math

`Math` — це не конструктор і не клас: це звичайний, готовий об'єкт (singleton), який існує в глобальному просторі одразу. У нього немає конструктора — `new Math()` кине `TypeError`. Усі методи — статичні (викликаються напряму через `Math.method()`, а не через екземпляр), і всі вони — чисті функції (крім `Math.random()`) — не мають стану і не залежать ні від чого, окрім своїх аргументів.

```js
console.log(typeof Math); // "object"
// new Math(); // TypeError: Math is not a constructor
```

## 2. Константи Math — готові числові значення

```js
console.log(Math.PI); // 3.141592653589793 — довжина півкола одиничного радіуса
console.log(Math.E); // 2.718281828459045 — основа натурального логарифма
console.log(Math.LN2); // 0.6931471805599453 — натуральний логарифм від 2
console.log(Math.LN10); // 2.302585092994046 — натуральний логарифм від 10
console.log(Math.LOG2E); // 1.4426950408889634 — логарифм від E за основою 2
console.log(Math.LOG10E); // 0.4342944819032518 — логарифм від E за основою 10
console.log(Math.SQRT2); // 1.4142135623730951 — квадратний корінь з 2
console.log(Math.SQRT1_2); // 0.7071067811865476 — квадратний корінь з 1/2
```

Усі константи `Math` — це властивості, а не методи (звертання без дужок). Вони non-writable, non-enumerable, non-configurable — спробувати змінити `Math.PI` просто мовчки не спрацює (у нестрогому режимі):

```js
Math.PI = 3;
console.log(Math.PI); // 3.141592653589793 — значення незмінне

// Для округленого відображення числа використовують toFixed()
// (метод Number, не Math — детально нижче, у розділі "округлення"):
console.log(Math.PI.toFixed(2)); // "3.14" — повертає рядок, не число!
```

## 3. Округлення: round / floor / ceil / trunc — чотири різні стратегії

```js
// Math.round(x) — округлення до найближчого цілого (за стандартними
// правилами "округлення половини вгору" — .5 завжди йде до +Infinity,
// це важливо для від'ємних чисел):
console.log(Math.round(3.5)); // 4
console.log(Math.round(3.4)); // 3
console.log(Math.round(-3.5)); // -3 !!! — округлення "половини вгору", а не "від нуля"
console.log(Math.round(-3.6)); // -4

// Math.floor(x) — округлення "вниз" (до -Infinity), незалежно від знаку:
console.log(Math.floor(3.9)); // 3
console.log(Math.floor(-3.1)); // -4 — "вниз" означає "менше", а не "ближче до нуля"

// Math.ceil(x) — округлення "вгору" (до +Infinity):
console.log(Math.ceil(3.1)); // 4
console.log(Math.ceil(-3.9)); // -3

// Math.trunc(x) (ES6) — просто відкидає дробову частину, без округлення:
console.log(Math.trunc(3.9)); // 3
console.log(Math.trunc(-3.9)); // -3 — на відміну від floor(), який дав би -4!
```

Порівняльна таблиця на `-3.5` і `3.5`:

| Функція | `3.5` | `-3.5` |
|---|---|---|
| `round` | 4 | -3 |
| `floor` | 3 | -4 |
| `ceil` | 4 | -3 |
| `trunc` | 3 | -3 |

Найчастіша помилка: використовувати `round()` там, де насправді потрібен `trunc()` (наприклад, «просто відкинути дробову частину»). Для позитивних чисел `floor()` і `trunc()` дають однаковий результат, але для негативних — ні, тож підміна `floor()` на `trunc()` (чи навпаки) у коді, що працює з від'ємними числами, — джерело «тихих» багів.

## 4. Степені та корені

```js
console.log(Math.pow(2, 3)); // 8 — 2 в степені 3
console.log(2 ** 3); // 8 — сучасний оператор **, робить те саме (ES2016)
console.log(Math.pow(2, 0.5)); // 1.4142135623730951 — те саме, що sqrt(2)

console.log(Math.sqrt(16)); // 4 — квадратний корінь (лише для x >= 0, інакше NaN)
console.log(Math.sqrt(-1)); // NaN — від'ємне число немає дійсного кореня
console.log(Math.cbrt(8)); // 2 — кубічний корінь (працює і для від'ємних!)
console.log(Math.cbrt(-8)); // -2 — на відміну від sqrt(), приймає від'ємні числа

// Math.hypot(...values) (ES6) — довжина гіпотенузи / евклідова норма
// вектора: sqrt(a² + b² + c² + ...), але математично стабільніше за
// ручний запис (уникає переповнення/втрати точності на екстремальних
// значеннях):
console.log(Math.hypot(3, 4)); // 5 — класичний "трикутник 3-4-5"
console.log(Math.hypot(3, 4, 12)); // 13 — працює для будь-якої кількості вимірів
```

## 5. Мінімум, максимум, знак, модуль

```js
console.log(Math.max(1, 2, 3, 4, 5)); // 5
console.log(Math.min(1, 2, 3, 4, 5)); // 1

// Math.max()/Math.min() приймають аргументи через кому, а не масив —
// для масиву потрібен spread (...):
const numbersForMinMax = [4, 2, 9, 1, 7];
console.log(Math.max(...numbersForMinMax)); // 9
console.log(Math.min(...numbersForMinMax)); // 1

// Без аргументів — "нейтральні" для подальшого порівняння значення:
console.log(Math.max()); // -Infinity — "програє" будь-якому реальному числу
console.log(Math.min()); // Infinity — те саме навпаки

// Якщо будь-який аргумент не приводиться до числа — результат NaN,
// і це "заражує" весь виклик (навіть якщо решта — коректні числа):
console.log(Math.max(1, 2, "text")); // NaN

// Math.sign(x) — повертає знак числа: -1, 0, -0 чи 1 (або NaN, якщо
// вхід не число):
console.log(Math.sign(-3)); // -1
console.log(Math.sign(3)); // 1
console.log(Math.sign(0)); // 0
console.log(Math.sign(-0)); // -0 — зберігає навіть знак нуля!
console.log(Math.sign("x")); // NaN

// Math.abs(x) — модуль (абсолютне значення), завжди >= 0:
console.log(Math.abs(-3)); // 3
console.log(Math.abs(3)); // 3
console.log(Math.abs("-5")); // 5 — рядок неявно приводиться до числа
```

## 6. Випадкові числа: Math.random()

`Math.random()` — єдиний метод `Math`, що не є чистою функцією: щоразу повертає інше псевдовипадкове число з півввідкритого діапазону `[0, 1)` — 0 включно, 1 ніколи не включається.

```js
console.log(Math.random()); // наприклад, 0.7834521...

// Найпоширеніший патерн: випадкове ціле число в діапазоні [min, max]
// (включно з обома кінцями):
function randomInt(min, max) {
  return Math.floor(Math.random() * (max - min + 1)) + min;
}
console.log(randomInt(1, 6)); // "кидок кубика" — ціле число від 1 до 6
```

Чому саме `floor()`, а не `round()`: `round()` дав би нерівномірний розподіл — межові значення (`min` і `max`) випадали б приблизно вдвічі рідше за середні, бо для них «влучає» лише половина інтервалу округлення, а не ціла.

`Math.random()` не придатний для криптографії/безпеки — для цього існує спеціальний API `crypto.getRandomValues()` (поза `Math`).

## 7. Логарифми та експонента

```js
console.log(Math.exp(1)); // 2.718281828459045 — e^1 (те саме, що Math.E)
console.log(Math.exp(0)); // 1 — e^0
console.log(Math.expm1(1)); // 1.718281828459045 — e^x - 1, точніше для малих x,
// ніж Math.exp(x) - 1 через плаваючу кому

console.log(Math.log(Math.E)); // 1 — натуральний логарифм (за основою e)
console.log(Math.log(1)); // 0
console.log(Math.log(0)); // -Infinity
console.log(Math.log(-1)); // NaN — логарифм від'ємного числа не визначений

console.log(Math.log2(8)); // 3 — логарифм за основою 2 (скільки разів ділити 8 навпіл до 1)
console.log(Math.log10(100)); // 2 — логарифм за основою 10 (кількість нулів)
```

Чому `Math.log2()`/`Math.log10()` існують окремо, а не через ручний перерахунок `Math.log(x) / Math.log(2)` — точність: пряме обчислення уникає накопичення похибки округлення, властивого діленню двох приблизних значень:

```js
console.log(Math.log(8) / Math.log(2)); // 3
console.log(Math.log2(8)); // 3 — так само точно
```

> ⚠️ **Реальний вимір**: в оригінальному файлі стверджувалось, що `Math.log(8) / Math.log(2)` дає `2.9999999999999996` через накопичену похибку округлення. На цій машині (Node.js v24, той самий рушій V8, що й в інших нотатках цієї серії) обидва вирази дають рівно `3`. Це не помилка старого твердження як принципу — ручне ділення логарифмів дійсно може накопичувати похибку округлення на інших аргументах чи інших реалізаціях `Math.log` — просто саме для `Math.log(8) / Math.log(2)` конкретна версія V8 тут не показує розбіжності. Загальна порада лишається чинною: для степенів двійки й десятки використовуйте `Math.log2`/`Math.log10` напряму, а не ручний перерахунок — це і точніше за задумом, і не залежить від того, пощастить чи ні з конкретними числами на конкретному рушії.

## 8. Тригонометрія (у радіанах, не в градусах!)

Усі тригонометричні функції `Math` працюють з радіанами. Якщо є градуси — потрібно самостійно конвертувати: `radians = degrees * (Math.PI / 180)`.

```js
function degreesToRadians(deg) {
  return deg * (Math.PI / 180);
}
function radiansToDegrees(rad) {
  return rad * (180 / Math.PI);
}

console.log(Math.sin(Math.PI / 2)); // 1 — синус 90°
console.log(Math.cos(Math.PI)); // -1 — косинус 180°
console.log(Math.tan(Math.PI / 4)); // 0.9999999999999999 — тангенс 45° (майже 1,
// похибка через представлення чисел з плаваючою комою)

console.log(Math.sin(degreesToRadians(90))); // 1 — той самий результат через явну конвертацію

// Обернені тригонометричні функції (arc-функції) повертають радіани:
console.log(Math.asin(1)); // 1.5707963267948966 (= π/2)
console.log(Math.acos(-1)); // 3.141592653589793 (= π)
console.log(Math.atan(1)); // 0.7853981633974483 (= π/4)

// Math.atan2(y, x) — особливо важлива функція: кут (у радіанах) між
// віссю X та точкою (x, y), з урахуванням знаків обох координат —
// на відміну від atan(y/x), правильно визначає чверть координатної
// площини (критично для геометрії, ігор, навігації):
console.log(Math.atan2(1, 1)); // 0.7853981633974483 (= π/4, перша чверть)
console.log(Math.atan2(1, -1)); // 2.356194490192345 (третя за atan2, друга чверть)
console.log(Math.atan(1 / -1)); // -0.7853981633974483 — atan() "не бачить" різницю
// чвертей, бо (1/-1) === (-1/1) арифметично
```

console.log(Math.sinh(1)); // 1.1752011936438014 — гіперболічний синус

## 10. Низькорівневі бітові/числові утиліти (ES6, рідко потрібні напряму)

```js
// Math.clz32(x) — count leading zeros: кількість нулів на початку 32-бітного
// (беззнакового) представлення числа:
console.log(Math.clz32(1)); // 31 — 1 у 32-біт: 00000000000000000000000000000001
console.log(Math.clz32(0)); // 32 — усі 32 біти нульові
console.log(Math.clz32(2147483648)); // 0 — старший біт уже одиниця, нулів немає
// Використовується у низькорівневих оптимізаціях (наприклад, швидке
// обчислення log2 для цілих степенів двійки).

// Math.imul(a, b) — 32-бітне цілочисельне множення (як у C/Java int*int),
// з коректним переповненням (overflow), на відміну від звичайного *,
// який працює через double і втрачає точність на дуже великих числах:
console.log(Math.imul(2, 3)); // 6 — для малих чисел як звичайне *
console.log(Math.imul(0xffffffff, 5)); // -5 — коректне 32-бітне переповнення
console.log(0xffffffff * 5); // 21474836475 — звичайне * тут не переповнюється,
// бо працює через double, інший результат

// Math.fround(x) — округлює число до найближчого 32-бітного
// float-значення (замість "рідного" для JS 64-бітного double):
console.log(Math.fround(1.5)); // 1.5 — точно представляється й у 32-бітах
console.log(Math.fround(1.1)); // 1.100000023841858 — втрата точності через 32-біт округлення
console.log(Math.fround(1.1) === 1.1); // false — видно різницю
```

Детально про `clz32`/`imul` у контексті бітових операцій і хешів — [bitwise-operations.md](bitwise-operations.md). `Math.fround` застосовується при роботі з `Float32Array` — щоб проміжні обчислення відповідали точності, яку реально матиме значення після запису в 32-бітний типізований масив ([TypedArray.js](data-structures/Array/TypedArray.md)).

## 11. Чому Math не завжди дає «математично ідеальний» результат

Усі числа в JS — це IEEE 754 double (64-біт число з плаваючою комою) — і `Math` просто оперує цим самим представленням. Звідси — класичні «неточності», що не є багом самого `Math`, а властивістю представлення дробових чисел узагалі:

```js
console.log(0.1 + 0.2); // 0.30000000000000004 — класична пастка
console.log(Math.abs(0.1 + 0.2 - 0.3) < Number.EPSILON); // true — правильний спосіб
// порівнювати дробові числа "з допуском"

// Number.EPSILON — найменша різниця між 1 і наступним представленим
// числом з плаваючою комою — стандартний "допуск" для порівняння:
console.log(Number.EPSILON); // 2.220446049250313e-16
```

## 12. Найчастіші практичні патерни

```js
// а) обмеження значення в межах діапазону (clamp) — теж часто через
// Math.min/Math.max разом (детально розглянуто з погляду branch
// prediction в performance/08-branch-prediction.md):
function clamp(value, min, max) {
  return Math.min(Math.max(value, min), max);
}
console.log(clamp(150, 0, 100)); // 100
console.log(clamp(-10, 0, 100)); // 0
console.log(clamp(50, 0, 100)); // 50

// б) округлення числа до N знаків після коми (без рядкового toFixed,
// повертає саме число, а не рядок):
function roundTo(value, decimals) {
  const factor = 10 ** decimals;
  return Math.round(value * factor) / factor;
}
console.log(roundTo(3.14159, 2)); // 3.14 (число, не рядок)

// в) сума/середнє масиву чисел (Math тут дає лише max/min/hypot;
// саму суму рахують через reduce, Math у цьому не бере участі
// напряму — наведено для контрасту з тим, чого Math не вміє):
const values = [4, 8, 15, 16, 23, 42];
const sum = values.reduce((acc, n) => acc + n, 0);
const average = sum / values.length;
console.log(sum, average.toFixed(2)); // 108 18.00

// г) відстань між двома точками на площині — типове застосування hypot():
function distance(x1, y1, x2, y2) {
  return Math.hypot(x2 - x1, y2 - y1);
}
console.log(distance(0, 0, 3, 4)); // 5
```

## Підсумок

- `Math` — готовий, статичний об'єкт-набір утиліт, не конструктор; усі методи, крім `random()`, — чисті функції.
- Константи (`PI`, `E`, `LN2`...) — властивості, не методи, і незмінні.
- `round`/`floor`/`ceil`/`trunc` — чотири різні стратегії округлення, що дають різні результати саме на від'ємних числах.
- `pow()`/`**` — степінь; `sqrt()`/`cbrt()` — корені (`cbrt` працює й для від'ємних, `sqrt` — ні); `hypot()` — довжина гіпотенузи/вектора.
- `max()`/`min()` приймають аргументи через кому (не масив — потрібен spread), без аргументів дають `-Infinity`/`Infinity` відповідно.
- `random()` — єдиний нечистий метод, повертає `[0, 1)`; для цілого діапазону — `floor(random() * (max - min + 1)) + min`.
- Усі тригонометричні функції працюють у радіанах, не в градусах; `atan2(y, x)` правильно враховує чверть координатної площини, на відміну від `atan(y / x)`.
- `clz32`/`imul`/`fround` — низькорівневі бітові утиліти для точної 32-бітної арифметики (рідко потрібні поза спеціалізованим кодом).
- `Math` працює з тим самим IEEE 754 double, що й усі числа в JS — звідси й класичні неточності (`0.1 + 0.2 !== 0.3`); для порівняння дробових чисел використовуй допуск через `Number.EPSILON`.
- Навіть точні на вигляд твердження про накопичення похибки округлення варто перевіряти на конкретній версії рушія — вона не завжди відтворюється однаково (розділ 7).

## 13. Повний перелік Math (Node 24 / V8): 8 констант, 35 методів

Усе, що повертає `Object.getOwnPropertyNames(Math)`: константи `E LN10 LN2 LOG10E LOG2E PI SQRT1_2 SQRT2` та методи
`abs acos acosh asin asinh atan atan2 atanh cbrt ceil clz32 cos cosh exp expm1 f16round floor fround hypot imul log log10 log1p log2 max min pow random round sign sin sinh sqrt tan tanh trunc`.
Плюс `Math[Symbol.toStringTag]`. `Math.f16round` (ES2025) у Node 24 є; `Math.sumPrecise` — ще ні (`typeof` → `undefined`).

Кількість параметрів (`fn.length`): `atan2` = 2, `pow` = 2, `imul` = 2, `hypot` = 2, `max` = 2, `min` = 2, `random` = 0, решта = 1. (`hypot/max/min` приймають скільки завгодно аргументів — `length` лише орієнтир.)

| Група | Методи | Вхід | Результат |
|---|---|---|---|
| Округлення | `round floor ceil trunc` | 1 число | ціле |
| Знак/модуль | `sign abs` | 1 | `-1/0/-0/1` / `≥ 0` |
| Порівняння | `max min` | 0…N | число (`-Infinity`/`Infinity` без аргументів) |
| Степені | `pow sqrt cbrt hypot` | 1–N | число |
| Експонента/логарифми | `exp expm1 log log1p log2 log10` | 1 | число |
| Тригонометрія | `sin cos tan asin acos atan atan2` | радіани / відношення | радіани / відношення |
| Гіперболічні | `sinh cosh tanh asinh acosh atanh` | 1 | число |
| Низький рівень | `clz32 imul fround f16round` | 1–2 | 32-бітні значення |
| Випадкове | `random` | — | `[0, 1)` |

## 14. Властивості самого об'єкта Math (виміряно)

```js
Object.prototype.toString.call(Math);   // "[object Math]"
typeof Math;                            // "object"
new Math();   // TypeError: Math is not a constructor
Math();       // TypeError: Math is not a function
Object.keys(Math).length;               // 0   (усе non-enumerable)
JSON.stringify(Math);                   // "{}"
Object.getPrototypeOf(Math) === Object.prototype;   // true
```
- Константи: `writable: false, enumerable: false, configurable: false`. У строгому режимі `Math.PI = 3` → `TypeError: Cannot assign to read only property 'PI' of object '#<Object>'`.
- **Методи** — `writable: true, enumerable: false, configurable: true`: `Math.abs = 1` спрацює (!) — так можна зламати (або «запатчити») `Math`. Не роби цього.
- `Math[Symbol.toStringTag]` = `"Math"`, `writable: false, configurable: true`.
- Можна додавати власні властивості (`Math.foo = 1`) — не варто.

## 16. Округлення — граничні випадки (виміряно)

- `Math.round(2.5)` = `3`, `Math.round(-2.5)` = `-2`, `Math.round(0.5)` = `1`, `Math.round(-0.5)` = **`-0`**, `Math.round(-0.2)` = **`-0`**. `Math.round(x)` = `Math.floor(x + 0.5)` за змістом.
- `Math.round(0.49999999999999994)` = `0` (правильно; наївне `floor(x+0.5)` дало б 1).
- `Math.floor(-0)` = `-0`, `Math.ceil(-0.5)` = **`-0`**, `Math.trunc(-0.9)` = **`-0`**. `-0 === 0` → `true`, але `Object.is(-0, 0)` → `false`, а `console.log(-0)` → `-0`.
- `Math.trunc('7.8')` = `7`, `Math.trunc(NaN)` = `NaN`, `Math.floor(-Infinity)` = `-Infinity`.
- `Math.trunc(2**40 + 0.5)` = `1099511627776`, а `(2**40+0.5) | 0` та `~~(2**40+0.5)` = **`0`** (побітові оператори обрізають до 32 біт!).
- `Math.round(1.005 * 100) / 100` = `1`, не `1.01`, бо `1.005 * 100` = `100.49999999999999`. `(1.005).toFixed(2)` = `"1.00"`. Обхід: `Math.round((1.005 + Number.EPSILON) * 100) / 100` = `1.01`.
- `toFixed` — не те саме, що `Math.round`: `(2.5).toFixed(0)` = `"3"`, `(0.5).toFixed(0)` = `"1"`, `(2.345).toFixed(2)` = `"2.35"`, але повертає **рядок**.
- Округлення «від нуля» (symmetric): `Math.sign(x) * Math.round(Math.abs(x))`: для `-2.5` → `-3` (а `Math.round(-2.5)` → `-2`).
- Для чисел > 2⁵² дробової частини немає: `Math.round(2**52 + 0.5)` = `4503599627370496`.
- `Math.round(Infinity)` = `Infinity`.

## 17. abs / sign / max / min — граничні випадки

- `Math.abs(-0)` = `0`, `Math.abs(-Infinity)` = `Infinity`, `Math.abs(-(2**31))` = `2147483648`. Зауваж: `-2**31` без дужок — **SyntaxError** (унарний мінус перед `**` заборонений).
- `Math.sign(-Infinity)` = `-1`, `Math.sign('5')` = `1`, `Math.sign(NaN)` = `NaN`.
- `Math.max(0, -0)` = `0`, `Math.min(0, -0)` = **`-0`** (метод враховує знак нуля).
- `Math.max(1, NaN, 3)` = `NaN`.
- **Ліміт аргументів:** `Math.max(...Array(200000).fill(1))` → `RangeError: Maximum call stack size exceeded`; те саме для `Math.max.apply(null, Array(1e6).fill(1))`. Для великих масивів — `reduce`: `arr.reduce((a, b) => Math.max(a, b), -Infinity)`.
- `Math.max(...[])` = `-Infinity`, `Math.max(...[-1,-2])` = `-1`.
- `clamp` з `NaN`: `Math.min(Math.max(NaN, 0), 100)` = `NaN`.

## 18. Степені та корені — граничні випадки

- `Math.pow(2, 10)` = `1024`; `Math.pow(2, -1)` = `0.5`; `Math.pow(2, 1024)` = `Infinity`.
- `Math.pow(-8, 1/3)` = `NaN` (дробовий степінь від'ємного), `Math.cbrt(-8)` = `-2`.
- `Math.pow(0, 0)` = `1`; `Math.pow(NaN, 0)` = `1`; `Math.pow(1, Infinity)` = `NaN` (у `Math.pow` і `**`).
- `Math.pow(-0, -1)` = `-Infinity`.
- `**` правоасоціативний: `2 ** 3 ** 2` = `512` (= `2 ** 9`).
- `(-2) ** 2` = `4`; `-2 ** 2` — SyntaxError.
- `Math.sqrt(-0)` = `-0`; `Math.sqrt(Infinity)` = `Infinity`; `Math.sqrt(2)` = `1.4142135623730951`.
- `Math.cbrt(27)` = `3`, `Math.cbrt(2)` = `1.2599210498948732`, `Math.cbrt(1e-300)` = `1e-100`.
- `Math.hypot()` = `0`; `Math.hypot(5)` = `5`; `Math.hypot(-5)` = `5`; `Math.hypot('3','4')` = `5`; `Math.hypot(NaN, Infinity)` = `Infinity`.
- **Переповнення:** `Math.hypot(1e200, 1e200)` = `1.414213562373095e+200`, а `Math.sqrt(1e200**2 + 1e200**2)` = `Infinity`.
- `Math.hypot(1, 2, 2)` = `3` (3D-відстань).

## 19. Експонента й логарифми — граничні випадки

- `Math.exp(0)` = `1`, `Math.exp(2)` = `7.38905609893065`, `Math.exp(-Infinity)` = `0`, `Math.exp(710)` = `Infinity` (поріг переповнення ≈ 709.78).
- **`expm1`** (e^x − 1) для малих x: `Math.expm1(1e-10)` = `1.00000000005e-10`, а `Math.exp(1e-10) - 1` = `1.000000082740371e-10` — похибка вже в 8-й цифрі.
- **`log1p`** (ln(1 + x)): `Math.log1p(1e-10)` = `9.999999999500001e-11`, а `Math.log(1 + 1e-10)` = `1.000000082690371e-10`. `Math.log1p(-1)` = `-Infinity`, `Math.log1p(-2)` = `NaN`.
- `Math.log(0)` = `-Infinity`, `Math.log(-0)` = `-Infinity`, `Math.log(Infinity)` = `Infinity`, `Math.log(10)` = `2.302585092994046`.
- `Math.log2(1024)` = `10`, `Math.log2(3)` = `1.584962500721156`, `Math.log2(0.5)` = `-1`, `Math.log2(-1)` = `NaN`.
- `Math.log10(1000)` = `3`, `Math.log10(0.001)` = `-3`, `Math.log10(5)` = `0.6989700043360189`, `Math.log10(0)` = `-Infinity`.
- **Реальний приклад похибки ділення логарифмів:** `Math.log(1000) / Math.log(10)` = **`2.9999999999999996`**, а `Math.log10(1000)` = `3`. `Math.log(125) / Math.log(5)` = `3.0000000000000004`. (А `Math.log(8)/Math.log(2)` = `3` — приклад, що не завжди видно.) Висновок: для основ 2 і 10 — `log2/log10`; для довільної основи — `Math.round(...)`, якщо результат має бути цілим.
- Кількість цифр числа: `Math.floor(Math.log10(12345)) + 1` = `5`; кількість біт: `Math.floor(Math.log2(1000)) + 1` = `10` (= `(1000).toString(2).length`).
- Складні відсотки: `1000 * Math.exp(0.05 * 10)` = `1648.7212707001281` (неперервне нарахування); `1000 * (1 + 0.05) ** 10` = `1628.894626777442` (щорічне).

## 20. Тригонометрія — граничні випадки

- `Math.sin(Math.PI)` = **`1.2246467991473532e-16`**, не `0`; `Math.cos(Math.PI/2)` = `6.123233995736766e-17`; `Math.tan(Math.PI/2)` = `16331239353195370` (не `Infinity`!); `Math.tan(Math.PI)` = `-1.2246467991473532e-16`.
- `Math.sin(Math.PI/6)` = `0.49999999999999994`; `Math.cos(Math.PI/3)` = `0.5000000000000001`.
- `Math.sin(30)` = `-0.9880316240928618` — це 30 **радіан**, не градусів.
- `Math.sin(Infinity)` = `NaN`.
- Градуси ↔ радіани: `deg * Math.PI / 180`, `rad * 180 / Math.PI`. `180 * (Math.PI/180)` = `3.141592653589793`.
- `Math.asin(0.5)` = `0.5235987755982989` (= π/6); `Math.asin(2)` = `NaN` (область −1…1); `Math.acos(0)` = `1.5707963267948966`; `Math.acos(0.5)` = `1.0471975511965979`; `Math.acos(-2)` = `NaN`.
- `Math.atan(Infinity)` = `1.5707963267948966`, `Math.atan(-Infinity)` = `-1.5707963267948966`.
- **`atan2(y, x)`** — порядок аргументів: **спочатку y, потім x**. Діапазон `(−π, π]`:
  `atan2(1,1)` = `0.7853981633974483` (45°), `atan2(1,-1)` = `2.356194490192345` (135°), `atan2(-1,-1)` = `-2.356194490192345` (−135°), `atan2(-1,1)` = `-0.7853981633974483`, `atan2(0,-1)` = `π`, `atan2(-0,-1)` = `-π`, `atan2(0,0)` = `0`, `atan2(1,0)` = `π/2`.
  Кут у градусах 0…360: `(Math.atan2(y, x) * 180 / Math.PI + 360) % 360`; для (−1,−1): `-135` → `225`.
  `atan2(3, 4)` у градусах = `36.86989764584402`.
- Полярні ↔ декартові: `x = r·cos(a)`, `y = r·sin(a)`; для r=2, a=π/3: `(1, 1.7321)`. Назад для (1, √3): `r = Math.hypot(x, y)` = `2`, `a = Math.atan2(y, x)·180/π` = `59.99999999999999°`.

## 21. Гіперболічні функції (виміряно)

`sinh(0)` = `0`, `sinh(1)` = `1.1752011936438014`; `cosh(0)` = `1`, `cosh(1)` = `1.5430806348152437`; `tanh(0)` = `0`, `tanh(1)` = `0.7615941559557649`, `tanh(100)` = `1`, `tanh(-Infinity)` = `-1`; `asinh(1)` = `0.881373587019543`; `acosh(1)` = `0`, `acosh(0.5)` = `NaN` (область x ≥ 1); `atanh(0.5)` = `0.5493061443340548`, `atanh(1)` = `Infinity`, `atanh(-1)` = `-Infinity`, `atanh(2)` = `NaN` (область −1…1).
Формули: `sinh x = (eˣ − e⁻ˣ)/2`, `cosh x = (eˣ + e⁻ˣ)/2`, `tanh x = sinh/cosh`. Сигмоїда: `1/(1+Math.exp(-x))`: x=2 → `0.8807970779778823`; `tanh(0.5)` = `0.46211715726000974`.

## 22. Бітові утиліти (виміряно)

- `Math.clz32`: `1` → `31`, `0` → `32`, `255` → `24`, `256` → `23`, `-1` → `0`, `0.9` → `32` (ToUint32 → 0), `2**32` → `32`, `NaN` → `32`, `1<<31` → `0`. Кількість біт числа n>0: `32 - Math.clz32(n)`.
- `Math.imul`: `imul(2,3)` = `6`; `imul(0xffffffff, 5)` = `-5`; `imul(-5, 12)` = `-60`; `imul(2**31, 2)` = `0`; `imul(65536, 65536)` = `0`, а `65536 * 65536` = `4294967296`; `imul(1.9, 2.9)` = `2` (аргументи спершу ToInt32 → 1 і 2); `imul(0x7fffffff, 0x7fffffff)` = `1`, а `0x7fffffff * 0x7fffffff` = `4611686014132420600` (з втратою точності).
- `Math.fround`: `5.5` → `5.5`; `5.05` → `5.050000190734863`; `0.1` → `0.10000000149011612`; `2**128` → `Infinity`; `1e-50` → `0`; `16777217` → `16777216` (float32 тримає цілі точно лише до 2²⁴); `Math.fround(0.1) === 0.1` → `false`.
- `Math.f16round` (ES2025): `0.1` → `0.0999755859375`; `1.337` → `1.3369140625`; `65504` → `65504` (макс. half-float); `65520` → `Infinity`; `1e-8` → `0`.

## 23. Константи — перевірені співвідношення

`Math.E === Math.exp(1)` → `true`; `Math.LN2 === Math.log(2)` → `true`; `Math.SQRT2 === Math.sqrt(2)` → `true`; `Math.LOG2E === 1/Math.LN2` → `true`; `Math.LOG10E` = `0.4342944819032518`, а `1/Math.LN10` = `0.43429448190325176` (не збігаються в останньому знаку!); `1/Math.SQRT2` = `0.7071067811865475`, а `Math.SQRT1_2` = `0.7071067811865476`.
Застосування: площа кола `Math.PI * r**2` (r=5 → `78.53981633974483`), довжина `2*Math.PI*r` (`31.41592653589793`), об'єм кулі `4/3*Math.PI*r**3` (r=3 → `113.09733552923254`).

## 24. Math.random — виміряно

- 10⁶ викликів: мін `2.88e-7`, макс `0.99999998…` — завжди `< 1`.
- `Math.floor(Math.random() * 6) + 1`: 600 000 кидків → `100055 99847 99765 100083 100211 100039` (рівномірно).
- `Math.round(Math.random() * 6)` (помилка): `49603 100264 99978 99921 100002 100258 49974` — крайні значення 0 і 6 випадають **вдвічі рідше**.
- Дійсне в діапазоні `[min, max)`: `Math.random() * (max - min) + min`.
- Перемішування `arr.sort(() => Math.random() - 0.5)` — **упереджене й не рекомендоване** (результат залежить від алгоритму сортування); правильно — Fisher–Yates: `for (let i = a.length - 1; i > 0; i--) { const j = Math.floor(Math.random() * (i + 1)); [a[i], a[j]] = [a[j], a[i]]; }`.
- Не можна задати seed — для відтворюваних послідовностей потрібен власний генератор (див. [seed-data.md](../utils/seed-data.md)); для безпеки — `crypto.getRandomValues`.

## 25. Корисне поруч із Math

- Залишок `%` ≠ математичний модуль: `7 % 3` = `1`, `-7 % 3` = `-1`, `((-7 % 3) + 3) % 3` = `2` (правильний mod), `5.5 % 2` = `1.5`, `-0 % 5` = `-0`.
- Лінійна інтерполяція: `lerp(a, b, t) = a + (b - a) * t`; `lerp(10, 20, 0.25)` = `12.5`.
- Числові константи Number: `Number.EPSILON` = `2.220446049250313e-16`, `MAX_SAFE_INTEGER` = `9007199254740991`, `MIN_VALUE` = `5e-324`, `MAX_VALUE` = `1.7976931348623157e+308`. За межею 2⁵³: `2**53 === 2**53 + 1` → `true`.
- Сума дробових: `[0.1,0.2,0.3].reduce((a,b)=>a+b)` = `0.6000000000000001`; з округленням `0.6`.

## 26. Типові помилки (підсумок)

1. `Math.round` для від'ємних «.5» — округлює до +∞ (`-2.5 → -2`).
2. `floor` замість `trunc` для від'ємних; `|0` / `~~` замість `trunc` для чисел > 2³¹.
3. `Math.max(array)` без spread (→ `NaN`); `Math.max(...hugeArray)` (→ RangeError).
4. Градуси замість радіанів.
5. `atan2(x, y)` замість `atan2(y, x)`.
6. `Math.round(Math.random() * n)` замість `floor(random() * (n + 1))`.
7. Порівняння дробових `===` — потрібен допуск (`Math.abs(a - b) < Number.EPSILON` для чисел біля 1).
8. `log(x) / log(b)` для цілих логарифмів — похибка (`log(1000)/log(10)` = `2.9999999999999996`).
9. `Math.round(x * 100) / 100` для грошей — `1.005 → 1`; використовуй цілі копійки.
10. Очікувати `Math.sin(Math.PI)` = `0` або `tan(π/2)` = `Infinity`.
11. `-2 ** 2` — SyntaxError; `Math.pow(-2, 2)` = `4`.
12. Перезаписувати `Math.abs` тощо — методи writable.
