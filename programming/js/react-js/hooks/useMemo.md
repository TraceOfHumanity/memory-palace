# React: `useMemo`

Виміряно на React 18.3.1 (`react-test-renderer`).

## 1. Що це

`useMemo(calculate, deps)` **запам'ятовує результат** обчислення між рендерами й перераховує його лише тоді, коли змінилась хоча б одна залежність.

```jsx
const sorted = useMemo(() => items.slice().sort(compare), [items]);
```

Сигнатура: `useMemo(() => значення, [залежності])`; повертає значення (не функцію).

## 2. Як це виконується покроково

1. **Перший рендер:** React викликає `calculate`, зберігає результат і масив залежностей у слоті.
2. **Наступний рендер:** React порівнює нові залежності зі збереженими **поелементно через `Object.is`**.
3. Усі однакові → повертається **збережений результат**, `calculate` не викликається.
4. Хоча б одна відрізняється → `calculate` викликається знову, результат і залежності оновлюються.

Виміряно: `useMemo(() => a * 2, [a])`, 3 рендери (`a = 1, 1, 2`, змінювався ще й `b`) → обчислено **2 рази** (на першому рендері й коли `a` змінилось).

## 3. Для чого використовують

1. **Дорогі обчислення** (фільтрація/сортування великих списків, складна математика). Критерій: помітно > 1 мс (вимірюй `console.time`/Profiler).
2. **Стабільне посилання на об'єкт/масив**, що йде як пропс у `React.memo`-компонент або як залежність іншого хука.
3. Уникнути «викликів з нуля» у `useEffect`-залежностях.

## 4. Це підказка, а не гарантія

React **може** викинути кеш (наприклад, для економії пам'яті чи в Offscreen/Suspense). Код має бути коректним і без `useMemo` — він лише оптимізація. Не клади в `useMemo` побічні ефекти.

## 5. Strict Mode

У розробці `calculate` викликається **двічі** на рендер (для виявлення нечистоти); результат використовується один. Виклик має бути чистим.

## 6. Пастка: нестабільні залежності

Залежності порівнюються за `Object.is`. Новий об'єкт/масив/функція створюється щоразу → кеш **ніколи не спрацьовує**. Виміряно: `useMemo(..., [{ x: a }])` → обчислено **3 рази за 3 рендери**.
```jsx
useMemo(() => f(), [{ x }])    // ✗ новий об'єкт щоразу
useMemo(() => f(x), [x])       // ✔ примітив
```

## 7. Пастка: хибне уявлення, що мемоізація безкоштовна

Саме `useMemo` теж має ціну (порівняння залежностей, пам'ять). Для дешевих обчислень (`a + b`, `list.length`) це **шкодить**. Спершу виміряй.

## 8. Пастка: застарілі значення

Якщо у `calculate` використовується значення, якого немає в `deps` — результат залишиться старим. Правило: **усе реактивне, що читається всередині, має бути в масиві залежностей** (правило eslint `react-hooks/exhaustive-deps`).

## 9. `useMemo` і `React.memo`

`useMemo` кешує **значення**, `React.memo` кешує **рендер компонента** за пропсами. Разом: `React.memo` не допоможе, якщо пропс — новий об'єкт щоразу; `useMemo` стабілізує посилання на цей об'єкт.

## 10. React Compiler

React Compiler (19) автоматично розставляє мемоізацію на рівні компілятора — ручні `useMemo`/`useCallback` стають необов'язковими в багатьох випадках.

## 11. Типові помилки

1. `useMemo` для кожного значення «про всяк випадок».
2. Нестабільні залежності (об'єкт у масиві залежностей).
3. Пропущені залежності → застарілий результат.
4. Асинхронний код чи побічні ефекти всередині.
5. Мутувати результат (`memoized.push(...)`) — зіпсуєте кеш.
6. Покладатися на `useMemo` як на гарантію (семантичну), а не оптимізацію.
7. Забути, що в dev `calculate` викликається двічі.

## 12. Алгоритм

1. Обчислення дороге (виміряно) або посилання має бути стабільним?
2. Ні → просто рахуй у рендері.
3. Так → `useMemo(() => ..., [усі реактивні значення])`.
4. Перевір, що залежності примітиви або стабільні посилання.
5. Переконайся Profiler'ом, що це справді допомагає.
