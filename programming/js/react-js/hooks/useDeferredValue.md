# React: `useDeferredValue`

Виміряно на React 18.3.1 і React 19 (`react-dom` + `jsdom`, `createRoot`).

## 1. Що це

`useDeferredValue(value)` повертає **«відкладену» копію** значення: спочатку **старе** значення, а коли React встигне — нове. Оновлення відкладеного значення рендериться з **низьким пріоритетом** і може бути перерване. Це аналог debounce, але **вбудований у рендер** і без фіксованої затримки.

```jsx
function Search({ query }) {
  const deferredQuery = useDeferredValue(query);
  return <Results query={deferredQuery} />;     // важкий компонент
}
```

## 2. Як це виконується (реальний вивід)

Компонент `App`: `t` змінюється `'a' → 'ab'`, `deferred = useDeferredValue(t)`, дочірній `Slow` (`React.memo`) отримує `deferred`.
```
App render t=ab deferred=a     ← 1. термінове: t нове, deferred ще старе → Slow не рендериться
App render t=ab deferred=ab    ← 2. фоновий рендер: deferred наздогнав
Slow render ab                 ← важкий компонент оновився
```
Кроки:
1. Значення змінюється → React рендерить **спершу зі старим** deferred (UI відгукується миттєво).
2. У фоні планує другий рендер з новим deferred (низький пріоритет).
3. Якщо значення знову змінилось до завершення — фоновий рендер **перериває** і починає з нового.
4. Дорогий дочірній компонент мусить бути обгорнутий `React.memo`, інакше він рендериться і в кроці 1 (пропс не змінився → memo його пропускає).

## 3. Початкове значення (React 19)

`useDeferredValue(value, initialValue)` — на **першому** рендері повертає `initialValue`, а відразу після планує рендер з `value`. Виміряно: `deferred=INITIAL v=real | deferred=real v=real`. Корисно, щоб швидко показати каркас, а важчу частину довантажити.

## 4. Відмінності від debounce/throttle

| | debounce | `useDeferredValue` |
|---|---|---|
| Затримка | фіксована (наприклад 300 мс) | **адаптивна** (залежить від швидкості пристрою) |
| Перериваність | ні | **так** |
| Зменшує мережеві запити | так | **ні** (це про рендер) |
| Потрібен таймер | так | ні |

Для **мережевих запитів** debounce усе ще потрібен; `useDeferredValue` оптимізує **рендер**.

## 5. Умови, за яких це працює

- Дочірній компонент **мемоізований** (`React.memo`) і дорогий.
- Відкладене значення передається в пропси, а **не** лише відображається (текст у `<p>` оновлюється миттєво й без користі).
- Для Suspense-даних: показується старий результат поки завантажуються нові (без fallback).

## 6. Типові помилки

1. Забути `React.memo` на важкому дочірньому компоненті → зайві рендери.
2. Очікувати, що це зменшить кількість запитів (воно лише відкладає рендер).
3. Відкладати значення, яке керує **полем введення** (воно має оновлюватись миттєво).
4. Передавати у `useDeferredValue` новий об'єкт щоразу → відкладена версія не «стабілізується».
5. Плутати з `useTransition`: тут значення, а не `setState`.
6. Показувати застарілі дані без індикатора — користувач не розуміє, що екран відстає (порівняй `value !== deferred`).

## 7. Індикація застарілості

```jsx
const stale = query !== deferredQuery;
<div style={{ opacity: stale ? 0.5 : 1 }}><Results query={deferredQuery} /></div>
```

## 8. Алгоритм

1. Є значення (пропс/стан) і важкий компонент, що від нього залежить.
2. `const d = useDeferredValue(value)` → передай `d` важкому компоненту.
3. Обгорни важкий компонент у `React.memo`.
4. Покажи індикацію `value !== d`.
5. Для запитів до мережі додатково debounce.
