# JavaScript: загальна характеристика

> «JavaScript: The World's Most Misunderstood Programming Language» — так у 2001 році Дуглас Крокфорд назвав власне есе, тезою якого було: мову широко використовують, але рідко розуміють. Ця назва дала ім'я корінню цієї бази знань.

## Ключові відомості

| Параметр | Характеристика |
|---|---|
| Автор | Брендан Айк, Brendan Eich (Netscape Communications) |
| Рік появи | 1995 |
| Специфікація | ECMAScript, стандарт ECMA-262 (комітет TC39) |
| Парадигми | мультипарадигмальна: прототипно-орієнтована, функціональна, імперативна, подієво-кероване програмування |
| Типізація | динамічна, слабка |
| Виконання | інтерпретація та JIT-компіляція у рушії |
| Керування пам'яттю | автоматичне (збирач сміття) |
| Основні рушії | V8, SpiderMonkey, JavaScriptCore |
| Розширення файлів | `.js`, `.mjs`, `.cjs` |

## 1. Історичний контекст

JavaScript створено 1995 року в компанії Netscape як скриптову мову для браузера Navigator. За загальновідомою версією, першу робочу версію Брендан Айк підготував приблизно за десять днів. Мова змінила кілька назв (Mocha, LiveScript) і отримала остаточну назву з маркетингових міркувань. Попри схожість імені, до мови Java вона не має жодного стосунку: різняться модель виконання, система типів і модель успадкування.

З метою уникнення розбіжностей між реалізаціями мову стандартизовано організацією Ecma International під назвою **ECMAScript**. Перша редакція стандарту вийшла 1997 року. Редакція ES2015 (ES6) стала найбільшим оновленням в історії мови: класи, модулі, `let`/`const`, стрілкові функції, `Promise`. Відтоді нові редакції виходять щороку. Кожна пропозиція проходить через послідовні стадії розгляду (від 0 до 4) в комітеті TC39.

Ключовою подією стало 2009 року створення Node.js: рушій V8 було винесено за межі браузера, і мова отримала повноцінну серверну екосистему.

## 2. Принципи дизайну

1. **Функції — значення першого класу.** Функцію можна зберігати у змінній, передавати як аргумент і повертати як результат. Разом із лексичними замиканнями це робить мову близькою до функціональних мов (Scheme), що часто залишається непоміченим через «Сі-подібний» синтаксис.
2. **Прототипне успадкування.** Об'єкти успадковують властивості безпосередньо від інших об'єктів, а не від класів. Ключове слово `class` (ES2015) є синтаксичним надбудовуванням над цим механізмом.
3. **Динамічність.** Тип має значення, а не змінна; структуру об'єкта можна змінювати під час виконання.
4. **Толерантність до помилок.** Мова прагне продовжувати виконання (неявні перетворення типів, `undefined` замість винятку). Це історично зумовлене середовищем браузера, але є джерелом більшості «сюрпризів».

## 3. Модель виконання

JavaScript виконується в **одному потоці** і спирається на **цикл подій** (event loop). Тривалі операції (мережа, файли, таймери) делегуються середовищу, а результат повертається через черги завдань: спочатку виконується синхронний код, потім черга мікрозавдань (`Promise`), потім макрозавдання (`setTimeout`, події вводу-виводу). Наслідок: жодна функція не переривається посеред виконання, але довга синхронна операція блокує все застосунок.

Сучасні рушії не інтерпретують код рядок за рядком: вони компілюють «гарячі» ділянки в машинний код (JIT) на основі спостережень за типами. Тому продуктивність залежить від стабільності форм об'єктів і типів (детально — у теці `performance/` цієї бази знань).

## 4. Система типів

Існує сім примітивних типів (`undefined`, `null`, `boolean`, `number`, `bigint`, `string`, `symbol`) та тип `object`. Усі числа типу `number` — 64-бітні числа з рухомою комою (IEEE 754), звідси відомий результат:

```js
console.log(0.1 + 0.2);   // 0.30000000000000004
console.log(typeof null); // "object" — деталі нижче
console.log([] + {});     // "[object Object]" — наслідок неявного приведення типів
```

`typeof null === "object"` — не «недогляд, який хтось не помітив», а зафіксована в специфікації ECMA-262 поведінка з чіткою технічною причиною. У найпершій реалізації 1995 року значення JS кодувалися як машинне слово: кілька бітів-тег визначали тип, решта — самі дані. Тег `000` позначав об'єкт, а `null` представлявся нульовим машинним покажчиком — тобто всі біти нульові, включно з тими самими бітами тегу `000`. На рівні бітового представлення `null` і об'єкт були нерозрізненні, тому `typeof` для `null` повертав `"object"`. Сам Брендан Айк публічно називав це «помилкою» дизайну заднім числом, але виправити її вже не можна: занадто багато коду в мережі покладається на `typeof x === "object"` як спосіб (неповністю коректний) перевірити, що `x` — об'єкт або `null`. Тому поведінка стандартизована й гарантовано стабільна — це не випадковість чи баг конкретного рушія, а зафіксована частина мови.

Слабка типізація означає, що оператори автоматично перетворюють операнди. Саме тому мову часто критикують, і саме тому надійний код використовує сувору рівність `===`. Для статичної перевірки типів застосовують надмножину **TypeScript** (Microsoft, 2012), яка компілюється в звичайний JavaScript.

## 5. Керування пам'яттю

Пам'яттю керує збирач сміття (алгоритм позначення та очищення, з поколіннями об'єктів). Програміст не звільняє пам'ять явно, проте відповідає за відсутність небажаних посилань: типова причина витоків — забуті обробники подій, глобальні змінні, замикання, що утримують великі структури.

## 6. Екосистема та сфери застосування

- **Браузер:** єдина мова, що виконується у всіх браузерах без додаткових засобів; взаємодіє з DOM.
- **Сервер:** Node.js, Deno, Bun; веб-фреймворки (Express, NestJS).
- **Мобільні та настільні застосунки:** React Native, Electron.
- **Інтерфейсні бібліотеки:** React, Vue, Svelte, Angular.
- **Інструменти розробки:** збирачі, лінтери, тестові фреймворки.

## 7. Сильні сторони та обмеження

| Сильні сторони | Обмеження |
|---|---|
| Універсальність середовища виконання | Слабка типізація і неявні перетворення |
| Величезна екосистема (npm) | Однопотокова модель для обчислень |
| Низький поріг входу, швидке прототипування | Числа з рухомою комою для всіх обчислень |
| Асинхронність «з коробки» | Нестабільність екосистеми, залежності |
