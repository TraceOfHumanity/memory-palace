# Bubble Sort — сортування бульбашкою

Усі виводи отримані реальним запуском (Node 24). Реалізації перевірені на 300 випадкових масивах проти `Array.prototype.sort`.

## 1. Ідея

Проходимо масивом зліва направо, порівнюємо **сусідів** і міняємо їх місцями, якщо вони стоять у неправильному порядку. Після першого проходу **найбільший** елемент «спливає» (як бульбашка) у кінець. Після другого — другий за величиною на передостаннє місце тощо. Після `i` проходів останні `i` елементів уже на своїх місцях.

## 2. Приклад: `[5, 2, 9, 1, 5, 6]`

Стан після кожного проходу (реальний вивід):

| Прохід | Масив після проходу |
|---|---|
| початок | `5 2 9 1 5 6` |
| 1 | `2 5 1 5 6 9` — `9` спливло в кінець |
| 2 | `2 1 5 5 6 9` — `6` на місці |
| 3 | `1 2 5 5 6 9` — відсортовано |
| 4 | `1 2 5 5 6 9` — жодного обміну → зупинка |

Для цього масиву: **14 порівнянь, 6 обмінів, 4 проходи**.

## 3. Реалізація

```js
function bubbleSort(a) {
  a = [...a];                                   // не мутуємо вхід
  for (let i = 0; i < a.length - 1; i++) {
    let swapped = false;
    for (let j = 0; j < a.length - 1 - i; j++) {   // останні i вже на місці
      if (a[j] > a[j + 1]) {
        [a[j], a[j + 1]] = [a[j + 1], a[j]];
        swapped = true;
      }
    }
    if (!swapped) break;                        // обмінів не було → вже відсортовано
  }
  return a;
}
```

Три важливі деталі:
1. **`a.length - 1 - i`** — внутрішній цикл скорочується, бо хвіст уже відсортований.
2. **Прапорець `swapped`** — ранній вихід. Без нього алгоритм завжди робить усі проходи.
3. Порівняння **строге** (`>`), а не `>=` — рівні елементи не міняються місцями, тому сортування **стабільне**.

## 4. Складність (виміряно)

Кількість порівнянь / обмінів:

| n | Дані | Без прапорця | З прапорцем |
|---|---|---|---|
| 10 | випадкові | 45 / 33 | 45 / 33 |
| 10 | відсортовані | 45 / 0 | **9 / 0** |
| 10 | зворотні | 45 / 45 | 45 / 45 |
| 100 | випадкові | 4 950 / 2 368 | 4 929 / 2 368 |
| 100 | відсортовані | 4 950 / 0 | **99 / 0** |
| 100 | зворотні | 4 950 / 4 944 | 4 950 / 4 944 |
| 1 000 | випадкові | 499 500 / 251 342 | 498 372 / 251 342 |
| 1 000 | відсортовані | 499 500 / 0 | **999 / 0** |
| 1 000 | зворотні | 499 500 / 499 442 | 499 500 / 499 442 |

- Без прапорця — завжди `n(n−1)/2` порівнянь.
- **Найкращий випадок** (вже відсортований, з прапорцем): один прохід, `n − 1` порівнянь → `O(n)`.
- **Середній і найгірший**: `O(n²)`. Обмінів у середньому ≈ `n(n−1)/4` (для 1000 — 251 342 ≈ 249 750), у найгіршому (зворотний масив) `n(n−1)/2` (499 442 для 1000 з дублями).
- **Пам'ять:** `O(1)` (на місці, in-place).
- **Стабільне:** так.

Асиметрія: великий елемент у **початку** піднімається за один прохід (спливає), а малий елемент у **кінці** опускається лише на **1 позицію за прохід** («черепахи»). Приклади: `[2,3,4,5,1]` потребує **4 проходи** (10 порівнянь), а `[5,1,2,3,4]` — лише **2** (7 порівнянь).

## 5. Час (ця машина, випадкові дані)

| n | bubble | з прапорцем | selection | insertion | `Array.sort` |
|---|---|---|---|---|---|
| 1 000 | 0,7 мс | 0,7 | 0,5 | 0,3 | 0,2 |
| 5 000 | 15 мс | 16 | 12 | 7,9 | 0,7 |
| 10 000 | 67 мс | 69 | 48 | 31 | 1,7 |
| 20 000 | 440 мс | 444 | 192 | 128 | 2,9 |

Подвоїв `n` (10 000 → 20 000) — час ×6,6 (квадрат). Bubble sort — найповільніший з простих: багато **обмінів** (записів у пам'ять).
Майже відсортований масив з 20 000 елементів (20 випадкових перестановок): bubble з прапорцем ≈ **197 мс** (малі елементи в кінці рухаються по 1 позиції за прохід), а insertion sort — **0,4 мс**.

## 6. Варіанти

- **З прапорцем** (вище) — ранній вихід на відсортованих.
- **Запам'ятовувати останній обмін:** після проходу нове значення межі = індекс останнього обміну (все після нього вже відсортовано) — скорочує проходи на «частково впорядкованих».
- **Cocktail shaker sort** (двонапрямлена): прохід вперед (спливає максимум) і назад (занурюється мінімум) — лікує «черепах».
- **Comb sort** — порівнює елементи на відстані (gap), що зменшується (≈ ділення на 1,3) — швидше, але нестабільне.

## 7. Коли використовувати

На практиці — **майже ніколи**. Він корисний для навчання (дуже простий, наочний), і інколи для масивів з кількох елементів або для перевірки «чи вже відсортовано» за один прохід. Для реальних даних — `Array.prototype.sort` (`O(n log n)`) або insertion sort для малих/майже відсортованих.

## 8. Типові помилки

1. **Не скорочувати межу** внутрішнього циклу (`a.length - 1` замість `- i`) — зайві порівняння; з `a[j + 1]` без `- 1` — вихід за межі (`undefined`).
2. **Без прапорця** — на відсортованих даних усе одно `O(n²)`.
3. `>=` замість `>` — зайві обміни рівних і втрата **стабільності**.
4. Мутувати вхідний масив, не попередивши (`a = [...a]` для копії).
5. Обмін через тимчасову змінну забути (`a[j] = a[j+1]; a[j+1] = a[j]` затре значення) — використовуй деструктуризацію або `tmp`.
6. Вважати, що bubble sort швидший за selection через «ранній вихід» — на випадкових даних він майже завжди повільніший (багато обмінів).
7. Плутати з вбудованим `sort()` без компаратора: `[10, 9, 1, 100, 25].sort()` → `[1, 10, 100, 25, 9]` (лексикографічно). У власному коді порівняння `>` для чисел працює правильно.

## 9. Алгоритм

1. Повторюй для `i` від `0` до `n − 2`:
   1. Став прапорець `swapped = false`.
   2. Для `j` від `0` до `n − 2 − i`: якщо `a[j] > a[j + 1]` — обміняй, `swapped = true`.
   3. Якщо `swapped == false` — **зупинись** (відсортовано).
2. Результат — відсортований масив.
3. Складність: час `O(n²)` (у кращому `O(n)`), пам'ять `O(1)`, стабільне.
