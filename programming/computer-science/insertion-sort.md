# Insertion Sort — сортування вставками

Усі виводи — реальним запуском (Node 24), реалізація перевірена на 300 випадкових масивах.

## 1. Ідея

Так розкладають карти в руці. Ліва частина масиву вже **відсортована**. Беремо наступний елемент (**ключ**), **зсуваємо** вправо всі більші за нього елементи відсортованої частини й вставляємо ключ у звільнене місце. Спочатку відсортована частина — перший елемент (один елемент завжди відсортований).

## 2. Приклад: `[5, 2, 9, 1, 5, 6]`

Реальний вивід (ключ → стан масиву; відсортована частина зростає зліва):

| Ключ | Масив після вставки |
|---|---|
| початок | `5 2 9 1 5 6` |
| `2` | `2 5 9 1 5 6` — `5` зсунулось вправо |
| `9` | `2 5 9 1 5 6` — зсувів немає |
| `1` | `1 2 5 9 5 6` — зсунулись `9, 5, 2` |
| `5` | `1 2 5 5 9 6` — `9` зсунулось; рівне `5` не чіпали |
| `6` | `1 2 5 5 6 9` |

Разом **9 порівнянь, 6 зсувів**.

## 3. Реалізація

```js
function insertionSort(a) {
  a = [...a];
  for (let i = 1; i < a.length; i++) {
    const key = a[i];
    let j = i - 1;
    while (j >= 0 && a[j] > key) {     // зсуваємо більші вправо
      a[j + 1] = a[j];
      j--;
    }
    a[j + 1] = key;                    // вставляємо ключ
  }
  return a;
}
```
Це **зсув**, а не обмін: кожен елемент записується один раз (`a[j+1] = a[j]`), ключ — один раз наприкінці. Цикл зупиняється на першому елементі `≤ key` — тому рівні елементи не міняються місцями (**стабільне**).

## 4. Складність (виміряно)

Порівнянь / зсувів:

| n | Дані | Порівнянь | Зсувів |
|---|---|---|---|
| 10 | випадкові | 38 | 33 |
| 10 | відсортовані | **9** | 0 |
| 10 | зворотні | 45 | 45 |
| 100 | випадкові | 2 461 | 2 368 |
| 100 | відсортовані | **99** | 0 |
| 100 | зворотні | 4 950 | 4 944 |
| 1 000 | випадкові | 252 334 | 251 342 |
| 1 000 | відсортовані | **999** | 0 |
| 1 000 | зворотні | 499 500 | 499 442 |

- **Найкращий випадок** (відсортований): `n − 1` порівнянь → **`O(n)`**.
- **Середній** ≈ `n²/4` порівнянь/зсувів → `O(n²)` (для 1000: ≈ 250 000).
- **Найгірший** (зворотний): `n(n−1)/2` → `O(n²)`.
- Кількість зсувів = **кількість інверсій** (пар «більший стоїть лівіше за менший») у масиві. Звідси адаптивність: час ≈ `O(n + k)`, де `k` — інверсії.
- **Пам'ять:** `O(1)`. **Стабільне:** так. **Онлайн:** вміє приймати елементи по одному.

## 5. Час (ця машина, випадкові дані)

| n | insertion | selection | bubble | `Array.sort` |
|---|---|---|---|---|
| 1 000 | 0,3 мс | 0,5 | 0,7 | 0,2 |
| 5 000 | 7,9 | 12 | 15 | 0,7 |
| 10 000 | 31 | 48 | 67 | 1,7 |
| 20 000 | 128 | 192 | 440 | 2,9 |

**Найшвидший з простих** `O(n²)`-алгоритмів. На **майже відсортованому** масиві з 20 000 елементів (20 випадкових обмінів): insertion — **0,4 мс**, bubble — 197 мс, selection — 191 мс. Це і є його сильна сторона.

## 6. Де застосовують

- **Малі масиви** (≈ до 10–50 елементів): через малі сталі швидший за merge/quick. Гібридні алгоритми (TimSort — у `Array.prototype.sort` V8, Introsort) використовують insertion sort для маленьких фрагментів.
- **Майже відсортовані** дані — майже лінійний час.
- **Онлайн-сортування** потоку: вставляти нові елементи у відсортований список.

## 7. Варіанти

- **Binary insertion sort:** позицію вставки шукати **бінарним пошуком** (`O(log n)` порівнянь), але зсуви все одно `O(n)` → загалом `O(n²)` зсувів, менше порівнянь (корисно, коли порівняння дороге).
- **Shell sort:** insertion sort по елементах на відстані gap, що зменшується (…, 4, 2, 1) — прискорює «далекі» переміщення, `~O(n^1.3)`.
- **Вставка у зв'язний список:** зсувів немає (перелінковка), але пошук позиції — `O(n)`.

## 8. Типові помилки

1. **Обмін замість зсуву:** `swap` на кожному кроці в 3 рази більше записів — повільніше.
2. Порівняння `>=` замість `>` — рівні елементи переступають один одного → **втрата стабільності**.
3. **Порядок умов** у `while`: `a[j] > key && j >= 0` → читання `a[-1]` (`undefined`); перевіряй `j >= 0` **першим**.
4. Починати з `i = 0` (нічого не робить, зайва ітерація) або забути, що `a[0]` вже «відсортований».
5. Забути записати ключ після циклу (`a[j + 1] = key`) — втратиш елемент.
6. Мутувати вхід без копії.
7. Застосовувати до великих випадкових масивів: 20 000 елементів ≈ 128 мс проти 3 мс у `Array.sort`.

## 9. Алгоритм

1. Вважай `a[0]` відсортованою частиною.
2. Для `i` від `1` до `n − 1`:
   1. `key = a[i]`, `j = i − 1`.
   2. Поки `j ≥ 0` і `a[j] > key`: `a[j + 1] = a[j]`, `j--`.
   3. `a[j + 1] = key`.
3. Складність: час `O(n²)` (у кращому `O(n)`), пам'ять `O(1)`, стабільне, адаптивне.
