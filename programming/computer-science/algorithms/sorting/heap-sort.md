# Heap Sort — пірамідальне сортування

Heap sort сортує масив **на місці** (`O(1)` додаткової пам'яті) і **гарантує** `O(n log n)` у найгіршому випадку. Він поєднує сильні сторони merge sort (гарантований час) і quick sort/insertion sort (мало пам'яті) — ціною нестабільності та поганої роботи з кешем процесора. Щоб його зрозуміти, потрібно зрозуміти одну структуру — **бінарну купу** (binary heap).

## 1. Бінарна купа

**Max-heap** — це повне бінарне дерево, у якому кожен вузол **не менший за своїх дітей**. Отже, найбільший елемент завжди в корені. (У **min-heap** навпаки: корінь — найменший.)

Головна хитрість: повне бінарне дерево (усі рівні заповнені, крім, можливо, останнього, який заповнюється зліва направо) зручно зберігати **в масиві без жодних вказівників**. Для вузла з індексом `i` (нумерація з нуля):

- лівий син: `2i + 1`;
- правий син: `2i + 2`;
- батько: `⌊(i − 1) / 2⌋`.

Масив `[9, 7, 8, 3, 5, 6, 2]` — це дерево:

```text
        9
      /   \
     7     8
    / \   / \
   3   5 6   2
```

Обхід масиву зліва направо — це обхід дерева по рівнях. Властивість купи — лише вертикальна (батько ≥ діти); горизонтальної впорядкованості немає, тому купа **не відсортований** масив. Перевірка: `isMaxHeap([9, 7, 8, 3, 5, 6, 2])` = `true`, а `isMaxHeap([1, 2, 3])` = `false`.

Висота купи з `n` елементів — `⌊log₂ n⌋`: для 1000 елементів це 9 рівнів. Саме звідси береться `log n` у складності.

## 2. Основна операція: sift-down (просіювання вниз)

Припустимо, що піддерева вузла `i` вже є купами, а сам `a[i]` може порушувати властивість (він менший за когось із дітей). Виправлення:

1. Знайти більшого з дітей.
2. Якщо `a[i]` не менший за нього — готово.
3. Інакше **обміняти** `a[i]` з більшим сином і повторити для його нової позиції.

Елемент «тоне» донизу, доки не знайде своє місце. Максимум за `h = ⌊log₂ n⌋` обмінів → `O(log n)`.

Чому обмін саме з **більшим** сином? Тоді новий батько ≥ обох дітей: більший син ≥ менший ≥ усього піддерева, а старий батько, що опустився, — лише в одне з піддерев, де продовжиться перевірка.

## 3. Побудова купи: heapify за `O(n)`

Щоб перетворити довільний масив на max-heap, викликаємо sift-down для всіх **внутрішніх** вузлів від **останнього** до кореня: індекси `⌊n/2⌋ − 1, …, 0`. Листки (друга половина масиву) — це вже купи з одного елемента.

Приклад: `[4, 10, 3, 5, 1]` → `[10, 5, 3, 4, 1]`.

Чому `O(n)`, а не `O(n log n)`? Вузол на висоті `k` (рахуємо від листків) просівається щонайбільше на `k` рівнів, а таких вузлів не більше `n / 2^{k+1}`. Сума:

`Σ k · n / 2^{k+1} = n · Σ k / 2^{k+1} ≤ n`

бо ряд `Σ k / 2^k` збігається до 2. Тобто більшість вузлів — близько до листків і майже не рухаються. Це типова пастка інтерв'ю: «побудова купи — `O(n)`», хоча `n` вставок по черзі — `O(n log n)`.

## 4. Алгоритм Heap Sort

1. **Побудувати max-heap** з вхідного масиву (`O(n)`).
2. Повторювати, поки розмір купи > 1:
   - обміняти корінь (максимум) з **останнім** елементом купи — максимум потрапляє на своє остаточне місце в кінці;
   - **зменшити** розмір купи на 1 (відсортований «хвіст» росте, купа стискається);
   - просіяти новий корінь вниз (`O(log n)`).

Масив ділиться на дві частини: ліворуч — купа, праворуч — відсортований хвіст з найбільших елементів. Це ідея selection sort («знайди максимум і поклади в кінець»), але максимум шукається за `O(log n)` замість `O(n)` — завдяки купі.

Трасування для `[5, 3, 8, 1, 9, 2]`. Після побудови купи: `[9, 5, 8, 1, 3, 2]`. Далі стан масиву після кожного кроку (позначка `|` відділяє хвіст):

1. `8, 5, 2, 1, 3 | 9`
2. `5, 3, 2, 1 | 8, 9`
3. `3, 1, 2 | 5, 8, 9`
4. `2, 1 | 3, 5, 8, 9`
5. `1 | 2, 3, 5, 8, 9`

## 5. Реалізація

```js
function siftDown(a, i, n) {
  while (true) {
    const l = 2 * i + 1;
    const r = l + 1;
    let big = i;
    if (l < n && a[l] > a[big]) big = l;
    if (r < n && a[r] > a[big]) big = r;
    if (big === i) return;
    [a[i], a[big]] = [a[big], a[i]];
    i = big;
  }
}

function buildMaxHeap(input) {
  const a = input.slice();
  for (let i = (a.length >> 1) - 1; i >= 0; i--) siftDown(a, i, a.length);
  return a;
}

function heapSort(input) {
  const a = buildMaxHeap(input);
  for (let end = a.length - 1; end > 0; end--) {
    [a[0], a[end]] = [a[end], a[0]];
    siftDown(a, 0, end);
  }
  return a;
}

function isMaxHeap(a) {
  for (let i = 1; i < a.length; i++) if (a[(i - 1) >> 1] < a[i]) return false;
  return true;
}

function heapSortTrace(input) {
  const a = buildMaxHeap(input);
  const out = [];
  for (let end = a.length - 1; end > 0; end--) {
    [a[0], a[end]] = [a[end], a[0]];
    siftDown(a, 0, end);
    out.push(a.slice(0, end).join(', ') + ' | ' + a.slice(end).join(', '));
  }
  return out;
}

function heapSortStats(input) {
  const a = input.slice();
  let cmp = 0;
  let swaps = 0;
  const sift = (i, n) => {
    while (true) {
      const l = 2 * i + 1;
      const r = l + 1;
      let big = i;
      if (l < n) { cmp++; if (a[l] > a[big]) big = l; }
      if (r < n) { cmp++; if (a[r] > a[big]) big = r; }
      if (big === i) return;
      [a[i], a[big]] = [a[big], a[i]];
      swaps++;
      i = big;
    }
  };
  for (let i = (a.length >> 1) - 1; i >= 0; i--) sift(i, a.length);
  for (let end = a.length - 1; end > 0; end--) {
    [a[0], a[end]] = [a[end], a[0]];
    swaps++;
    sift(0, end);
  }
  return { sorted: a, cmp, swaps };
}

class MinHeap {
  constructor() { this.a = []; }
  get size() { return this.a.length; }
  peek() { return this.a[0]; }
  push(x) {
    const a = this.a;
    a.push(x);
    let i = a.length - 1;
    while (i > 0) {
      const p = (i - 1) >> 1;
      if (a[p] <= a[i]) break;
      [a[p], a[i]] = [a[i], a[p]];
      i = p;
    }
  }
  pop() {
    const a = this.a;
    const top = a[0];
    const last = a.pop();
    if (a.length) {
      a[0] = last;
      let i = 0;
      while (true) {
        const l = 2 * i + 1;
        const r = l + 1;
        let m = i;
        if (l < a.length && a[l] < a[m]) m = l;
        if (r < a.length && a[r] < a[m]) m = r;
        if (m === i) break;
        [a[i], a[m]] = [a[m], a[i]];
        i = m;
      }
    }
    return top;
  }
}

function kLargest(a, k) {
  const h = new MinHeap();
  for (const x of a) {
    h.push(x);
    if (h.size > k) h.pop();
  }
  const out = [];
  while (h.size) out.push(h.pop());
  return out.reverse();
}
```

## 6. Складність

- **Побудова купи:** `O(n)` (розділ 3).
- **Фаза вилучень:** `n − 1` разів просівання на глибину до `log n` → `O(n log n)`.
- **Разом:** `O(n log n)` у **найкращому, середньому і найгіршому** випадках — час майже не залежить від вхідних даних (на відміну від quick sort і insertion sort). У найкращому випадку (усі елементи рівні) просівання закінчується одразу, але фаза вилучень усе одно лінійна за кількістю викликів.
- **Пам'ять:** `O(1)` — усе відбувається в самому масиві (рекурсії немає; `siftDown` ітеративний).
- **Стабільність:** **ні**. Обмін кореня з останнім елементом «перестрибує» через рівні елементи й порушує їхній порядок.
- **Точні числа:** для випадкового масиву з 1000 елементів — близько 16837 порівнянь; для `n log₂ n` це 9966, тож константа порядку 2.

Нижня межа порівняльних сортувань — `Ω(n log n)` (дерево рішень з `n!` листками має висоту `≥ log₂ n! ≈ n log₂ n − 1,44n`). Heap sort і merge sort **асимптотично оптимальні**.

## 7. Порівняння з іншими сортуваннями

| | Heap | Merge | Quick | Insertion |
|---|---|---|---|---|
| Найгірший | `O(n log n)` | `O(n log n)` | `O(n²)` | `O(n²)` |
| Середній | `O(n log n)` | `O(n log n)` | `O(n log n)` | `O(n²)` |
| Пам'ять | `O(1)` | `O(n)` | `O(log n)` | `O(1)` |
| Стабільне | ні | так | ні | так |
| Кеш-дружність | погана | добра | відмінна | відмінна |

На практиці heap sort у 2–3 рази повільніший за добре налаштований quick sort: sift-down стрибає по масиву (індекси `i → 2i + 1`), а кеш процесора найкраще працює з послідовним доступом. Тому **introsort** (C++ `std::sort`) починає як quick sort, а коли глибина рекурсії перевищує `2·log n`, **перемикається на heap sort**, щоб гарантувати `O(n log n)`.

Коли обирати heap sort: жорсткі обмеження пам'яті **і** потрібен гарантований час (вбудовані системи, ядро ОС). Для загального призначення — стандартне сортування бібліотеки.

## 8. Бонус: де купа справді незамінна

Сама купа корисніша за heap sort — це реалізація **черги з пріоритетом** (priority queue): `push` і `pop` за `O(log n)`, `peek` за `O(1)`.

- **Top-K:** `kLargest([5, 1, 9, 3, 7, 6, 8], 3)` = `[9, 8, 7]`. Тримаємо min-heap розміру `k`: новий елемент входить, найменший вилітає. Час `O(n log k)`, пам'ять `O(k)` — працює на потоці даних, що не вміщується в пам'ять.
- **Dijkstra, Prim, A\*:** вибір вершини з найменшою відстанню (див. [dijkstra.md](../graphs/dijkstra.md)).
- **Злиття `k` відсортованих списків** за `O(N log k)`.
- **Медіана потоку:** max-heap для нижньої половини й min-heap для верхньої.
- **Планувальники подій і завдань**, стиснення Хаффмана ([huffman-coding.md](../greedy/huffman-coding.md)).

Структура даних докладно описана в [Heap.md](../../../js/common/data-structures/Heap/Heap.md).

## 9. Типові помилки

1. **Індекси:** для нумерації з нуля діти `2i + 1`, `2i + 2`. Формули `2i`, `2i + 1` — для нумерації з одиниці; змішування дає зсув на 1.
2. **Просівати не до `n`, а до довжини масиву** у фазі вилучень: треба передавати поточний розмір купи `end`, інакше відсортований хвіст знову зіпсується.
3. **Будувати купу з `i = 0` вгору** (sift-up від кореня) — це теж можливо, але `O(n log n)`; sift-down від середини — `O(n)`.
4. **Починати heapify з `n − 1`** — зайві виклики на листках; початок — `⌊n/2⌋ − 1`.
5. **Порівнювати лише з лівим сином** — права гілка ігнорується; не забувайте перевірку `r < n`.
6. **Обмін не з більшим сином** — порушує інваріант купи.
7. **Очікувати стабільності.** Для стабільного порядку додають до ключа початковий індекс.
8. **Плутати купу (heap) з пам'яттю «heap»** (динамічна пам'ять) — це різні поняття.
9. **Забувати, що `Array.prototype.sort` у JS — не heap sort**: у V8 це TimSort (стабільний).

## 10. Алгоритм (стисло)

1. `heapify`: для `i` від `⌊n/2⌋ − 1` до `0` виконати `siftDown(i, n)`.
2. Для `end` від `n − 1` до `1`: обміняти `a[0]` і `a[end]`, виконати `siftDown(0, end)`.
3. Час `O(n log n)` завжди, пам'ять `O(1)`, нестабільне.

   ```js
   function mergeKSorted(lists) {
     const heap = [];
     const less = (x, y) => x[0] < y[0];
     const push = (x) => {
       heap.push(x);
       let i = heap.length - 1;
       while (i > 0) {
         const p = (i - 1) >> 1;
         if (!less(heap[i], heap[p])) break;
         [heap[i], heap[p]] = [heap[p], heap[i]];
         i = p;
       }
     };
     const pop = () => {
       const top = heap[0];
       const last = heap.pop();
       if (heap.length) {
         heap[0] = last;
         let i = 0;
         while (true) {
           const l = 2 * i + 1, r = l + 1;
           let m = i;
           if (l < heap.length && less(heap[l], heap[m])) m = l;
           if (r < heap.length && less(heap[r], heap[m])) m = r;
           if (m === i) break;
           [heap[i], heap[m]] = [heap[m], heap[i]];
           i = m;
         }
       }
       return top;
     };
     lists.forEach((l, i) => { if (l.length) push([l[0], i, 0]); });
     const out = [];
     while (heap.length) {
       const [v, li, pos] = pop();
       out.push(v);
       if (pos + 1 < lists[li].length) push([lists[li][pos + 1], li, pos + 1]);
     }
     return out;
   }
   ```

   ```js
       if (lo.size === 0 || x <= -lo.peek()) lo.push(-x);
   ```

40. Приклад розв'язку:

   ```js
   function heapSortBy(a, key) {
     const h = a.map(x => [key(x), x]);
     const sift = (i, n) => {
       while (true) {
         const l = 2 * i + 1, r = l + 1;
         let b = i;
         if (l < n && h[l][0] > h[b][0]) b = l;
         if (r < n && h[r][0] > h[b][0]) b = r;
         if (b === i) return;
         [h[i], h[b]] = [h[b], h[i]];
         i = b;
       }
     };
     for (let i = (h.length >> 1) - 1; i >= 0; i--) sift(i, h.length);
     for (let e = h.length - 1; e > 0; e--) {
       [h[0], h[e]] = [h[e], h[0]];
       sift(0, e);
     }
     return h.map(p => p[1]);
   }
   ```

41. Властивість купи вертикальна: кожен батько не менший за дітей. Між «братами» й «двоюрідними» вузлами порядку немає: у `[9, 7, 8, 3, 5, 6, 2]` елемент `7` лівіше за `8`, але менший, а `3` лівіше за `5`. Гарантовано лише, що корінь — максимум.
42. У `siftDown`-підході більшість вузлів (половина — листки, чверть — на висоті 1 тощо) просівається на дуже малу глибину: сума `Σ k · n/2^{k+1}` обмежена `n`. Вставка ж «спливає» вгору від листка до кореня, а листків — половина, тому в гіршому разі кожна з `n` вставок коштує `log n`.
43. Обмін кореня з останнім елементом переносить значення через довільну кількість рівних елементів, тож їхній відносний порядок губиться. Виправлення: сортувати за складеним ключем `(значення, початковий індекс)` — це додає пам'ять і порівняння.
44. Sift-down звертається до елементів `i`, `2i + 1`, `2i + 2` — адреси швидко розходяться, і кеш процесора працює погано, тоді як quick sort проходить масив послідовно. Крім того, heap sort виконує приблизно вдвічі більше порівнянь.
45. Introsort — гібрид: починає як quick sort, відстежує глибину рекурсії, і коли вона перевищує `≈ 2·log₂ n` (ознака поганих опорних елементів), перемикається на heap sort, що гарантує `O(n log n)`. Для малих підмасивів використовується insertion sort. Так працює `std::sort` у багатьох реалізаціях C++.
46. Індекси `⌊n/2⌋ … n − 1` — листки: у них немає дітей (`2i + 1 ≥ n`), тож вони вже є купами з одного елемента. Перший вузол, що має хоч одного сина, — `⌊n/2⌋ − 1`.
47. Тримати min-heap розміру `k`: кожен новий елемент додається, а якщо розмір перевищив `k` — видаляється мінімум. Час `O(n log k)`, пам'ять `O(k)`, один прохід.
48. Це лише збіг назв. Бінарна купа — повне дерево з властивістю «батько ≥ діти», яке зберігають у масиві. Heap-пам'ять — область, з якої `malloc`/`new` виділяють блоки; вона не має відношення до порядку елементів.
