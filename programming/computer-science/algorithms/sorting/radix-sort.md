# Radix Sort — порозрядне сортування

Radix sort сортує числа (або рядки) **по одній цифрі**, не порівнюючи числа цілком. Якщо ключ складається з `d` цифр у системі числення з основою `b`, час становить `O(d · (n + b))` — для 32-бітових чисел із `b = 256` це 4 проходи, тобто **лінійний** час. Це принцип сортувальних машин для перфокарт, а сьогодні — один зі швидких способів сортувати цілі ключі у базах даних і на GPU.

## 1. Ідея

Як ви сортуєте колоду карт за мастю і значенням? Можна спочатку розкласти за **значенням**, потім **стабільно** розкласти за мастю — тоді всередині кожної масті карти залишаються впорядковані за значенням.

Те саме з числами: сортуємо спочатку за **останньою** (наймолодшою) цифрою, потім за передостанньою і так до старшої. Кожен прохід — **стабільне** сортування за однією цифрою (зазвичай [counting sort](counting-sort.md), бо цифр лише `b`). Стабільність гарантує: коли ми впорядкували за старшою цифрою, числа з однаковою старшою цифрою лишаються у порядку, який дали молодші цифри.

Приклад: `[170, 45, 75, 90, 802, 24, 2, 66]`, основа 10. Стан після кожного проходу:

- за розрядом 1: 170, 90, 802, 2, 24, 45, 75, 66
- за розрядом 10: 802, 2, 24, 45, 66, 170, 75, 90
- за розрядом 100: 2, 24, 45, 66, 75, 90, 170, 802

Після останнього проходу масив відсортований. Зверніть увагу на числа `2`, `24`, `45`, `66`, `75`, `90`: у проході по сотнях усі вони мають цифру `0`, тож їхній порядок цілком береться з попередніх проходів. Саме так стабільність «переносить» результат.

## 2. Два види: LSD і MSD

- **LSD (least significant digit)** — від молодшої цифри до старшої; усі проходи однакові й охоплюють **весь** масив. Просто, швидко, потребує стабільного внутрішнього сортування. Це класичний radix sort.
- **MSD (most significant digit)** — від старшої цифри; масив розбивається на групи за старшою цифрою, і кожна група сортується **рекурсивно** за наступною цифрою. Не потребує проходу по всіх цифрах, якщо групи швидко стають малими (для рядків різної довжини; лексикографічний порядок). Складніший, є рекурсія, але може зупинитись раніше.

## 3. Чому LSD правильний

Інваріант: після `p` проходів масив відсортований **за молодшими `p` цифрами** (як за числом, утвореним цими цифрами).

- Початок (`p = 0`): порожня умова.
- Крок: сортуємо стабільно за цифрою `p + 1`. Два числа `x`, `y`: якщо їхні цифри `p + 1` різні — порядок визначає ця цифра, і це правильно, бо вона старша за попередні. Якщо **однакові** — стабільність залишає їх у порядку, який вони мали (за молодшими `p` цифрами). Отже, інваріант зберігається.
- Кінець: після `d` проходів масив відсортований за всіма цифрами.

Без стабільності доведення руйнується: рівні цифри розірвали б попередню роботу.

## 4. Реалізація

```js
function digitsCount(max, base = 10) {
  let d = 1;
  while (max >= base) { max = Math.floor(max / base); d++; }
  return d;
}

function countingPass(a, exp, base) {
  const count = new Array(base).fill(0);
  const out = new Array(a.length);
  for (const x of a) count[Math.floor(x / exp) % base]++;
  for (let i = 1; i < base; i++) count[i] += count[i - 1];
  for (let i = a.length - 1; i >= 0; i--) {
    const d = Math.floor(a[i] / exp) % base;
    out[--count[d]] = a[i];
  }
  return out;
}

function radixSort(input, base = 10) {
  let a = input.slice();
  if (a.length < 2) return a;
  const max = Math.max(...a);
  for (let exp = 1; Math.floor(max / exp) > 0; exp *= base) a = countingPass(a, exp, base);
  return a;
}

function radixSortSigned(a, base = 10) {
  const neg = a.filter((x) => x < 0).map((x) => -x);
  const pos = a.filter((x) => x >= 0);
  const sn = radixSort(neg, base).reverse().map((x) => -x);
  return [...sn, ...radixSort(pos, base)];
}

function radixTrace(input, base = 10) {
  let a = input.slice();
  const max = Math.max(...a);
  const out = [];
  for (let exp = 1; Math.floor(max / exp) > 0; exp *= base) {
    a = countingPass(a, exp, base);
    out.push('за розрядом ' + exp + ': ' + a.join(', '));
  }
  return out;
}

function radixSortUint32(input) {
  let a = Uint32Array.from(input);
  let b = new Uint32Array(a.length);
  for (let shift = 0; shift < 32; shift += 8) {
    const count = new Array(257).fill(0);
    for (const x of a) count[((x >>> shift) & 255) + 1]++;
    for (let i = 0; i < 256; i++) count[i + 1] += count[i];
    for (const x of a) b[count[(x >>> shift) & 255]++] = x;
    [a, b] = [b, a];
  }
  return Array.from(a);
}

function radixSortStrings(words) {
  const L = words[0].length;
  let a = words.slice();
  for (let pos = L - 1; pos >= 0; pos--) {
    const count = new Array(257).fill(0);
    for (const w of a) count[w.charCodeAt(pos) + 1]++;
    for (let i = 0; i < 256; i++) count[i + 1] += count[i];
    const out = new Array(a.length);
    for (const w of a) out[count[w.charCodeAt(pos)]++] = w;
    a = out;
  }
  return a;
}

function passesNeeded(max, base) {
  return digitsCount(max, base);
}
```

Приклади: `radixSort([170, 45, 75, 90, 802, 24, 2, 66])` → `[2, 24, 45, 66, 75, 90, 170, 802]`; з від'ємними — `radixSortSigned([3, -1, -20, 5, 0])` → `[-20, -1, 0, 3, 5]`; рядки однакової довжини — `radixSortStrings(['dog', 'cat', 'ant', 'bee', 'cow'])` → `['ant', 'bee', 'cat', 'cow', 'dog']`.

## 5. Складність

Нехай `n` — кількість чисел, `b` — основа, `d` — кількість цифр найбільшого числа: `d = ⌊log_b(max)⌋ + 1`.

- **Час:** `d` проходів по `O(n + b)` кожен → **`O(d · (n + b))`**.
- **Пам'ять:** `O(n + b)` — вихідний масив і лічильники.
- **Стабільне:** так.
- **Вибір основи:** більша основа — менше проходів, але більші лічильники (гірше для кеша). Для 32-бітових чисел практичний вибір `b = 256` (байт): 4 проходи. Для `b = 10` потрібно 10 проходів, для `b = 2` — 32.
- **Порівняння з `O(n log n)`:** при `n = 10⁶` порівняльне сортування виконує ≈ 19931569 порівнянь, radix із 4 проходами — ≈ `4·(10⁶ + 256)` = 4001024 операцій. Але константи і кеш-промахи (розкидані записи) часто зменшують перевагу; Radix виграє на великих масивах цілих.
- Якщо `d` порівнянний з `log n` (наприклад, ключі довжини `n`), переваги немає: `O(d·n) = O(n log n)`.

## 6. Особливості та пастки

- **Від'ємні числа:** цифрове розкладання не працює з мінусом. Варіанти: розділити на від'ємні й невід'ємні (як у `radixSortSigned`) або **зсунути** всі числа на `−min`; для цілих у доповнювальному коді — інвертувати знаковий біт старшого байта.
- **Дробові числа (IEEE 754):** бітове представлення `double` можна впорядкувати як цілі, якщо для від'ємних інвертувати всі біти, а для додатних — лише знаковий. Так сортують `float` на GPU.
- **Рядки різної довжини:** LSD потребує вирівнювання (доповнення «порожнім» символом) або MSD.
- **Основа — степінь двійки:** замість ділення використовують зсув і маску (`(x >>> shift) & 255`) — швидше і без помилок округлення дробових результатів `Math.floor(x / exp)`.
- **Великі числа:** `Math.floor(x / exp)` коректне лише до `2⁵³`; для більших використовують `BigInt` або побітові операції на розрядах.

## 7. Де використовують

- Сортування великих масивів цілих і індексів (бази даних, GPU, суфіксні масиви).
- Рядки фіксованої довжини: телефонні номери, IP-адреси, дати у форматі `YYYYMMDD`, ключі UUID.
- Багатоключове сортування: спершу за другорядним ключем, потім стабільно за головним (так і сортують таблиці в SQL).
- Тріє-структури по суті реалізують MSD radix sort ([trie.md](../strings/trie.md)).

## 8. Типові помилки

1. **Нестабільне внутрішнє сортування** — результат неправильний.
2. **Хибна умова зупинки** — потрібно проходити, поки `⌊max / exp⌋ > 0`; зупинка за кількістю елементів дає недосортований масив.
3. **Від'ємні числа:** `x % 10` для від'ємних дає від'ємний залишок (`-7 % 10 = -7`), тому лічильник отримує індекс `-7`.
4. **Порожній масив:** `Math.max(...[])` = `-Infinity` — цикл не виконується або виконується нескінченно; потрібна окрема перевірка.
5. **Ділення з плаваючою комою:** без `Math.floor` дробова частина псує цифру.
6. **Мала основа для великих чисел:** 32 проходи при `b = 2` — повільно.
7. **Розмір лічильників `b`, а не `b + 1`** у варіанті зі зсувом `count[d + 1]`.
8. **Припущення, що radix завжди швидший** за вбудоване сортування — для малих масивів (десятки елементів) це не так.

## 9. Алгоритм (стисло)

1. Знайти максимум і кількість цифр `d`.
2. Для `exp = 1, b, b², …` поки `⌊max / exp⌋ > 0`: стабільно відсортувати масив за цифрою `⌊x / exp⌋ mod b` (counting sort).
3. Для від'ємних — окремо або зі зсувом.
4. Час `O(d·(n + b))`, пам'ять `O(n + b)`, стабільне.

41. Після сортування за старшою цифрою числа з однаковою цифрою мають зберегти порядок, який їм дали молодші цифри. Якщо внутрішнє сортування нестабільне, воно може переставити такі числа довільно і зіпсувати результат попередніх проходів.
42. `O(d·(n + b))`: `d` — кількість цифр максимального числа в основі `b` (`d = ⌊log_b max⌋ + 1`), `n + b` — вартість одного проходу counting sort. Збільшення основи зменшує `d`, але збільшує `b`.
43. LSD починає з молодшої цифри й проходить усі елементи на кожному кроці; MSD починає зі старшої, розбиває масив на групи й сортує кожну групу рекурсивно за наступною цифрою. MSD може зупинитись раніше для груп з одного елемента і природно сортує рядки різної довжини.
44. Він не порівнює елементи між собою, а використовує значення цифри як індекс масиву, тому доведення нижньої межі для дерева порівнянь на нього не поширюється. Натомість він вимагає, щоб ключі були цілими числами або рядками обмеженої довжини.
45. Це 4 проходи (по байту) замість 10 при основі 10 чи 32 при основі 2; лічильники з 256 клітинок вміщуються в кеш першого рівня, а цифра обчислюється побітово, без ділення: `(x >>> shift) & 255`.
46. Розділити на від'ємні й невід'ємні, відсортувати модулі від'ємних і розвернути, або зсунути всі на `−min`; у двійковому доповнювальному коді інвертують знаковий біт старшого байта, щоб від'ємні опинилися перед додатними.
47. Коли ключі довгі (кількість цифр `d` порівнянна з `log n`), коли `n` мале (накладні витрати лічильників і додатковий масив) або коли дані погано поміщаються в кеш; також він потребує `O(n)` додаткової пам'яті.
48. LSD проходить позиції від кінця; у коротших рядків на цій позиції немає символа. Їх доповнюють «порожнім» символом, меншим за будь-який літерний (пробіл, нуль), щоб короткий рядок стояв перед довшим з тим самим префіксом.
49. Так, якщо працювати з бітовим представленням IEEE 754: для додатних чисел порядок бітів збігається з порядком значень, для від'ємних потрібно інвертувати біти (для знака — лише знаковий біт). Після такого перетворення число сортується як беззнакове ціле.
50. Числа JS — це `double`: цілі точно представляються лише до `2⁵³`. Для більших значень ділення дає наближені результати, і цифри будуть хибними; потрібен `BigInt` або побітове розбиття.
