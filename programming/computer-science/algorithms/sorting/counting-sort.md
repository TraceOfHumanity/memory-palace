# Counting Sort — сортування підрахунком

Counting sort — сортування **без жодного порівняння елементів між собою**. Тому до нього не застосовується нижня межа `Ω(n log n)` для порівняльних алгоритмів: коли елементи — цілі числа з **невеликого діапазону** `[0, k)`, відсортувати їх можна за `O(n + k)`. Це перший алгоритм, де видно головну ідею: використати **структуру даних**, а не лише порівняння.

## 1. Ідея

Замість питання «чи менший `a[i]` за `a[j]`?» ставимо питання «скільки разів зустрілось кожне значення?». Заводимо масив лічильників `count[0..k-1]`, проходимо вхід один раз і збільшуємо `count[a[i]]`. Далі знаємо, скільки разів кожне значення має з'явитись у відповіді, і можемо його «видати» у правильному порядку.

Приклад: `[4, 2, 2, 8, 3, 3, 1]`, значення від 0 до 8.

Лічильники (індекс — значення): ``[0, 1, 2, 2, 1, 0, 0, 0, 1]``. Простий варіант сортування: пройти значення від 0 до 8 і виписати кожне стільки разів, скільки воно зустрілось → ``[1, 2, 2, 3, 3, 4, 8]``.

Простий варіант працює тільки для **самих чисел**. Якщо ми сортуємо **записи** (об'єкти з ключем і даними), то потрібен варіант, що переставляє самі записи **стабільно**. Для цього використовують **префіксні суми**.

## 2. Стабільний варіант: префіксні суми

Нехай `count[v]` — скільки елементів дорівнюють `v`. Тоді **префіксна сума** `pos[v] = count[0] + … + count[v-1]` — це кількість елементів, строго менших за `v`, тобто **індекс**, з якого починається блок значень `v` у відсортованому результаті.

Алгоритм:

1. Порахувати `count`.
2. Перетворити `count` на **початкові позиції** (exclusive prefix sum).
3. Пройти вхід **зліва направо** (або кумулятивну суму брати «включно» і йти **справа наліво**), поклавши кожен елемент у `out[pos[key]++]`.

Для `[4, 2, 2, 8, 3, 3, 1]`: лічильники ``[0, 1, 2, 2, 1, 0, 0, 0, 1]`` → початкові позиції ``[0, 0, 1, 3, 5, 6, 6, 6, 6]``. Наприклад, значення `3` починається з індексу ``3``: перед ним лежать `1, 2, 2`.

**Чому це стабільно?** Елементи з однаковим ключем потрапляють у свій блок у тому порядку, в якому ми їх зустрічаємо: перший із ключем `3` отримує позицію `pos[3]`, наступний — `pos[3] + 1`. Стабільність критична, бо counting sort — «двигун» radix sort (див. [radix-sort.md](radix-sort.md)), який сортує за цифрами послідовно й спирається на збереження попереднього порядку.

Стабільність на прикладі. Сортуємо слова за довжиною (ключ — довжина):

fig, pear, kiwi, plum, lime, date, apple

Усі чотирилітерні слова (`pear`, `kiwi`, `plum`, `lime`, `date`) залишаються в початковому відносному порядку.

## 3. Реалізація

```js
function countsOf(a, k) {
  const count = new Array(k).fill(0);
  for (const x of a) count[x]++;
  return count;
}

function startPositions(a, k) {
  const count = countsOf(a, k);
  const pos = new Array(k).fill(0);
  for (let v = 1; v < k; v++) pos[v] = pos[v - 1] + count[v - 1];
  return pos;
}

function countingSortSimple(a, k) {
  const count = countsOf(a, k);
  const out = [];
  for (let v = 0; v < k; v++) for (let c = 0; c < count[v]; c++) out.push(v);
  return out;
}

function countingSortBy(a, key, k) {
  const pos = new Array(k).fill(0);
  for (const x of a) if (key(x) + 1 < k) pos[key(x) + 1]++;
  for (let v = 1; v < k; v++) pos[v] += pos[v - 1];
  const out = new Array(a.length);
  for (const x of a) out[pos[key(x)]++] = x;
  return out;
}

function countingSort(a) {
  if (a.length === 0) return [];
  let min = a[0];
  let max = a[0];
  for (const x of a) { if (x < min) min = x; if (x > max) max = x; }
  const k = max - min + 1;
  const count = new Array(k).fill(0);
  for (const x of a) count[x - min]++;
  for (let i = 1; i < k; i++) count[i] += count[i - 1];
  const out = new Array(a.length);
  for (let i = a.length - 1; i >= 0; i--) out[--count[a[i] - min]] = a[i];
  return out;
}

function bucketSort(a, buckets = a.length) {
  const b = Array.from({ length: buckets }, () => []);
  for (const x of a) b[Math.min(buckets - 1, Math.floor(x * buckets))].push(x);
  for (const bucket of b) bucket.sort((p, q) => p - q);
  return b.flat();
}

function sortLetters(s) {
  const count = new Array(26).fill(0);
  for (const ch of s) count[ch.charCodeAt(0) - 97]++;
  let out = '';
  for (let i = 0; i < 26; i++) out += String.fromCharCode(97 + i).repeat(count[i]);
  return out;
}

function isAnagram(s, t) {
  if (s.length !== t.length) return false;
  const count = new Array(26).fill(0);
  for (let i = 0; i < s.length; i++) {
    count[s.charCodeAt(i) - 97]++;
    count[t.charCodeAt(i) - 97]--;
  }
  return count.every((c) => c === 0);
}
```

`countingSort(a)` — універсальний варіант: знаходить `min` і `max`, зсуває ключі на `min` (тож **від'ємні** числа теж працюють) і заповнює результат **справа наліво**, що зберігає стабільність при кумулятивних (включних) префіксних сумах. Приклад: `countingSort([3, -1, 4, -1, 5, 0, 3])` → `[-1, -1, 0, 3, 3, 4, 5]`.

## 4. Складність

- **Час:** один прохід для підрахунку (`n`), один для префіксних сум (`k`), один для розкладання (`n`). Разом **`O(n + k)`**, де `k = max − min + 1` — розмір діапазону ключів.
- **Пам'ять:** `O(n + k)` — масив лічильників і вихідний масив. Це **не** сортування на місці.
- **Коли швидко:** `k = O(n)` (наприклад, оцінки 0–100, вік людей, байти 0–255, літери a–z) — тоді `O(n)` лінійний час.
- **Коли катастрофічно:** `k ≫ n`. Масив із двох чисел `[0, 1000000]` потребує `k = 1000001` лічильників заради двох елементів. Для 32-бітових ключів `k = 2³²` — тому застосовують **radix sort**, що розбиває ключ на частини.
- **Стабільне:** так (при правильному порядку проходу).
- **Нижня межа не діє:** `Ω(n log n)` стосується алгоритмів, що користуються лише операцією «порівняти»; counting sort **індексує масив значенням ключа** — це інша обчислювальна модель (потребує, щоб ключі були малими цілими).

## 5. Споріднені: bucket sort

**Bucket sort** — «підрахунок» для дробових чисел із відомого рівномірного розподілу. Розподіляємо `n` чисел із `[0, 1)` по `n` кошиках (`⌊x·n⌋`), кожен кошик сортуємо (зазвичай вставками), зливаємо. Для рівномірних даних кошики маленькі, і середній час `O(n)`. Приклад: `bucketSort([0.78, 0.17, 0.39, 0.26, 0.72, 0.94, 0.21, 0.12])` → `[0.12, 0.17, 0.21, 0.26, 0.39, 0.72, 0.78, 0.94]`. Якщо всі числа потрапляють в один кошик — виродження в `O(n²)` (або `O(n log n)` з розумним внутрішнім сортуванням).

Три «лінійні» сортування:

| | Для чого | Час | Умова |
|---|---|---|---|
| Counting | цілі з малого діапазону | `O(n + k)` | `k` мале |
| Radix | цілі/рядки фіксованої довжини | `O(d·(n + b))` | `d` цифр у системі з основою `b` |
| Bucket | дійсні, рівномірний розподіл | `O(n)` середній | рівномірність |

## 6. Практичні застосування

- **Гістограми й частоти:** оцінки, вік, пікселі зображення (256 рівнів яскравості) — вирівнювання гістограми.
- **Сортування символів у рядку:** `sortLetters('banana')` = `'aaabnn'`; ключ для групування анаграм (`'listen'` і `'silent'` дають однаковий відсортований рядок).
- **Перевірка анаграм за `O(n)`:** `isAnagram('listen', 'silent')` = `true`, `isAnagram('rat', 'car')` = `false`.
- **Підрозрядне сортування** (radix) — використовує counting sort як стабільний внутрішній крок.
- **Задачі з обмеженим діапазоном:** «відсортувати кольори» (0/1/2) — див. [dutch-national-flag.md](../techniques/dutch-national-flag.md).
- **Пошук частих елементів, відсутнього числа, дублікатів** — підрахунок частот замість сортування.

## 7. Типові помилки

1. **Забути зсув на `min`** — від'ємні числа дають індекс `−1`: `count[-1]` — це властивість об'єкта, а не клітинка.
2. **Проходити вхід зліва направо при кумулятивних (включних) префіксних сумах** — зникає стабільність: рівні елементи опиняються в зворотному порядку. Включні суми → йдемо **справа наліво**; початкові позиції → зліва направо.
3. **`k` без запасу:** розмір `count` має бути `max + 1`, а не `max` (значення `max` потребує власної клітинки).
4. **Нечислові ключі:** рядки, об'єкти потрібно спочатку відобразити у цілі індекси.
5. **Дробові числа:** індекс `3.7` не працює; потрібен bucket sort чи масштабування.
6. **Використовувати для величезних діапазонів** (`k ≈ 10⁹`) — пам'ять і час гірші за звичайне сортування.
7. **Плутати «лінійний час» і «швидко»:** константи й кеш-промахи при великому `k` можуть зробити його повільнішим за `Array.prototype.sort` на малих `n`.
8. **Очікувати «на місці»:** потрібен додатковий вихідний масив.

## 8. Алгоритм (стисло)

1. Знайти `min` та `max`; `k = max − min + 1`.
2. `count[x − min]++` для кожного елемента.
3. `count[i] += count[i − 1]` — тепер `count[i]` — кількість елементів `≤` значення `i + min`.
4. Для `i` від `n − 1` до `0`: `out[--count[a[i] − min]] = a[i]`.
5. Час `O(n + k)`, пам'ять `O(n + k)`, стабільне.

   function countingSortDesc(a, k) {
     const c = countsOf(a, k);
     const o = [];
     for (let v = k - 1; v >= 0; v--) for (let i = 0; i < c[v]; i++) o.push(v);

39. Приклад розв'язку:

   ```js
   function relativeSort(a, order) {
     const c = new Map();
     for (const x of a) c.set(x, (c.get(x) || 0) + 1);
     const o = [];
     for (const x of order) {
       o.push(...Array(c.get(x) || 0).fill(x));
       c.delete(x);
     }
     const rest = [];
     for (const [x, n] of c) rest.push(...Array(n).fill(x));
     return [...o, ...countingSort(rest)];
   }
   ```

     const c = countsOf(a, maxV + 1);

41. Ця межа доведена для алгоритмів, які отримують інформацію про порядок тільки через порівняння двох елементів (дерево рішень із `n!` листками). Counting sort використовує значення ключа як **індекс** масиву — це операція, що виходить за межі моделі «порівняння», тому доведення не застосовується.
42. Після кумулятивного підсумовування `count[v]` указує на позицію **після** останнього елемента зі значенням `v`. Ми розміщуємо елементи, зменшуючи лічильник, тобто заповнюємо блок **з кінця**. Щоб перший за порядком елемент опинився першим у своєму блоці, вхід треба обходити з кінця.
43. Початкова позиція `pos[v]` — кількість елементів, менших за `v` (індекс першого місця блоку). Кумулятивна сума включно `count[v]` — кількість елементів `≤ v` (індекс після останнього місця блоку). Перша потребує обходу зліва направо, друга — справа наліво.
44. Коли діапазон ключів `k` значно більший за `n` (великі числа, 64-бітові ключі), коли ключі не цілі (рядки, дробові числа) або коли критична пам'ять: потрібні `O(n + k)` додаткових клітинок.
45. Radix sort сортує числа по цифрах, від молодшої до старшої. Щоб сортування за старшою цифрою не зіпсувало порядок за молодшими, внутрішнє сортування мусить зберігати відносний порядок рівних ключів — тобто бути стабільним.
46. Counting sort має по лічильнику на кожне можливе значення і підходить для цілих із малого діапазону. Bucket sort розкидає дійсні значення по кошиках-інтервалах, кожен кошик сортує окремо й зливає; ефективний за рівномірного розподілу, інакше вироджується.
47. Завести 26 лічильників (або 256 для ASCII), порахувати літери, і вивести кожну потрібну кількість разів. Час `O(n + 26) = O(n)`, пам'ять `O(1)` не залежно від `n`.
48. Діапазон `[min, max]` містить `max − min + 1` різних значень: наприклад, від 3 до 5 — це 3 значення (3, 4, 5), а не 2. Тому потрібно саме `+ 1` клітинок.
49. Безпосередньо — ні, ключі мають бути малими цілими. Але рядки фіксованої довжини сортують radix sort'ом, де кожна позиція символів сортується counting sort'ом із `k = 256` (або розмір алфавіту).
50. Лічильники літер порівнюють за `O(n)`: +1 для першого рядка, −1 для другого, і перевіряють, що всі нулі. Сортування рядків коштувало б `O(n log n)`.
