# Quickselect — k-й за порядком елемент

Quickselect відповідає на питання: «який елемент був би на позиції `k`, якби масив відсортували?» — **без** повного сортування. Це дає медіану, k-й найбільший, перцентилі за **очікуваний лінійний** час `O(n)`. Алгоритм — рідний брат [quick sort](../sorting/quick-sort.md): та сама функція розбиття, але рекурсія йде лише в **одну** половину.

## 1. Навіщо

Знайти медіану масиву з мільйона чисел. Сортування коштує `O(n log n)`; але ми не потребуємо порядку **всіх** елементів — лише одного. Якщо розбити масив навколо опорного елемента `p` (менші ліворуч, більші праворуч), то `p` опиняється на **остаточній** позиції `m`. Далі:

- `m === k` — готово, `a[m]` і є відповідь;
- `k < m` — шукаємо в лівій частині;
- `k > m` — у правій (з тим самим `k`, якщо індекси зберігаються).

Друга половина більше не потрібна. Розмір задачі: `n → n/2 → n/4 → …`, сума `n + n/2 + n/4 + … ≤ 2n` — лінійно.

## 2. Розбиття (partition)

Схема Ломуто: опорний — останній елемент, поточна межа `i` ділить масив на «менші за опорний» і «решту». Після проходу опорний ставимо на межу.

Для `[3, 6, 8, 10, 1, 2, 5]` з опорним `5` (останній): `3, 1, 2, 5, 6, 8, 10`, межа 3. Опорний `5` став на індекс 3: ліворуч — менші за нього (`3, 1, 2`), праворуч — не менші (`8, 10, 6`).

Властивість розбиття: опорний елемент стоїть на тому місці, де він стояв би у відсортованому масиві. Усе інше всередині частин ще не впорядковане — і це нам не потрібно.

## 3. Реалізація

```js
function partitionLomuto(a, lo, hi) {
  const pivot = a[hi];
  let i = lo;
  for (let j = lo; j < hi; j++) {
    if (a[j] < pivot) {
      [a[i], a[j]] = [a[j], a[i]];
      i++;
    }
  }
  [a[i], a[hi]] = [a[hi], a[i]];
  return i;
}

function partitionTrace(input) {
  const a = input.slice();
  const m = partitionLomuto(a, 0, a.length - 1);
  return '`' + a.join(', ') + '`, межа ' + m;
}

function quickselect(input, k) {
  const a = input.slice();
  let lo = 0;
  let hi = a.length - 1;
  while (lo <= hi) {
    const m = partitionLomuto(a, lo, hi);
    if (m === k) return a[m];
    if (k < m) hi = m - 1;
    else lo = m + 1;
  }
  return undefined;
}

function makeRng(seed) {
  let s = seed >>> 0;
  return () => {
    s = (s * 1664525 + 1013904223) >>> 0;
    return s / 4294967296;
  };
}

function quickselectRandom(input, k, seed = 1) {
  const rng = makeRng(seed);
  const a = input.slice();
  let lo = 0;
  let hi = a.length - 1;
  let comparisons = 0;
  while (lo <= hi) {
    const r = lo + Math.floor(rng() * (hi - lo + 1));
    [a[r], a[hi]] = [a[hi], a[r]];
    const pivot = a[hi];
    let i = lo;
    for (let j = lo; j < hi; j++) {
      comparisons++;
      if (a[j] < pivot) { [a[i], a[j]] = [a[j], a[i]]; i++; }
    }
    [a[i], a[hi]] = [a[hi], a[i]];
    if (i === k) return { value: a[i], comparisons };
    if (k < i) hi = i - 1;
    else lo = i + 1;
  }
  return { value: undefined, comparisons };
}

function quickselectLast(input, k) {
  const a = input.slice();
  let lo = 0;
  let hi = a.length - 1;
  let comparisons = 0;
  while (lo <= hi) {
    const pivot = a[hi];
    let i = lo;
    for (let j = lo; j < hi; j++) {
      comparisons++;
      if (a[j] < pivot) { [a[i], a[j]] = [a[j], a[i]]; i++; }
    }
    [a[i], a[hi]] = [a[hi], a[i]];
    if (i === k) return { value: a[i], comparisons };
    if (k < i) hi = i - 1;
    else lo = i + 1;
  }
  return { value: undefined, comparisons };
}

function kthSmallest(a, k) {
  return quickselect(a, k - 1);
}

function kthLargest(a, k) {
  return quickselect(a, a.length - k);
}

function median(a) {
  const n = a.length;
  if (n % 2) return quickselect(a, (n - 1) / 2);
  return (quickselect(a, n / 2 - 1) + quickselect(a, n / 2)) / 2;
}

function select(input, k) {
  const a = input.slice();
  const go = (arr, kk) => {
    if (arr.length <= 5) return arr.slice().sort((x, y) => x - y)[kk];
    const medians = [];
    for (let i = 0; i < arr.length; i += 5) {
      const g = arr.slice(i, i + 5).sort((x, y) => x - y);
      medians.push(g[g.length >> 1]);
    }
    const pivot = go(medians, medians.length >> 1);
    const less = arr.filter((x) => x < pivot);
    const equal = arr.filter((x) => x === pivot);
    const greater = arr.filter((x) => x > pivot);
    if (kk < less.length) return go(less, kk);
    if (kk < less.length + equal.length) return pivot;
    return go(greater, kk - less.length - equal.length);
  };
  return go(a, k);
}

function topKSmallestUnordered(input, k) {
  const a = input.slice();
  let lo = 0;
  let hi = a.length - 1;
  while (lo < hi) {
    const m = partitionLomuto(a, lo, hi);
    if (m === k - 1) break;
    if (m < k - 1) lo = m + 1;
    else hi = m - 1;
  }
  return a.slice(0, k);
}
```

Приклади: `kthSmallest([7, 10, 4, 3, 20, 15], 3)` = `7` (відсортований масив `[3, 4, 7, 10, 15, 20]`), `kthLargest([7, 10, 4, 3, 20, 15], 2)` = `15`, `median([5, 1, 4, 2, 3])` = `3`, `median([1, 2, 3, 4])` = `2.5`.

## 4. Складність

**Середній випадок `O(n)`.** Якщо опорний «розумний» (близький до середини), розмір задачі зменшується вдвічі, робота на кожному кроці — лінійна розбиттям: `T(n) = T(n/2) + O(n) = O(n)`. Для випадкового опорного очікуваний час теж `O(n)` — приблизно `3,4·n` порівнянь для медіани і `2·n` для крайніх `k`. Формальний аргумент: опорний потрапляє в «середню половину» значень із ймовірністю ½, після чого розмір не перевищує `3n/4`; очікувана кількість спроб — 2; отже, `E[T(n)] ≤ T(3n/4) + 2cn → O(n)`.

**Найгірший випадок `O(n²)`.** Якщо опорний завжди найменший чи найбільший (відсортований масив + опорний = останній), розмір зменшується лише на 1: `n + (n−1) + … = n(n−1)/2`. Порівняйте на масиві з 200 елементів, шукаючи елемент `k = 100`:

| Вхід | Стратегія опорного | Порівнянь |
|---|---|---|
| відсортований | останній | 14950 |
| відсортований | випадковий | 965 |
| «хаотичний» | останній | 454 |

**Пам'ять:** ітеративна версія — `O(1)` додатково (масив копіюємо лише для безпеки вхідних даних; у «справжньому» варіанті працюють на місці).

**Гарантований `O(n)`: Median of Medians (BFPRT, 1973).** Ділимо масив на п'ятірки, знаходимо медіану кожної, **рекурсивно** шукаємо медіану цих медіан і використовуємо її як опорний. Такий опорний гарантовано відкидає щонайменше `30%` елементів, тому `T(n) ≤ T(n/5) + T(7n/10) + O(n)`, а оскільки `1/5 + 7/10 < 1`, розв'язок `O(n)`. Функція `select` реалізує ідею: `select([9, 1, 8, 2, 7, 3, 6, 4, 5, 0, 11, 10], 5)` = `5`. Константа велика, тому на практиці частіше беруть випадковий опорний або **introselect** (комбінація: швидкий випадковий опорний + перемикання на median of medians при вироджених розбиттях).

## 5. Варіанти розбиття і вибір опорного

- **Ломуто:** простіша, але виконує більше обмінів і погано поводиться з багатьма рівними елементами (усі «не менші» йдуть праворуч, розбиття виходить нерівним).
- **Хоара:** два вказівники йдуть з країв назустріч; менше обмінів, краща на дублікатах, але тонші кордони.
- **Тристороннє розбиття** (Dutch national flag, `< = >`): усі рівні опорному збираються в середині; для масивів з багатьма дублікатами повертає діапазон `[lt, gt]` — див. [dutch-national-flag.md](../techniques/dutch-national-flag.md).
- **Вибір опорного:** випадковий (стандарт), медіана з трьох (перший, середній, останній), `median of medians` (гарантія).

## 6. Типові задачі

- **K-й найбільший елемент** у масиві (LeetCode 215): `kthLargest`.
- **Медіана** масиву: `median`.
- **Top-K** елементів без порядку: `topKSmallestUnordered([9, 3, 7, 1, 8, 2], 3)` → `[1, 2, 3]` (після сортування для читабельності; перші `k` позицій містять `k` найменших у довільному порядку).
- **Перцентилі:** 95-й перцентиль затримок — `quickselect(lat, ceil(0.95 n) − 1)`.
- **Найближчі `k` точок до початку координат:** quickselect за відстанню.
- **Зміщення середнього (трансформації):** мінімальна сума абсолютних відхилень досягається в медіані.

Порівняння інструментів для top-K: **куча** (`O(n log k)`, потоки даних, `k` мале), **quickselect** (`O(n)` у середньому, потрібен весь масив у пам'яті), **сортування** (`O(n log n)`, коли потрібен порядок). Див. [heap-sort.md](../sorting/heap-sort.md).

## 7. Типові помилки

1. **Плутанина індексів:** `k` у «k-му найменшому» нумерується з 1, а в `quickselect` — з 0 (`k − 1`). k-й найбільший → індекс `n − k`.
2. **Мутація вхідного масиву:** quickselect переставляє елементи; якщо порядок потрібен далі — копіюйте (як у наведеній реалізації).
3. **Опорний — завжди крайній елемент** на відсортованих даних → `O(n²)`; використовуйте випадковий.
4. **Багато дублікатів + Ломуто** → вироджені розбиття; потрібне тристороннє розбиття.
5. **Нескінченний цикл** через неправильні межі після розбиття: опорний уже на місці, тож межі `m − 1` і `m + 1`, а не `m`.
6. **Порожній масив або `k` поза межами** — повернеться `undefined`; перевіряйте вхід.
7. **Рекурсія в обидві половини** перетворює quickselect на quick sort (`O(n log n)`).
8. **Очікувати стабільності чи відсортованості решти елементів:** гарантовано лише те, що `a[k]` на своєму місці.

## 8. Алгоритм (стисло)

1. Вибрати опорний, розбити діапазон `[lo, hi]` на `<` і `≥` опорного; отримати його остаточний індекс `m`.
2. Якщо `m === k` — повернути `a[m]`.
3. Інакше повторити в тій частині, де лежить `k`.
4. Очікуваний час `O(n)`, найгірший `O(n²)` (або `O(n)` з median of medians).

   ```js
   function threeWayPartition(a, pivot) {
     let lt = 0, i = 0, gt = a.length - 1;
     while (i <= gt) {
       if (a[i] < pivot) {
         [a[lt], a[i]] = [a[i], a[lt]];
         lt++;
         i++;
       } else if (a[i] > pivot) {
         [a[gt], a[i]] = [a[i], a[gt]];
         gt--;
       } else i++;
     }
     return [lt, gt];
   }
   ```

   ```js
   function quickselectIterHoare(input, k) {
     const a = input.slice();
     let lo = 0, hi = a.length - 1;
     while (lo < hi) {
       const p = a[(lo + hi) >> 1];
       let i = lo, j = hi;
       while (i <= j) {
         while (a[i] < p) i++;
         while (a[j] > p) j--;
         if (i <= j) {
           [a[i], a[j]] = [a[j], a[i]];
           i++;
           j--;
         }
       }
       if (k <= j) hi = j;
       else if (k >= i) lo = i;
       else return a[k];
     }
     return a[k];
   }
   ```

39. Quicksort рекурсивно обробляє **обидві** половини, і на кожному з `log n` рівнів загальна робота `O(n)`. Quickselect іде лише в **одну** половину, тож роботи `n + n/2 + n/4 + … ≤ 2n` (для балансних розбиттів), тобто лінійно.
40. Коли опорний щоразу виявляється найменшим або найбільшим (відсортований масив при опорному з краю, багато рівних елементів у Ломуто). Лікування: випадковий опорний, медіана з трьох, тристороннє розбиття для дублікатів або median of medians для гарантії `O(n)`.
41. Група з п'яти елементів → медіана → рекурсивно медіана медіан. Такий опорний більший щонайменше за `30%` елементів і менший за `30%`, тому розмір підзадачі `≤ 7n/10`. Рекурентність `T(n) ≤ T(n/5) + T(7n/10) + cn` дає `O(n)`, бо `1/5 + 7/10 < 1`.
42. Купа: `O(n log k)`, працює на потоці й не потребує всіх даних у пам'яті, зберігає `k` елементів. Quickselect: `O(n)` у середньому, потрібен весь масив і він його переставляє. Для малого `k` і потоків — купа; для разового запиту на масиві — quickselect.
43. Розбиття ставить опорний на остаточну позицію й гарантує тільки «ліворуч менші, праворуч більші». Усередині цих частин порядок довільний, а ми зупиняємося, щойно опорний потрапив на індекс `k`, тому решта елементів не відсортована.
44. k-й найбільший — це елемент, який у відсортованому за зростанням масиві стоїть на позиції `n − k` (нумерація з нуля): найбільший (`k = 1`) — на `n − 1`.
45. Перцентиль — це k-й за порядком елемент для `k = ⌈p·n⌉`; quickselect дає його без сортування. Для безперервного потоку потрібні дві купи або наближені структури (t-digest), бо quickselect вимагає всього масиву.
46. Ломуто — один вказівник, опорний лишається на межі й повертається його остаточний індекс, але багато обмінів і слабка робота з дублікатами. Хоара — два вказівники з країв; менше обмінів і краща поведінка на дублікатах, але повертає межу, яка не обов'язково є позицією опорного, тож кордони рекурсії інші.
47. Опорний уже стоїть на остаточній позиції `m` і не повинен розглядатися знову; якщо залишити `m` у діапазоні, можливе зациклення, коли діапазон не звужується.
48. Так: якщо рядки й стовпці відсортовані, застосовують бінарний пошук за значенням із підрахунком кількості елементів `≤ x` за `O(n)` на крок, загалом `O(n log(max − min))`, або купу. Quickselect на розгорнутій матриці дав би `O(n²)` на `n×n`.
49. Кордон і результат лишаться правильними (опорний усе одно стає на межу), але для масивів із багатьма рівними елементами розбиття ще більше перекошуватиметься в один бік, бо всі рівні йтимуть ліворуч; на однакових елементах час вироджується в `O(n²)`.
