# Floyd–Warshall — найкоротші шляхи між усіма парами

Алгоритм Флойда—Воршелла обчислює найкоротші відстані **між усіма парами вершин** за `O(V³)`: три вкладені цикли й один рядок у середині. Він працює з від'ємними вагами (але без від'ємних циклів), знаходить їх і природно пов'язаний із **транзитивним замиканням** (чи досяжна `v` з `u`). Це класичний приклад динамічного програмування, чия елегантність — у правильному **порядку циклів**.

## 1. Задача

Дано зважений орієнтований граф на `V` вершинах. Побудувати таблицю `d[i][j]` — довжину найкоротшого шляху `i → j` для всіх пар. Альтернативи: запустити [Дейкстру](dijkstra.md) із кожної вершини (`O(V·(V + E) log V)`, ваги `≥ 0`) або Беллмана—Форда (`O(V²·E)`). Флойд—Воршелл виграє на **щільних** графах і за простотою коду.

## 2. Динаміка: «дозволені проміжні вершини»

Позначимо `d_k[i][j]` — довжину найкоротшого шляху `i → j`, у якому **проміжними вершинами** можуть бути лише `{0, …, k − 1}` (перші `k` вершин). Тоді:

- `d_0[i][j]` — вага прямого ребра (або `0` при `i = j`, `∞` якщо ребра немає);
- перехід до `d_{k+1}` — додаємо вершину `k` як дозволену проміжну. Найкоротший шлях `i → j` або **не проходить** через `k` (тоді `d_k[i][j]`), або проходить **рівно один раз** (шлях без циклів): `i → k` та `k → j`, обидва з проміжними з `{0..k−1}`:

`d_{k+1}[i][j] = min(d_k[i][j], d_k[i][k] + d_k[k][j])`.

Після `k = V` проміжними можуть бути всі вершини — отримали відповідь. Таблиці можна **перезаписувати на місці**, бо `d[i][k]` і `d[k][j]` на `k`-му кроці не змінюються (при відсутності від'ємних циклів `d[k][k] = 0`).

**Зовнішнім циклом має бути `k`** (проміжна вершина), а не `i` чи `j`. Це найчастіша помилка: ітерація по `k` ззовні гарантує, що на момент врахування `k` усі комбінації з меншими проміжними вершинами вже готові.

## 3. Приклад

Орієнтований граф на 4 вершинах (`0..3`): `0→1 (5)`, `0→3 (10)`, `1→2 (3)`, `2→3 (1)`. Таблиця відстаней:

```text
0	5	8	9
∞	0	3	4
∞	∞	0	1
∞	∞	∞	0
```

(`∞` — шляху немає). Відстань `0 → 3`: пряме ребро коштує 10, а шлях `0→1→2→3` — `5 + 3 + 1 = 9`, тому 9. Відновлений шлях: `[0, 1, 2, 3]`.

## 4. Реалізація

```js
const fwEdges = [[0, 1, 5], [0, 3, 10], [1, 2, 3], [2, 3, 1]];

function fw(n, edges) {
  const dist = Array.from({ length: n }, (_, i) => Array.from({ length: n }, (_, j) => (i === j ? 0 : Infinity)));
  const next = Array.from({ length: n }, () => new Array(n).fill(-1));
  for (const [u, v, w] of edges) {
    if (w < dist[u][v]) { dist[u][v] = w; next[u][v] = v; }
  }
  for (let i = 0; i < n; i++) next[i][i] = i;
  for (let k = 0; k < n; k++) {
    for (let i = 0; i < n; i++) {
      if (dist[i][k] === Infinity) continue;
      for (let j = 0; j < n; j++) {
        if (dist[i][k] + dist[k][j] < dist[i][j]) {
          dist[i][j] = dist[i][k] + dist[k][j];
          next[i][j] = next[i][k];
        }
      }
    }
  }
  return { dist, next };
}

function fwTable(dist) {
  return dist.map((row) => row.map((x) => (x === Infinity ? '∞' : String(x))).join('\t')).join('\n');
}

function fwPath(res, u, v) {
  if (res.next[u][v] === -1) return null;
  const path = [u];
  while (u !== v) {
    u = res.next[u][v];
    path.push(u);
  }
  return path;
}

function hasNegativeCycleFW(n, edges) {
  const { dist } = fw(n, edges);
  for (let i = 0; i < n; i++) if (dist[i][i] < 0) return true;
  return false;
}

function transitiveClosure(n, edges) {
  const reach = Array.from({ length: n }, (_, i) => Array.from({ length: n }, (_, j) => i === j));
  for (const [u, v] of edges) reach[u][v] = true;
  for (let k = 0; k < n; k++) for (let i = 0; i < n; i++) for (let j = 0; j < n; j++) {
    if (reach[i][k] && reach[k][j]) reach[i][j] = true;
  }
  return reach;
}

function graphDiameter(n, edges) {
  const { dist } = fw(n, edges);
  let best = 0;
  for (let i = 0; i < n; i++) for (let j = 0; j < n; j++) if (dist[i][j] !== Infinity) best = Math.max(best, dist[i][j]);
  return best;
}

function graphCenter(n, edges) {
  const { dist } = fw(n, edges);
  let best = Infinity;
  let center = -1;
  for (let i = 0; i < n; i++) {
    const ecc = Math.max(...dist[i]);
    if (ecc < best) { best = ecc; center = i; }
  }
  return center;
}

function findTheCity(n, edges, threshold) {
  const und = edges.flatMap(([u, v, w]) => [[u, v, w], [v, u, w]]);
  const { dist } = fw(n, und);
  let best = -1;
  let bestCount = Infinity;
  for (let i = 0; i < n; i++) {
    let c = 0;
    for (let j = 0; j < n; j++) if (i !== j && dist[i][j] <= threshold) c++;
    if (c <= bestCount) { bestCount = c; best = i; }
  }
  return best;
}

function countSccPairs(n, edges) {
  const r = transitiveClosure(n, edges);
  let pairs = 0;
  for (let i = 0; i < n; i++) for (let j = i + 1; j < n; j++) if (r[i][j] && r[j][i]) pairs++;
  return pairs;
}

function minimaxPaths(n, edges) {
  const b = Array.from({ length: n }, (_, i) => Array.from({ length: n }, (_, j) => (i === j ? 0 : Infinity)));
  for (const [u, v, w] of edges) b[u][v] = Math.min(b[u][v], w);
  for (let k = 0; k < n; k++) for (let i = 0; i < n; i++) for (let j = 0; j < n; j++) {
    const cand = Math.max(b[i][k], b[k][j]);
    if (cand < b[i][j]) b[i][j] = cand;
  }
  return b;
}

function allPairsViaDijkstraCount(n, edges) {
  return n * (n + edges.length);
}
```

## 5. Відновлення шляху

Окрім відстаней зберігаємо таблицю `next[i][j]` — **наступну вершину** на найкоротшому шляху `i → j`. Початково `next[i][j] = j` для кожного ребра; при релаксації через `k` — `next[i][j] = next[i][k]` (першим кроком до `j` через `k` є перший крок до `k`). Шлях відновлюється циклом: `u = next[u][v]`, поки `u ≠ v`. `fwPath(fw(4, fwEdges), 0, 3)` = `[0, 1, 2, 3]`; недосяжний: `fwPath(fw(4, fwEdges), 3, 0)` = `null`.

## 6. Від'ємні цикли

Якщо після алгоритму `dist[i][i] < 0` для якоїсь вершини — вона лежить на від'ємному циклі. `hasNegativeCycleFW(3, [[0, 1, 1], [1, 2, -1], [2, 0, -1]])` = `true`; а для `fwEdges` — `false`. Але таблиця «відстаней» у присутності від'ємних циклів **неправильна** (значення можуть експоненційно зростати за модулем), тому цикли слід перевіряти й обробляти окремо.

## 7. Транзитивне замикання (алгоритм Воршелла)

Замість мін і суми — логічні `OR` і `AND`: `reach[i][j] ||= reach[i][k] && reach[k][j]`. Відповідає на питання «чи є шлях `i → j`» для всіх пар: `transitiveClosure(4, [[0, 1], [1, 2], [2, 3]])[0]` = `[true, true, true, true]`. Із бітовими масками — `O(V³ / 64)`.

Узагальнення: той самий шаблон дає **мінімаксні шляхи** (мінімізувати найважче ребро; `max` замість `+`), **максимальну пропускну здатність**, **найнадійніші шляхи** (добуток ймовірностей) — у будь-якому «напівкільці». Приклад мінімакс: `minimaxPaths(3, [[0, 1, 5], [1, 2, 2], [0, 2, 9]])[0][2]` = 5.

## 8. Застосування

- **Діаметр і центр графа:** `graphDiameter(4, fwEdges)` = `9`.
- **Задача «знайти місто» з порогом відстані** (LeetCode 1334): `findTheCity(4, [[0, 1, 3], [1, 2, 1], [1, 3, 4], [2, 3, 1]], 4)` = `3`.
- **Взаємна досяжність:** пар вершин у спільних сильно зв'язних компонентах — `1`; ефективніше — [Тар'ян](tarjan-scc.md).
- **Маршрутні таблиці, мережеві метрики, ранжування турнірів** (транзитивність перемог), **аналіз залежностей**.

## 9. Складність

- **Час `O(V³)`** незалежно від кількості ребер.
- **Пам'ять `O(V²)`** (таблиця відстаней, плюс `next` для шляхів).
- Для `V = 400` — 64 мільйони операцій (секунда в JS), для `V = 1000` — мільярд (десятки секунд).
- **Порівняння:** розріджений граф: `V` запусків Дейкстри (`O(V·E log V)`) краще; щільний або від'ємні ваги з малим `V` — Флойд—Воршелл. Для великих розріджених графів із від'ємними вагами — Джонсон (Беллман—Форд + Дейкстра).

## 10. Типові помилки

1. **Неправильний порядок циклів** (`k` не зовнішній) — часткові, неправильні відстані.
2. **`dist[i][i] ≠ 0`** на старті — діагональ має бути `0`.
3. **Мульти-ребра:** брати **мінімум** серед паралельних ребер, а не останнє.
4. **`∞ + w` в інших мовах** призводить до переповнення — перевіряйте `dist[i][k] !== ∞`.
5. **Від'ємні цикли** — результат бессенсовний; перевіряйте діагональ.
6. **Неорієнтований граф:** додавайте ребро в обидва боки.
7. **Відновлення шляху:** `next[i][j] = next[i][k]`, а не `k`.
8. **Використання для `V` порядку 10⁴** — `10¹²` операцій.

## 11. Алгоритм (стисло)

1. `d[i][i] = 0`, `d[i][j] = w(i, j)` або `∞`.
2. Для `k` від `0` до `V − 1`, для всіх `i`, `j`: `d[i][j] = min(d[i][j], d[i][k] + d[k][j])`.
3. Якщо `d[i][i] < 0` — є від'ємний цикл.
4. Час `O(V³)`, пам'ять `O(V²)`.

36. Динаміка `d_{k+1}[i][j] = min(d_k[i][j], d_k[i][k] + d_k[k][j])` вимагає, щоб при додаванні проміжної вершини `k` усі відстані з проміжними `{0..k−1}` уже були обчислені для всіх пар. Якщо `k` — внутрішній цикл, ці значення ще неготові.
37. На кроці `k` значення `d[i][k]` та `d[k][j]` не змінюються (бо `d[k][k] = 0` за відсутності від'ємних циклів), тож оновлення `d[i][j]` використовує ті самі значення, що й версія з двома таблицями.
38. Після завершення елемент діагоналі `d[i][i]` стає від'ємним, якщо вершина `i` лежить на від'ємному циклі, бо шлях від `i` до себе через цикл дешевший за `0`.
39. Зберігати `next[i][j]` — наступну вершину на шляху `i → j`: початково `j` для ребер, а при релаксації через `k` — `next[i][k]`. Далі, починаючи з `u`, переходити `u = next[u][v]`, поки `u ≠ v`.
40. У щільних графах (`E ≈ V²`), коли код має бути простим, або коли є від'ємні ваги й `V` невелике. Для розріджених графів із невід'ємними вагами `V` запусків Дейкстри асимптотично швидші.
41. Це матриця досяжності: чи існує шлях `i → j`. Алгоритм Воршелла — той самий шаблон із `OR`/`AND` замість `min`/`+`: `reach[i][j] ||= reach[i][k] && reach[k][j]`.
42. Для будь-якого напівкільця: мінімаксні шляхи (`max` замість `+`), найширший шлях (максимізація мінімального ребра), найнадійніший шлях (добуток ймовірностей), досяжність (булеві операції).
43. Кожне проходження циклу зменшує довжину, тож найкоротшого шляху не існує, а значення в таблиці залежать від порядку обробки й можуть зростати за модулем; тому слід спочатку перевірити діагональ і виключити такі пари.
