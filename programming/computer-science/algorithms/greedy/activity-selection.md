# Activity Selection та жадібні алгоритми

**Жадібний алгоритм** на кожному кроці робить **локально найкращий** вибір і ніколи не переглядає його, сподіваючись отримати глобальний оптимум. Для більшості задач це не працює (див. [coin-change.md](../dynamic-programming/coin-change.md)), але в окремих випадках жадібний вибір **доведено** оптимальним — і тоді алгоритм простий і швидкий. Ця нотатка — про класичну задачу **вибору заявок (activity selection)** і про те, **як доводити** правильність жадібного алгоритму.

## 1. Задача

Є `n` заявок (зустрічей, завдань) із часом початку `s[i]` і завершення `f[i]`; дві заявки **сумісні**, якщо їхні інтервали не перетинаються (`f[i] ≤ s[j]`). Вибрати **максимальну кількість** взаємно сумісних заявок на одну «кімнату/ресурс».

Приклад: `[[1, 4], [3, 5], [0, 6], [5, 7], [3, 9], [5, 9], [6, 10], [8, 11], [8, 12], [2, 14], [12, 16]]` → максимум `4` заявки: `[[1, 4], [5, 7], [8, 11], [12, 16]]`.

## 2. Які жадібні критерії спробувати

Інтуїтивно кілька ідей:

| Критерій | Працює? | Контрприклад |
|---|---|---|
| Найраніший **початок** | ні | `[0, 100]`, `[1, 2]`, `[3, 4]` — візьме довгу заявку |
| Найкоротша **тривалість** | ні | `[0, 5]`, `[4, 7]`, `[6, 11]`: коротка `[4, 7]` блокує обидві сусідні |
| Найменше **перетинів** з іншими | ні | існують складніші контрприклади |
| Найраніше **завершення** | **так** | — |

`earliestStartGreedy([[0, 100], [1, 2], [3, 4]])` = 1 (1 заявка), хоча оптимум — 2. Аналогічно `shortestFirstGreedy([[0, 5], [4, 7], [6, 11]])` = 1 проти оптимуму 2.

## 3. Правильний критерій: найраніше завершення

**Алгоритм.**

1. Відсортувати заявки за **часом завершення**.
2. Взяти першу. Нехай `lastEnd` — її кінець.
3. Для кожної наступної: якщо `start ≥ lastEnd` — взяти, `lastEnd = end`; інакше пропустити.

Сортування `O(n log n)`, прохід `O(n)`.

## 4. Доведення (технічка «обмін»: exchange argument)

**Лема 1 (жадібний вибір безпечний).** Існує оптимальний розв'язок, що містить заявку `a₁` з найранішим завершенням.

*Доказ.* Нехай `OPT` — оптимальний розв'язок, у якому першою (за часом) є заявка `b`. Якщо `b = a₁` — готово. Інакше замінимо `b` на `a₁`: оскільки `f(a₁) ≤ f(b)`, заявка `a₁` закінчується не пізніше за `b`, тож не перетинається з рештою `OPT`. Кількість заявок не змінилась, тому `OPT' = OPT \ {b} ∪ {a₁}` — теж оптимальний. ∎

**Лема 2 (оптимальна підструктура).** Після вибору `a₁` залишок задачі — це та сама задача на заявках, що починаються не раніше `f(a₁)`.

За індукцією жадібний алгоритм будує оптимум. Загальна схема доведення жадібних алгоритмів: **(1)** показати, що жадібний вибір може входити в оптимум (обмін); **(2)** показати оптимальну підструктуру.

## 5. Трасування

`activityTrace([[1, 4], [3, 5], [0, 6], [5, 7], [3, 9], [5, 9], [6, 10], [8, 11], [8, 12], [2, 14], [12, 16]])`:

- [1, 4] беремо
- [3, 5] перетинається (початок 3 < 4)
- [0, 6] перетинається (початок 0 < 4)
- [5, 7] беремо
- [3, 9] перетинається (початок 3 < 7)
- [5, 9] перетинається (початок 5 < 7)
- [6, 10] перетинається (початок 6 < 7)
- [8, 11] беремо
- [8, 12] перетинається (початок 8 < 11)
- [2, 14] перетинається (початок 2 < 11)
- [12, 16] беремо

## 6. Реалізація

```js
function maxActivities(acts) {
  const sorted = acts.slice().sort((a, b) => a[1] - b[1] || a[0] - b[0]);
  const chosen = [];
  let lastEnd = -Infinity;
  for (const [s, f] of sorted) {
    if (s >= lastEnd) {
      chosen.push([s, f]);
      lastEnd = f;
    }
  }
  return chosen;
}

function activityTrace(acts) {
  const sorted = acts.slice().sort((a, b) => a[1] - b[1] || a[0] - b[0]);
  const out = [];
  let lastEnd = -Infinity;
  for (const [s, f] of sorted) {
    if (s >= lastEnd) { out.push('[' + s + ', ' + f + '] беремо'); lastEnd = f; }
    else out.push('[' + s + ', ' + f + '] перетинається (початок ' + s + ' < ' + lastEnd + ')');
  }
  return out;
}

function earliestStartGreedy(acts) {
  const sorted = acts.slice().sort((a, b) => a[0] - b[0]);
  const chosen = [];
  let lastEnd = -Infinity;
  for (const [s, f] of sorted) if (s >= lastEnd) { chosen.push([s, f]); lastEnd = f; }
  return chosen.length;
}

function shortestFirstGreedy(acts) {
  const sorted = acts.slice().sort((a, b) => a[1] - a[0] - (b[1] - b[0]));
  const chosen = [];
  for (const [s, f] of sorted) if (chosen.every(([cs, cf]) => f <= cs || s >= cf)) chosen.push([s, f]);
  return chosen.length;
}

function bruteForceMax(acts) {
  let best = 0;
  const n = acts.length;
  for (let mask = 0; mask < 1 << n; mask++) {
    const sel = [];
    for (let i = 0; i < n; i++) if (mask & (1 << i)) sel.push(acts[i]);
    sel.sort((a, b) => a[0] - b[0]);
    let ok = true;
    for (let i = 1; i < sel.length; i++) if (sel[i][0] < sel[i - 1][1]) ok = false;
    if (ok) best = Math.max(best, sel.length);
  }
  return best;
}

function minRoomsGreedy(acts) {
  const starts = acts.map((a) => a[0]).sort((a, b) => a - b);
  const ends = acts.map((a) => a[1]).sort((a, b) => a - b);
  let rooms = 0;
  let j = 0;
  for (let i = 0; i < starts.length; i++) {
    if (starts[i] >= ends[j]) j++;
    else rooms++;
  }
  return rooms;
}

function weightedIntervalScheduling(acts) {
  const a = acts.slice().sort((x, y) => x[1] - y[1]);
  const n = a.length;
  const dp = new Array(n + 1).fill(0);
  for (let i = 1; i <= n; i++) {
    let lo = 0;
    let hi = i - 1;
    let p = 0;
    while (lo <= hi) {
      const mid = (lo + hi) >> 1;
      if (a[mid][1] <= a[i - 1][0]) { p = mid + 1; lo = mid + 1; }
      else hi = mid - 1;
    }
    dp[i] = Math.max(dp[i - 1], dp[p] + a[i - 1][2]);
  }
  return dp[n];
}

function jumpGame(nums) {
  let far = 0;
  for (let i = 0; i < nums.length; i++) {
    if (i > far) return false;
    far = Math.max(far, i + nums[i]);
  }
  return true;
}

function jumpGameII(nums) {
  let jumps = 0;
  let curEnd = 0;
  let far = 0;
  for (let i = 0; i < nums.length - 1; i++) {
    far = Math.max(far, i + nums[i]);
    if (i === curEnd) { jumps++; curEnd = far; }
  }
  return jumps;
}

function gasStation(gas, cost) {
  let total = 0;
  let tank = 0;
  let start = 0;
  for (let i = 0; i < gas.length; i++) {
    const d = gas[i] - cost[i];
    total += d;
    tank += d;
    if (tank < 0) { start = i + 1; tank = 0; }
  }
  return total >= 0 ? start : -1;
}

function assignCookies(children, cookies) {
  const g = children.slice().sort((a, b) => a - b);
  const s = cookies.slice().sort((a, b) => a - b);
  let i = 0;
  for (const c of s) if (i < g.length && c >= g[i]) i++;
  return i;
}

function taskScheduler(tasks, n) {
  const freq = {};
  for (const t of tasks) freq[t] = (freq[t] || 0) + 1;
  const max = Math.max(...Object.values(freq));
  const countMax = Object.values(freq).filter((v) => v === max).length;
  return Math.max(tasks.length, (max - 1) * (n + 1) + countMax);
}

function minPlatforms(arr, dep) {
  return minRoomsGreedy(arr.map((a, i) => [a, dep[i]]));
}

function candyDistribution(ratings) {
  const n = ratings.length;
  const c = new Array(n).fill(1);
  for (let i = 1; i < n; i++) if (ratings[i] > ratings[i - 1]) c[i] = c[i - 1] + 1;
  for (let i = n - 2; i >= 0; i--) if (ratings[i] > ratings[i + 1]) c[i] = Math.max(c[i], c[i + 1] + 1);
  return c.reduce((s, x) => s + x, 0);
}

function lemonadeChange(bills) {
  let five = 0;
  let ten = 0;
  for (const b of bills) {
    if (b === 5) five++;
    else if (b === 10) { if (!five) return false; five--; ten++; }
    else {
      if (ten && five) { ten--; five--; }
      else if (five >= 3) five -= 3;
      else return false;
    }
  }
  return true;
}
```

## 7. Складність

- **Сортування** `O(n log n)`, прохід `O(n)` → `O(n log n)`; пам'ять `O(n)`.
- Якщо заявки вже відсортовані за завершенням — `O(n)`.
- Перебір усіх підмножин (`bruteForceMax`) — `O(2ⁿ · n)`; для `n = 20` — ≈ 20 млн варіантів.

## 8. Варіації

- **Мінімум кімнат/платформ** (graph colouring інтервального графа): sweep по відсортованих початках і кінцях: `minRoomsGreedy([[0, 30], [5, 10], [15, 20]])` = `2`; `minPlatforms([900, 940, 950, 1100, 1500, 1800], [910, 1200, 1120, 1130, 1900, 2000])` = `3`. Мінімальна кількість «кімнат» = максимальна кількість одночасно активних заявок.
- **Зважений вибір заявок** (кожна має вагу/прибуток): жадібність **не** працює — потрібне ДП + бінарний пошук `O(n log n)`: `weightedIntervalScheduling([[1, 3, 5], [2, 5, 6], [4, 6, 5], [6, 7, 4], [5, 8, 11], [7, 9, 2]])` = `17` (див. [merge-intervals.md](../techniques/merge-intervals.md)).
- **Мінімальне видалення для безперетину** — доповнення до максимального вибору.

## 9. Інші класичні жадібні задачі

- **Гра у стрибки:** `jumpGame([2, 3, 1, 1, 4])` = `true`, `jumpGame([3, 2, 1, 0, 4])` = `false`; мінімум стрибків `jumpGameII([2, 3, 1, 1, 4])` = `2` — жадібно: найдальше досяжне в межах поточного стрибка.
- **Заправка (gas station):** `gasStation([1, 2, 3, 4, 5], [3, 4, 5, 1, 2])` = `3` (старт з індексу 3).
- **Печиво дітям:** `assignCookies([1, 2, 3], [1, 1])` = `1`, `assignCookies([1, 2], [1, 2, 3])` = `2` — найменше печиво, що задовольняє найбільш невибагливу дитину.
- **Планувальник завдань із охолодженням:** `taskScheduler(['A', 'A', 'A', 'B', 'B', 'B'], 2)` = `8`.
- **Цукерки за рейтингами:** `candyDistribution([1, 0, 2])` = `5`; два проходи — зліва й справа.
- **Лимонад:** `lemonadeChange([5, 5, 5, 10, 20])` = `true`.
- **Кодування Хаффмана** — жадібно об'єднуємо два найрідші символи: [huffman-coding.md](huffman-coding.md).
- **Фракційний рюкзак**, **мінімальне кістякове дерево** (Крускал/Прим), **Дейкстра** — жадібні за природою.

## 10. Коли жадібність працює

Жадібний алгоритм коректний, коли виконуються:

1. **Властивість жадібного вибору:** локально оптимальний вибір входить у деякий глобальний оптимум (доводять обміном).
2. **Оптимальна підструктура.**

Часто це **матроїди** — структури, де жадібність гарантовано оптимальна (MST, вибір лінійно незалежних векторів). Приклади, де жадібність **не** працює: 0/1-рюкзак, розмін монет довільної системи, найкоротший шлях із від'ємними вагами, TSP.

## 11. Типові помилки

1. **Сортувати за початком або тривалістю** — хибний критерій.
2. **Строга/нестрога нерівність:** `start ≥ lastEnd` (дотик допустимий) чи `>` — за умовою.
3. **Брати першу заявку без сортування.**
4. **Жадібність у зваженому варіанті** — потрібне ДП.
5. **Не довести жадібний вибір** — інтуїція ненадійна; перевіряйте перебором на малих даних (`bruteForceMax`).
6. **Нестабільне сортування, що ламає рівні кінці:** вторинний ключ за початком.
7. **Мутація вхідного масиву `sort` на місці.**
8. **Плутанина між «максимум заявок» і «мінімум кімнат».**

## 12. Алгоритм (стисло)

1. Відсортувати заявки за кінцем.
2. `lastEnd = −∞`; для кожної: якщо `start ≥ lastEnd` — взяти й `lastEnd = end`.
3. Час `O(n log n)`.
