# Prefix Sums — префіксні суми та різницевий масив

Префіксні суми — спосіб **один раз** витратити `O(n)` на підготовку, щоб потім відповідати на запити «сума на відрізку `[l, r]`» за `O(1)`. Дзеркальна ідея — **різницевий масив** — дозволяє робити «додати `v` на всьому відрізку» за `O(1)`. Разом із хеш-таблицею префіксні суми розв'язують «сума підмасиву дорівнює `k`» там, де ковзне вікно безсиле (від'ємні числа).

## 1. Ідея

Нехай `a = [3, 1, 4, 1, 5, 9, 2, 6]`. Побудуємо масив `P` довжини `n + 1`:

`P[0] = 0`, `P[i + 1] = P[i] + a[i]`, тобто `P[i]` — сума перших `i` елементів.

Для нашого `a`: `P = `[0, 3, 4, 8, 9, 14, 23, 25, 31]``.

Сума елементів на відрізку `[l, r]` (включно) — це «все до `r`» мінус «все до `l − 1`»:

`sum(l, r) = P[r + 1] − P[l]`.

Наприклад, `sum(2, 5)` = `a[2] + a[3] + a[4] + a[5]` = `4 + 1 + 5 + 9` = 19. Один відлік замість циклу.

**Навіщо перший нуль** (`P[0] = 0`)? Щоб формула працювала й для відрізка, що починається з `0`: `sum(0, r) = P[r + 1] − P[0]`. Без цього довелося б обробляти `l = 0` окремо — головне джерело помилок.

**Ціна:** підготовка `O(n)`, пам'ять `O(n)`, запит `O(1)`. Це окупається, коли запитів багато (`q` запитів: `O(n + q)` замість `O(n·q)`). Якщо масив **змінюється**, префіксні суми застарівають — потрібне [дерево Фенвіка](../trees/fenwick-tree.md) або дерево відрізків (оновлення і запит за `O(log n)`).

## 2. Чому це працює: телескопічна сума

`P[r + 1] − P[l] = (a[0] + … + a[r]) − (a[0] + … + a[l − 1]) = a[l] + … + a[r]`. Усе зайве скорочується. Та сама ідея діє для будь-якої **оборотної** операції: сума, XOR (`x ^ x = 0`), добуток (якщо немає нулів; ділення), кількість елементів із властивістю. Для `min`/`max` префікси не підходять — для них немає оберненої операції (використовують sparse table чи дерево відрізків).

## 3. Підмасив із сумою `k`: префікси + хеш-таблиця

Задача: скільки неперервних підмасивів мають суму рівно `k`? Масив може містити **від'ємні** числа — вікно не працює.

Підмасив `(j, i]` має суму `k`, якщо `P[i] − P[j] = k`, тобто `P[j] = P[i] − k`. Рухаємось зліва направо, підтримуємо **частоти вже побачених префіксів** `seen`. У точці `i` кількість підмасивів, що закінчуються тут, дорівнює `seen[P[i] − k]`. Початкове `seen[0] = 1` — порожній префікс (відповідає підмасивам, що починаються з індексу 0).

`subarraySumCount([1, 2, 3], 3)` = `2` (`[1, 2]` і `[3]`), `subarraySumCount([1, -1, 0], 0)` = `3` (`[1, -1]`, `[1, -1, 0]`, `[0]`). Час `O(n)`, пам'ять `O(n)`.

Та сама схема:

- **Підмасив із сумою, кратною `k`:** префікси за модулем: `P[i] mod k = P[j] mod k` (`subarraysDivByK([4, 5, 0, -2, -3, 1], 5)` = `7`; зауважте, що залишок від'ємного числа треба нормувати `((x % k) + k) % k`).
- **Найдовший підмасив із сумою `k`:** зберігати **перший** індекс кожного префікса.
- **Однакова кількість нулів і одиниць:** замінити `0` на `−1` і шукати суму `0` (`findMaxLengthBinary([0, 1, 0, 0, 1, 1, 0])` = `6`).
- **Підмасив XOR = `k`:** префікси XOR.

## 4. Двовимірні префіксні суми

Для матриці `m` (`R × C`) будуємо `S[(R + 1) × (C + 1)]`, де `S[i][j]` — сума прямокутника з кутом `(0, 0)` до `(i − 1, j − 1)`:

`S[i + 1][j + 1] = m[i][j] + S[i][j + 1] + S[i + 1][j] − S[i][j]` (віднімаємо подвійно пораховане).

Сума прямокутника `(r1, c1)…(r2, c2)` за принципом включень-виключень:

`S[r2 + 1][c2 + 1] − S[r1][c2 + 1] − S[r2 + 1][c1] + S[r1][c1]`.

Приклад: матриця `[[1, 2, 3], [4, 5, 6], [7, 8, 9]]`, прямокутник `(1, 1)…(2, 2)` (нижній правий кут) = `5 + 6 + 8 + 9` = 28. Підготовка `O(R·C)`, запит `O(1)`. Це «інтегральне зображення» (summed-area table) із комп'ютерного зору.

## 5. Різницевий масив: «додати на відрізку» за `O(1)`

Обернена задача: є багато операцій «додати `v` до всіх `a[l..r]`», а прочитати масив потрібно лише в кінці. Різницевий масив `D`, де `D[i] = a[i] − a[i − 1]`. Додавання `v` на `[l, r]` змінює лише дві клітинки: `D[l] += v`, `D[r + 1] −= v`. Щоб відновити масив, беремо префіксні суми `D`. Тобто **різниці — це обернена операція до префіксних сум**.

`rangeAddUpdates(5, [[1, 3, 2], [2, 4, 3], [0, 2, −2]])` — масив із 5 нулів, три оновлення `[l, r, v]` → `[-2, 0, 3, 5, 3]`. `m` оновлень + відновлення коштують `O(m + n)` замість `O(m·n)`.

Застосування: бронювання місць (авіарейси), «карпулінг» (максимум пасажирів), покриття відрізками, інтервальні події (кількість активних подій у кожну мить — [merge-intervals.md](merge-intervals.md)).

## 6. Інші корисні прийоми

- **Точка рівноваги (pivot index):** індекс, де сума ліворуч дорівнює сумі праворуч: `pivotIndex([1, 7, 3, 6, 5, 6])` = `3` (`left = P[i]`, `right = total − P[i + 1]`).
- **Добуток усіх, крім поточного:** без ділення — префіксні й суфіксні добутки: `productExceptSelf([1, 2, 3, 4])` = `[24, 12, 8, 6]`.
- **Максимальний прибуток / дисбаланс:** найбільша різниця `P[j] − P[i]` для `j > i` (стежимо за мінімальним префіксом) — це і є ідея [алгоритму Кадане](kadane.md).
- **Префікси за літерами:** частота літери `c` на `[l, r]` — окремий префіксний масив для кожної літери (`26 × n`).

## 7. Реалізація

```js
function prefix(a) {
  const P = [0];
  for (const x of a) P.push(P[P.length - 1] + x);
  return P;
}

function rangeSum(P, l, r) {
  return P[r + 1] - P[l];
}

function subarraySumCount(a, k) {
  const seen = new Map([[0, 1]]);
  let sum = 0;
  let count = 0;
  for (const x of a) {
    sum += x;
    count += seen.get(sum - k) || 0;
    seen.set(sum, (seen.get(sum) || 0) + 1);
  }
  return count;
}

function subarraysDivByK(a, k) {
  const seen = new Map([[0, 1]]);
  let sum = 0;
  let count = 0;
  for (const x of a) {
    sum = (((sum + x) % k) + k) % k;
    count += seen.get(sum) || 0;
    seen.set(sum, (seen.get(sum) || 0) + 1);
  }
  return count;
}

function findMaxLengthBinary(a) {
  const first = new Map([[0, -1]]);
  let sum = 0;
  let best = 0;
  for (let i = 0; i < a.length; i++) {
    sum += a[i] === 1 ? 1 : -1;
    if (first.has(sum)) best = Math.max(best, i - first.get(sum));
    else first.set(sum, i);
  }
  return best;
}

function prefix2D(m) {
  const R = m.length;
  const C = R ? m[0].length : 0;
  const S = Array.from({ length: R + 1 }, () => new Array(C + 1).fill(0));
  for (let i = 0; i < R; i++) {
    for (let j = 0; j < C; j++) {
      S[i + 1][j + 1] = m[i][j] + S[i][j + 1] + S[i + 1][j] - S[i][j];
    }
  }
  return S;
}

function rectSum(S, r1, c1, r2, c2) {
  return S[r2 + 1][c2 + 1] - S[r1][c2 + 1] - S[r2 + 1][c1] + S[r1][c1];
}

function rangeAddUpdates(n, updates) {
  const D = new Array(n + 1).fill(0);
  for (const [l, r, v] of updates) {
    D[l] += v;
    D[r + 1] -= v;
  }
  const out = [];
  let cur = 0;
  for (let i = 0; i < n; i++) {
    cur += D[i];
    out.push(cur);
  }
  return out;
}

function pivotIndex(a) {
  const total = a.reduce((s, x) => s + x, 0);
  let left = 0;
  for (let i = 0; i < a.length; i++) {
    if (left === total - left - a[i]) return i;
    left += a[i];
  }
  return -1;
}

function productExceptSelf(a) {
  const n = a.length;
  const out = new Array(n).fill(1);
  let pre = 1;
  for (let i = 0; i < n; i++) { out[i] = pre; pre *= a[i]; }
  let suf = 1;
  for (let i = n - 1; i >= 0; i--) { out[i] *= suf; suf *= a[i]; }
  return out;
}
```

## 8. Складність

| Задача | Підготовка | Запит |
|---|---|---|
| Сума на відрізку | `O(n)` | `O(1)` |
| Сума в прямокутнику | `O(R·C)` | `O(1)` |
| Додати на відрізку (різниці) | `O(1)` на оновлення | `O(n)` відновлення |
| Підмасив із сумою `k` | — | `O(n)` одним проходом |

Для мінливих даних: [Фенвік](../trees/fenwick-tree.md) і дерево відрізків — `O(log n)` на оновлення й запит.

## 9. Типові помилки

1. **Без нульового елемента `P[0] = 0`** — `l = 0` ламається.
2. **Плутанина меж:** з довжиною `n + 1` сума `[l, r]` це `P[r + 1] − P[l]`; з `n` — `P[r] − P[l − 1]` з окремою обробкою `l = 0`.
3. **Забути `seen[0] = 1`** — не враховуються підмасиви з початку масиву.
4. **Спочатку записати поточний префікс, потім запитувати:** для `k = 0` підмасив порівняється сам із собою; правильний порядок — спочатку запит, потім запис.
5. **Від'ємні залишки** в `subarraysDivByK`: `(-3) % 5 = -3` у JS; нормуйте `((x % k) + k) % k`.
6. **Переповнення сум** (в мовах із фіксованою розрядністю): `P` може вийти за `int`.
7. **Використання вікна замість префіксів** при від'ємних числах.
8. **Подвійний облік у 2D:** забути додати `S[i][j]` назад.
9. **Різницевий масив:** забути `D[r + 1]` при `r = n − 1` (потрібен розмір `n + 1`).
10. **Змінні дані:** префікси потрібно перебудовувати — використовуйте дерево Фенвіка.

## 10. Алгоритм (стисло)

1. `P[0] = 0`, `P[i + 1] = P[i] + a[i]`.
2. Сума `[l, r]` = `P[r + 1] − P[l]`.
3. Для підрахунку підмасивів із сумою `k` — хеш-таблиця частот префіксів, початково `{0: 1}`.
4. Для масових оновлень на відрізках — різницевий масив і єдине відновлення префіксними сумами.

42. У вікні рух `l` чи `r` має монотонно змінювати суму. З від'ємними числами додавання може її зменшити, а видалення — збільшити, тому немає правила, куди рухати вказівник. Префікси ж обчислюють точні суми для всіх відрізків, а хеш-таблиця знаходить потрібний початок за `O(1)`.
43. У масиві різниць `D[i] = a[i] − a[i − 1]` додавання `v` на `[l, r]` змінює тільки `D[l]` (+v) і `D[r + 1]` (−v); решта різниць не змінюється. Відновлення масиву — префіксні суми `D` за `O(n)` в кінці.
44. Воно представляє порожній префікс (суму 0 до першого елемента). Без нього підмасиви, що починаються з індексу 0 і мають суму `k`, не будуть знайдені: для них `P[i] − k = 0`, а такого запису в карті немає.
45. Сума `(j, i]` кратна `k`, якщо `(P[i] − P[j]) mod k = 0`, тобто `P[i] ≡ P[j] (mod k)`. Тому достатньо рахувати, скільки разів зустрічався кожен залишок: пара однакових залишків дає підмасив.
