# Two Pointers — техніка двох вказівників

Техніка двох вказівників замінює вкладені цикли `O(n²)` одним проходом `O(n)`: два індекси рухаються по масиву (або рядку) за чіткими правилами, і кожен рух **відкидає** щось, що вже не може бути відповіддю. Це не окремий алгоритм, а **шаблон мислення**, який лежить в основі десятків задач інтерв'ю — від `two sum` до `trapping rain water`.

## 1. Три основні схеми

1. **Назустріч** (opposite ends): `l = 0`, `r = n − 1`, рухаємось до центру. Для відсортованих масивів, паліндромів, максимізації «ширина × висота».
2. **В один бік** (same direction / читач і письменник): `read` проходить усе, `write` позначає, куди писати результат. Для видалення дублікатів, фільтрації «на місці».
3. **Швидкий і повільний** (fast / slow): вказівники з різною швидкістю — пошук середини зв'язного списку, виявлення циклу (див. [floyd-cycle-detection.md](floyd-cycle-detection.md)).

Є також **два вказівники по двох масивах** (злиття, перетин, підпослідовність).

## 2. Схема «назустріч»: сума двох у відсортованому масиві

Задача: у відсортованому масиві знайти пару з сумою `target`.

Ідея: `l` на найменшому, `r` на найбільшому. Нехай `s = a[l] + a[r]`.

- `s === target` — знайшли.
- `s < target` — `a[l]` з **будь-яким** елементом ліворуч від `r` дасть ще меншу суму (бо `a[r]` — найбільший з тих, що лишилися), тому `a[l]` не підходить ніколи → `l++`.
- `s > target` — аналогічно `a[r]` непридатний → `r--`.

**Доведення коректності (інваріант):** якщо відповідна пара існує, то її індекси лежать у `[l, r]`. Кожен крок відкидає один індекс, що **доведено** не входить у жодну розв'язну пару. Кроків не більше `n`, тож час `O(n)`, пам'ять `O(1)`. Замість `O(n²)` перебору всіх пар або `O(n log n)` з бінарним пошуком.

Приклад: `twoSumSorted([2, 7, 11, 15], 9)` = `[0, 1]`. Кроки для `[1, 3, 4, 6, 8, 11]` і `target = 10`:

- l=0, r=5: 1 + 11 = 12 → r--
- l=0, r=4: 1 + 8 = 9 → l++
- l=1, r=4: 3 + 8 = 11 → r--
- l=1, r=3: 3 + 6 = 9 → l++
- l=2, r=3: 4 + 6 = 10 → знайдено

## 3. Схема «назустріч»: геометричні задачі

**Контейнер із найбільшою водою (container with most water).** Лінії висот `h[i]`; площа між лініями `i` і `j` — `(j − i) · min(h[i], h[j])`. Починаємо з найширшого контейнера (`l = 0`, `r = n − 1`). Ширина лише зменшуватиметься, тож щоб покращити площу, треба збільшити **меншу** стіну. Тому рухаємо вказівник біля **меншої** лінії: переміщення більшої нічого не дасть (мінімум не зросте, а ширина зменшиться). `maxArea([1, 8, 6, 2, 5, 4, 8, 3, 7])` = `49`.

**Захоплена дощова вода (trapping rain water).** Вода над стовпчиком `i` дорівнює `min(maxLeft, maxRight) − h[i]`. Два вказівники з двома лічильниками максимумів: якщо `leftMax < rightMax`, вода в `l` визначається лише `leftMax` (праворуч є принаймні `rightMax` — вищий). `trap([0, 1, 0, 2, 1, 0, 1, 3, 2, 1, 2, 1])` = `6`.

**Паліндром:** `isPalindrome('A man, a plan, a canal: Panama')` = `true` (ігноруємо не-літери й регістр, пропускаючи їх вказівниками).

**Квадрати відсортованого масиву з від'ємними числами:** найбільші квадрати — на краях. `sortedSquares([-4, -1, 0, 3, 10])` = `[0, 1, 9, 16, 100]`: заповнюємо результат з кінця, порівнюючи `|a[l]|` і `|a[r]|`.

## 4. Схема «читач і письменник»

Вказівник `read` проходить усі елементи, `write` — позиція наступного **збереженого** елемента. Масив ліворуч від `write` — уже готовий результат.

- **Видалення дублікатів у відсортованому масиві:** `removeDuplicates([0, 0, 1, 1, 1, 2, 2, 3, 3, 4])` → довжина 5, унікальні значення `[0, 1, 2, 3, 4]`.
- **Переміщення нулів у кінець:** `moveZeroes([0, 1, 0, 3, 12])` = `[1, 3, 12, 0, 0]` — порядок ненульових збережено.
- **Видалення елемента на місці:** `removeElement([3, 2, 2, 3], 3)` → `2` (нова довжина).
- **Розбиття (partition)** у quicksort — те саме: `write` ділить «менші» і «решту», див. [quick-sort.md](../sorting/quick-sort.md).

Усе виконується **на місці** за `O(n)` і `O(1)`.

## 5. Три суми та вкладений вказівник

`threeSum` — знайти всі унікальні трійки з нульовою сумою. Сортуємо (`O(n log n)`), потім фіксуємо `i` і для решти шукаємо пару схемою «назустріч» (`O(n)`), пропускаючи дублікати. Разом `O(n²)` (замість `O(n³)`). `threeSum([-1, 0, 1, 2, -1, -4])` = `[[-1, -1, 2], [-1, 0, 1]]`.

Узагальнення: `k`-sum — `O(n^{k−1})`; `4Sum` — два вкладені цикли + пара вказівників.

## 6. Два вказівники по двох масивах

- **Злиття двох відсортованих масивів:** `merge([1, 4, 7], [2, 3, 9])` = `[1, 2, 3, 4, 7, 9]` — основа [merge sort](../sorting/merge-sort.md).
- **Перетин відсортованих масивів:** `intersectSorted([1, 2, 2, 3, 5], [2, 2, 4, 5])` = `[2, 2, 5]`.
- **Підпослідовність:** `isSubsequence('ace', 'abcde')` = `true`, `isSubsequence('aec', 'abcde')` = `false` — жадібно рухаємо вказівник по довгому рядку.

## 7. Реалізація

```js
function twoSumSorted(a, target) {
  let l = 0;
  let r = a.length - 1;
  while (l < r) {
    const s = a[l] + a[r];
    if (s === target) return [l, r];
    if (s < target) l++;
    else r--;
  }
  return null;
}

function twoSumTrace(a, target) {
  const out = [];
  let l = 0;
  let r = a.length - 1;
  while (l < r) {
    const s = a[l] + a[r];
    const act = s === target ? 'знайдено' : s < target ? 'l++' : 'r--';
    out.push('l=' + l + ', r=' + r + ': ' + a[l] + ' + ' + a[r] + ' = ' + s + ' → ' + act);
    if (s === target) break;
    if (s < target) l++;
    else r--;
  }
  return out;
}

function maxArea(h) {
  let l = 0;
  let r = h.length - 1;
  let best = 0;
  while (l < r) {
    best = Math.max(best, (r - l) * Math.min(h[l], h[r]));
    if (h[l] < h[r]) l++;
    else r--;
  }
  return best;
}

function trap(h) {
  let l = 0;
  let r = h.length - 1;
  let leftMax = 0;
  let rightMax = 0;
  let water = 0;
  while (l < r) {
    if (h[l] < h[r]) {
      if (h[l] >= leftMax) leftMax = h[l];
      else water += leftMax - h[l];
      l++;
    } else {
      if (h[r] >= rightMax) rightMax = h[r];
      else water += rightMax - h[r];
      r--;
    }
  }
  return water;
}

function isPalindrome(s) {
  let l = 0;
  let r = s.length - 1;
  const isAlnum = (c) => /[a-z0-9]/i.test(c);
  while (l < r) {
    while (l < r && !isAlnum(s[l])) l++;
    while (l < r && !isAlnum(s[r])) r--;
    if (s[l].toLowerCase() !== s[r].toLowerCase()) return false;
    l++;
    r--;
  }
  return true;
}

function sortedSquares(a) {
  const out = new Array(a.length);
  let l = 0;
  let r = a.length - 1;
  for (let i = a.length - 1; i >= 0; i--) {
    if (Math.abs(a[l]) > Math.abs(a[r])) { out[i] = a[l] * a[l]; l++; }
    else { out[i] = a[r] * a[r]; r--; }
  }
  return out;
}

function removeDuplicates(input) {
  const a = input.slice();
  if (a.length === 0) return { length: 0, values: [] };
  let w = 1;
  for (let rd = 1; rd < a.length; rd++) {
    if (a[rd] !== a[w - 1]) a[w++] = a[rd];
  }
  return { length: w, values: a.slice(0, w) };
}

function moveZeroes(input) {
  const a = input.slice();
  let w = 0;
  for (let rd = 0; rd < a.length; rd++) {
    if (a[rd] !== 0) { [a[w], a[rd]] = [a[rd], a[w]]; w++; }
  }
  return a;
}

function removeElement(input, val) {
  const a = input.slice();
  let w = 0;
  for (let rd = 0; rd < a.length; rd++) if (a[rd] !== val) a[w++] = a[rd];
  return w;
}

function threeSum(input) {
  const a = input.slice().sort((x, y) => x - y);
  const out = [];
  for (let i = 0; i < a.length - 2; i++) {
    if (i > 0 && a[i] === a[i - 1]) continue;
    let l = i + 1;
    let r = a.length - 1;
    while (l < r) {
      const s = a[i] + a[l] + a[r];
      if (s === 0) {
        out.push([a[i], a[l], a[r]]);
        l++;
        r--;
        while (l < r && a[l] === a[l - 1]) l++;
        while (l < r && a[r] === a[r + 1]) r--;
      } else if (s < 0) l++;
      else r--;
    }
  }
  return out;
}

function merge(a, b) {
  const out = [];
  let i = 0;
  let j = 0;
  while (i < a.length && j < b.length) out.push(a[i] <= b[j] ? a[i++] : b[j++]);
  while (i < a.length) out.push(a[i++]);
  while (j < b.length) out.push(b[j++]);
  return out;
}

function intersectSorted(a, b) {
  const out = [];
  let i = 0;
  let j = 0;
  while (i < a.length && j < b.length) {
    if (a[i] === b[j]) { out.push(a[i]); i++; j++; }
    else if (a[i] < b[j]) i++;
    else j++;
  }
  return out;
}

function isSubsequence(s, t) {
  let i = 0;
  for (let j = 0; j < t.length && i < s.length; j++) if (s[i] === t[j]) i++;
  return i === s.length;
}

function reverseInPlace(input) {
  const a = input.slice();
  let l = 0;
  let r = a.length - 1;
  while (l < r) { [a[l], a[r]] = [a[r], a[l]]; l++; r--; }
  return a;
}
```

## 8. Складність і чому це швидко

Кожен вказівник рухається в **одному** напрямку і ніколи не повертається, тож сумарна кількість рухів `≤ n` (для назустріч — `≤ n`, для читач/письменник — `2n`). Звідси `O(n)` часу й `O(1)` пам'яті (не рахуючи результату). Якщо потрібне попереднє сортування — домінує `O(n log n)` (`threeSum`: `O(n²)` через зовнішній цикл).

**Коли техніка працює:** є **монотонність** — рух вказівника гарантовано не втрачає відповідь. Для відсортованих даних вона випливає з порядку; для `maxArea` — з аргументу про меншу стіну.

**Коли не працює:** невідсортований масив із від'ємними числами та пошуком суми підмасиву (там потрібні префіксні суми й хеш-таблиця: [prefix-sums.md](prefix-sums.md)); задачі, де рух вказівника може втратити розв'язок.

Споріднена техніка — [ковзне вікно](sliding-window.md), де вказівники `l` і `r` задають неперервний відрізок.

## 9. Типові помилки

1. **Умова `l <= r` замість `l < r`** у задачах про пари: елемент береться двічі (`target = 8`, `a = [4]` дасть `4 + 4`).
2. **Забути відсортувати** перед `twoSumSorted` — алгоритм мовчки повертає хибний результат.
3. **Не пропустити дублікати** у `threeSum` → повтор трійок.
4. **Рух не того вказівника** у `maxArea` (треба меншої стіни).
5. **Забути перевірку `l < r` у внутрішніх циклах** `isPalindrome`: індекси перетинаються, `undefined.toLowerCase()`.
6. **Обмін у `moveZeroes` при `w === rd`** — безпечний, але зайвий; обережно з порядком для не-нулів (потрібен стабільний прохід).
7. **Повернення довжини без обрізання масиву** в `removeDuplicates`: «хвіст» містить сміття.
8. **Переповнення індексів/цілочисельних сум** у мовах із фіксованою розрядністю (в JS — не проблема до `2⁵³`).
9. **Плутанина «індекси» чи «значення»:** `twoSum` на відсортованому масиві втрачає початкові індекси; якщо потрібні вихідні — спершу запам'ятати пари `(значення, індекс)`.

## 10. Алгоритм-шаблон

1. Визначити, що відкидається при кожному русі (обґрунтувати монотонністю).
2. Ініціалізувати `l`, `r` (краї або обидва на початку).
3. Цикл `while (l < r)`: обчислити стан, прийняти рішення, **гарантовано** посунути хоч один вказівник.
4. Повернути результат; час `O(n)`, пам'ять `O(1)`.

33. Приклад розв'язку:

   ```js
   function twoSumIndices(a, target) {
     const p = a.map((v, i) => [v, i]).sort((x, y) => x[0] - y[0]);
     let l = 0, r = p.length - 1;
     while (l < r) {
       const s = p[l][0] + p[r][0];
       if (s === target) return [p[l][1], p[r][1]].sort((x, y) => x - y);
       if (s < target) l++;
       else r--;
     }
     return null;
   }
   ```

   Виклик `[twoSumIndices([3, 2, 4], 6), twoSumIndices([2, 7, 11, 15], 9), twoSumIndices([1, 2], 10)]` → `[[1, 2], [0, 1], null]`

34. Приклад розв'язку:

   ```js
   function threeSumClosest(input, target) {
     const a = input.slice().sort((x, y) => x - y);
     let best = a[0] + a[1] + a[2];
     for (let i = 0; i < a.length - 2; i++) {
       let l = i + 1, r = a.length - 1;
       while (l < r) {
         const s = a[i] + a[l] + a[r];
         if (Math.abs(s - target) < Math.abs(best - target)) best = s;
         if (s < target) l++;
         else if (s > target) r--;
         else return s;
       }
     }
     return best;
   }
   ```

   Виклик `[threeSumClosest([-1, 2, 1, -4], 1), threeSumClosest([0, 0, 0], 1)]` → `[2, 0]`

35. Приклад розв'язку:

   ```js
   function countPairsLessThan(a, target) {
     let l = 0, r = a.length - 1, c = 0;
     while (l < r) {
       if (a[l] + a[r] < target) {
         c += r - l;
         l++;
       } else r--;
     }
     return c;
   }
   ```

   Виклик `[countPairsLessThan([1, 2, 3, 4, 5], 7), countPairsLessThan([1, 2], 100), countPairsLessThan([5, 6], 3)]` → `[6, 1, 0]`

36. Приклад розв'язку:

   ```js
   function validPalindromeII(s) {
     const ok = (l, r) => {
       while (l < r) {
         if (s[l] !== s[r]) return false;
         l++;
         r--;
       }
       return true;
     };
     let l = 0, r = s.length - 1;
     while (l < r) {
       if (s[l] !== s[r]) return ok(l + 1, r) || ok(l, r - 1);
       l++;
       r--;
     }
     return true;
   }
   ```

   Виклик `[validPalindromeII('aba'), validPalindromeII('abca'), validPalindromeII('abc')]` → `[true, true, false]`

37. Приклад розв'язку:

   ```js
   function mergeSortedInPlace(a, m, b, n) {
     let i = m - 1, j = n - 1, k = m + n - 1;
     while (j >= 0) a[k--] = i >= 0 && a[i] > b[j] ? a[i--] : b[j--];
     return a;
   }
   ```

   Виклик `mergeSortedInPlace([1, 2, 3, 0, 0, 0], 3, [2, 5, 6], 3)` → `[1, 2, 2, 3, 5, 6]`

   ```js
   function rotateArray(input, k) {
     const a = input.slice();
     const rev = (l, r) => {
       while (l < r) {
         [a[l], a[r]] = [a[r], a[l]];
         l++;
         r--;
       }
     };
     k %= a.length || 1;
     rev(0, a.length - 1);
     rev(0, k - 1);
     rev(k, a.length - 1);
     return a;
   }
   ```

41. Приклад розв'язку:

   ```js
   function longestMountain(a) {
     let best = 0, i = 1;
     while (i < a.length - 1) {
       if (a[i - 1] < a[i] && a[i] > a[i + 1]) {
         let l = i - 1, r = i + 1;
         while (l > 0 && a[l - 1] < a[l]) l--;
         while (r < a.length - 1 && a[r] > a[r + 1]) r++;
         best = Math.max(best, r - l + 1);
         i = r;
       } else i++;
     }
     return best;
   }
   ```

42. `a[r]` — найбільший елемент серед тих, що лишилися. Якщо навіть з ним сума менша за `target`, то з будь-яким меншим парним елементом вона буде ще меншою, тому `a[l]` не може входити в жодну розв'язну пару, і його можна виключити.
43. Площа обмежена меншою стіною. Якщо зрушити вищу, ширина зменшиться, а мінімум висоти не зросте — площа не може збільшитись. Зрушивши меншу стіну, ми маємо шанс знайти вищу й збільшити площу, тому всі контейнери з цією меншою стіною вже розглянуто й відкинуто.
44. У схемі «назустріч» вказівники починають із різних кінців і зближуються, відкидаючи кандидатів; у схемі «читач/письменник» обидва йдуть в один бік: `read` обходить усе, а `write` формує результат на місці.
