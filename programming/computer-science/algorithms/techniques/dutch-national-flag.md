# Dutch National Flag — тристороннє розбиття

Задача Дейкстри «голландський прапор»: масив містить три види значень («червоні», «білі», «сині» — наприклад, `0`, `1`, `2`); треба впорядкувати їх так, щоб однакові опинилися поруч, **за один прохід** і **на місці** (`O(n)` часу, `O(1)` пам'яті). Це не просто головоломка: **тристороннє розбиття** — серцевина quicksort на масивах із багатьма дублікатами та quickselect.

## 1. Задача

Дано `[2, 0, 2, 1, 1, 0]`. Результат: `[0, 0, 1, 1, 2, 2]`.

Підходи:

- **Сортування:** `O(n log n)` — надлишково.
- **Підрахунок (counting sort):** порахувати `0`, `1`, `2` і переписати масив: два проходи, `O(n)`, але читає масив двічі й не годиться, якщо елементи — **об'єкти** (їх треба переставляти, а не відновлювати за лічильниками).
- **Три вказівники:** один прохід, обміни на місці — алгоритм Дейкстри.

## 2. Три вказівники і чотири зони

Тримаємо індекси `lo`, `mid`, `hi` і ділимо масив на чотири зони:

```text
[ 0 0 0 | 1 1 1 | ? ? ? ? | 2 2 2 ]
  0..lo-1  lo..mid-1  mid..hi  hi+1..n-1
  (нулі)   (одиниці) (невідоме) (двійки)
```

**Інваріант:** `a[0..lo-1]` — усі `0`; `a[lo..mid-1]` — усі `1`; `a[mid..hi]` — ще не розглянуті; `a[hi+1..n-1]` — усі `2`.

Дивимось на `a[mid]`:

- `0` → обмінюємо з `a[lo]`, `lo++`, `mid++` (зона «нулі» росте, елемент з `a[lo]` був `1`, тож `mid` рухається далі).
- `1` → `mid++` (він уже на місці).
- `2` → обмінюємо з `a[hi]`, `hi--`. **`mid` не рухаємо:** елемент, що прийшов з `hi`, ще невідомий і його треба перевірити.

Цикл `while (mid <= hi)`. Кожен крок або збільшує `mid`, або зменшує `hi` — зона невідомих скорочується на 1, тому не більше `n` ітерацій.

Трасування для `[2, 0, 2, 1, 1, 0]`:

- lo=0 mid=0 hi=5 [2 0 2 1 1 0] a[mid]=2
- lo=0 mid=0 hi=4 [0 0 2 1 1 2] a[mid]=0
- lo=1 mid=1 hi=4 [0 0 2 1 1 2] a[mid]=0
- lo=2 mid=2 hi=4 [0 0 2 1 1 2] a[mid]=2
- lo=2 mid=2 hi=3 [0 0 1 1 2 2] a[mid]=1
- lo=2 mid=3 hi=3 [0 0 1 1 2 2] a[mid]=1
- результат [0 0 1 1 2 2]

## 3. Чому не рухаємо `mid` після обміну з `hi`

Елемент, який ми віддали вправо, — `2`, і це правильно. А от те, що прийшло з позиції `hi`, ми **ще не бачили** — це може бути `0`, `1` або `2`. Якщо `mid++`, ми пропустимо його перевірку. А після обміну з `lo` (випадок `0`) на `a[mid]` опиняється значення з `a[lo]`, а воно **вже перевірене** (з зони `1`, або дорівнює самому `mid`), тому `mid++` безпечний.

## 4. Реалізація

```js
function sortColors(input) {
  const a = input.slice();
  let lo = 0;
  let mid = 0;
  let hi = a.length - 1;
  while (mid <= hi) {
    if (a[mid] === 0) {
      [a[lo], a[mid]] = [a[mid], a[lo]];
      lo++;
      mid++;
    } else if (a[mid] === 1) {
      mid++;
    } else {
      [a[mid], a[hi]] = [a[hi], a[mid]];
      hi--;
    }
  }
  return a;
}

function dutchTrace(input) {
  const a = input.slice();
  let lo = 0;
  let mid = 0;
  let hi = a.length - 1;
  const out = [];
  while (mid <= hi) {
    const before = 'lo=' + lo + ' mid=' + mid + ' hi=' + hi + ' [' + a.join(' ') + '] a[mid]=' + a[mid];
    if (a[mid] === 0) {
      [a[lo], a[mid]] = [a[mid], a[lo]];
      lo++;
      mid++;
    } else if (a[mid] === 1) {
      mid++;
    } else {
      [a[mid], a[hi]] = [a[hi], a[mid]];
      hi--;
    }
    out.push(before);
  }
  out.push('результат [' + a.join(' ') + ']');
  return out;
}

function threeWayPartition(input, pivot) {
  const a = input.slice();
  let lt = 0;
  let i = 0;
  let gt = a.length - 1;
  while (i <= gt) {
    if (a[i] < pivot) {
      [a[lt], a[i]] = [a[i], a[lt]];
      lt++;
      i++;
    } else if (a[i] > pivot) {
      [a[gt], a[i]] = [a[i], a[gt]];
      gt--;
    } else {
      i++;
    }
  }
  return { a, lt, gt };
}

function quickSort3(input) {
  const a = input.slice();
  const go = (lo, hi) => {
    if (lo >= hi) return;
    const p = a[lo + ((hi - lo) >> 1)];
    let lt = lo;
    let i = lo;
    let gt = hi;
    while (i <= gt) {
      if (a[i] < p) { [a[lt], a[i]] = [a[i], a[lt]]; lt++; i++; }
      else if (a[i] > p) { [a[gt], a[i]] = [a[i], a[gt]]; gt--; }
      else i++;
    }
    go(lo, lt - 1);
    go(gt + 1, hi);
  };
  go(0, a.length - 1);
  return a;
}

function sortColorsCounting(a) {
  const c = [0, 0, 0];
  for (const x of a) c[x]++;
  return [...Array(c[0]).fill(0), ...Array(c[1]).fill(1), ...Array(c[2]).fill(2)];
}

function partitionEvenOdd(input) {
  const a = input.slice();
  let l = 0;
  let r = a.length - 1;
  while (l < r) {
    if (a[l] % 2 === 0) l++;
    else if (a[r] % 2 === 1) r--;
    else { [a[l], a[r]] = [a[r], a[l]]; l++; r--; }
  }
  return a;
}

function swapCounter(input) {
  const a = input.slice();
  let swaps = 0;
  let lo = 0;
  let mid = 0;
  let hi = a.length - 1;
  while (mid <= hi) {
    if (a[mid] === 0) { [a[lo], a[mid]] = [a[mid], a[lo]]; swaps++; lo++; mid++; }
    else if (a[mid] === 1) mid++;
    else { [a[mid], a[hi]] = [a[hi], a[mid]]; swaps++; hi--; }
  }
  return swaps;
}
```

Приклади: `sortColors([2, 0, 2, 1, 1, 0])` = `[0, 0, 1, 1, 2, 2]`; `threeWayPartition([4, 9, 4, 1, 4, 7, 2], 4)` = `{ a: [2, 1, 4, 4, 4, 7, 9], lt: 2, gt: 4 }`: ліворуч від `lt` — менші, від `lt` до `gt` — рівні `4`, праворуч — більші.

## 5. Тристороннє розбиття та quicksort

Класичний quicksort (Ломуто/Хоара) на масиві з однаковими елементами виродиться в `O(n²)`: усі елементи падають в одну частину. **Тристороннє розбиття** групує елементи, рівні опорному, у центрі й **виключає їх** з рекурсії:

`go(lo, lt − 1)` та `go(gt + 1, hi)`. Якщо в масиві лише `k` різних значень, рекурсія завершиться за `O(n·k)` (для `k = 1` — `O(n)`). Тому `quickSort3` для `[3, 1, 3, 2, 1, 3, 3]` → `[1, 1, 2, 3, 3, 3, 3]`. Див. [quick-sort.md](../sorting/quick-sort.md) та [quickselect.md](../searching/quickselect.md).

Узагальнення: **розбиття на `k` груп** вимагає `k − 1` меж і складніше; для `k > 3` зазвичай використовують [counting sort](../sorting/counting-sort.md).

## 6. Складність

- **Час `O(n)`**: кожен елемент обробляється не більше ніж двічі (елемент з `hi`, що став відомим, переглядається один раз).
- **Пам'ять `O(1)`.**
- **Кількість обмінів:** не більше `n`; для `[2, 0, 2, 1, 1, 0]` — 4.
- **Нестабільне:** обміни змінюють відносний порядок рівних елементів. Якщо потрібна стабільність — підрахунок із префіксними сумами або три списки (`O(n)` додаткової пам'яті).

## 7. Споріднені задачі

- **Парні/непарні:** `partitionEvenOdd([3, 1, 2, 4, 5, 6])` = `[6, 4, 2, 1, 5, 3]` (двосторонній варіант — два вказівники).
- **Нулі в кінець** ([two-pointers.md](two-pointers.md)).
- **Розбиття навколо опорного** — перший крок quickselect.
- **Сортування «за ключем із трьох значень»:** оцінки `низька/середня/висока`, статуси `new/active/done`.
- **Масив 0 і 1:** два вказівники; **0, 1, 2:** Дейкстра; **0…k:** підрахунок.

## 8. Типові помилки

1. **Рухати `mid` після обміну з `hi`** — елемент, що прийшов справа, не буде перевірений.
2. **Не рухати `mid` після обміну з `lo`** — або навпаки: пам'ятати, що `a[lo]` уже перевірене.
3. **Умова `mid < hi` замість `mid <= hi`** — останній невідомий елемент залишається необробленим.
4. **Порядок зон:** переплутати, з якого боку «нулі», а з якого «двійки».
5. **Очікувати стабільності.**
6. **Рекурсивний quicksort із двостороннім розбиттям на дублікатах** — `O(n²)` і переповнення стека.
7. **Забути, що значення, рівні опорному, у `threeWayPartition` — від `lt` до `gt` включно.**
8. **Порожній масив:** `hi = −1`, цикл не виконується — коректно, але перевірте в обгортках.

## 9. Алгоритм (стисло)

1. `lo = 0`, `mid = 0`, `hi = n − 1`.
2. Поки `mid ≤ hi`: `0` — обмін з `lo`, `lo++`, `mid++`; `1` — `mid++`; `2` — обмін з `hi`, `hi−−`.
3. Результат: `[0…0, 1…1, 2…2]`. Час `O(n)`, пам'ять `O(1)`.

           i++;

37. `[0, lo)` — нулі; `[lo, mid)` — одиниці; `[mid, hi]` — ще не розглянуті; `(hi, n)` — двійки. Кожна ітерація зменшує невідому зону на один елемент.
38. Елемент, що прийшов із позиції `hi`, ще не був перевірений: це може бути `0`, `1` або `2`. Якщо зсунути `mid`, він залишиться в зоні невідомих «позаду» вказівника й не буде оброблений.
39. Елемент, що прийшов з `a[lo]`, уже перевірений: це значення з зони одиниць (або сам `a[mid]`, якщо `lo = mid`). Тож він на правильному місці, і `mid` просувається разом із `lo`.
40. Усі елементи, рівні опорному, групуються в центрі й не потрапляють у рекурсію. Для масивів із багатьма дублікатами це зводить час до `O(n·k)` (де `k` — кількість різних значень) і запобігає виродженню в `O(n²)`.
41. Він працює на місці з одним проходом і переставляє самі елементи, тож годиться для об'єктів із ключем із трьох значень; підрахунок відновлює масив за лічильниками і для об'єктів не підходить (втрачаються самі об'єкти).
42. Ні: обміни переносять елементи через рівні. Стабільний варіант — три списки (за значеннями) та склеювання, `O(n)` додаткової пам'яті, або стабільний підрахунок із префіксними сумами.
43. Кожна ітерація зменшує розмір невідомої зони `[mid, hi]` на 1 (або `mid++`, або `hi--`), тому ітерацій не більше `n`; обмін коштує `O(1)`. Загальний час `O(n)`, пам'ять `O(1)`.
44. Для малого `k` — counting sort або розбиття послідовно (`k − 1` проходів); для рівномірного розбиття на довільне `k` — радикс/підрахунок. Одним проходом із `O(1)` пам'яті розбити на `k > 3` груп із довільними значеннями загалом неможливо без додаткових структур.
45. Тристороннє розбиття прибирає проблему дублікатів, але для різних значень поганий опорний (мінімум/максимум) усе ще дає розбиття `1 : n − 1` і `O(n²)`. Тому беруть випадковий або медіану з трьох.
