# Boyer–Moore Majority Vote — алгоритм більшості

Елемент **більшості** (majority element) у масиві з `n` елементів — це значення, що зустрічається **більш ніж `n/2` разів**. Алгоритм Бойєра–Мура знаходить кандидата за **один прохід**, `O(n)` часу й `O(1)` пам'яті — без сортування й хеш-таблиці. Його ще називають «голосуванням» (Boyer–Moore voting) через образ виборів.

## 1. Задача і наївні підходи

Дано `[2, 2, 1, 1, 1, 2, 2]`. Елемент `2` зустрічається 4 рази з 7 — більше половини.

- **Хеш-таблиця:** порахувати частоти — `O(n)` часу, `O(n)` пам'яті.
- **Сортування:** елемент більшості стоїть посередині відсортованого масиву (`a[⌊n/2⌋]`) — `O(n log n)`.
- **Quickselect:** медіана і є кандидатом — `O(n)` у середньому (див. [quickselect.md](../searching/quickselect.md)).
- **Boyer–Moore:** `O(n)` часу і `O(1)` пам'яті — найкращий варіант.

## 2. Ідея: взаємне знищення

Уявіть, що елементи — виборці різних кандидатів. Візьмемо **пару різних** виборців і «вилучимо» їх із розгляду. Якщо кандидат має **строгу більшість**, то він не може бути повністю знищений: кожна вилучена пара містить щонайбільше одного його виборця, а виборців більшості більше за половину. Після вилучення всіх можливих різних пар **залишаться тільки голоси одного й того самого кандидата** — і це буде він.

Алгоритм реалізує це лічильником:

1. `candidate` — поточний претендент, `count` — «запас» його голосів.
2. Якщо `count === 0` — призначити новим кандидатом поточний елемент.
3. Якщо елемент збігається з кандидатом — `count++`; інакше — `count--` (пара «різних» знищує один голос).

Для `[2, 2, 1, 1, 1, 2, 2]`:

| Елемент | Кандидат | `count` |
|---|---|---|
| 2 | 2 | 1 |
| 2 | 2 | 2 |
| 1 | 2 | 1 |
| 1 | 2 | 0 |
| 1 | 1 | 1 |
| 2 | 1 | 0 |
| 2 | 2 | 1 |

Кінцевий кандидат — `2`.

## 3. Доведення

**Твердження.** Якщо в масиві є елемент більшості, то після проходу `candidate` дорівнює йому.

**Доказ.** Розіб'ємо масив на послідовні **блоки**: блок закінчується на моменті, коли `count` стає `0`. Усередині такого блоку кандидат (той, що був на початку) мав рівно стільки ж елементів, скільки «інших» — кожному «іншому» відповідає знищений голос, — тобто в кожному завершеному блоку **рівно половина** елементів належить кандидату блоку. Отже, жоден завершений блок не може дати елементу більшості більше за половину свого розміру. Тому весь «внесок» більшості має бути в **незавершеному** хвості (де `count > 0`), де вона має строгу перевагу, — і кандидат хвоста, що лишився, дорівнює елементу більшості. ∎

**Важливо:** алгоритм дає **кандидата**, а не гарантію існування більшості. Для `[1, 2, 3]` більшості немає, але повернеться `3`. Тому другий прохід — **перевірка**: порахувати, чи кандидат справді зустрічається `> n/2` разів (`majorityElement`).

## 4. Узагальнення: елементи, що зустрічаються понад `n/k` разів

Для `n/3` може бути не більше **двох** таких елементів (три по `> n/3` не вмістяться). Тримаємо **два** кандидати з двома лічильниками: новий елемент збігається з одним — `++`; обидва лічильники ненульові й елемент інший — зменшуємо обидва (знищуємо **трійку** різних); якщо є вільний слот — займаємо. Загалом для `n/k` потрібно `k − 1` кандидатів — **алгоритм Місра–Гріса** (Misra–Gries heavy hitters), `O(n·k)` часу й `O(k)` пам'яті. Він лежить в основі потокових алгоритмів пошуку «гарячих» елементів у трафіку.

`majorityNOverThree([3, 2, 3])` = `[3]`, `majorityNOverThree([1, 1, 1, 3, 3, 2, 2, 2])` = `[1, 2]`.

## 5. Реалізація

```js
function majorityCandidate(a) {
  let cand = null;
  let count = 0;
  for (const x of a) {
    if (count === 0) cand = x;
    count += x === cand ? 1 : -1;
  }
  return cand;
}

function majorityTrace(a) {
  const out = [];
  let cand = null;
  let count = 0;
  for (const x of a) {
    if (count === 0) cand = x;
    count += x === cand ? 1 : -1;
    out.push({ x, cand, count });
  }
  return out;
}

function majorityElement(a) {
  const c = majorityCandidate(a);
  let n = 0;
  for (const x of a) if (x === c) n++;
  return n * 2 > a.length ? c : null;
}

function majorityNOverThree(a) {
  let c1 = null;
  let c2 = null;
  let n1 = 0;
  let n2 = 0;
  for (const x of a) {
    if (x === c1) n1++;
    else if (x === c2) n2++;
    else if (n1 === 0) { c1 = x; n1 = 1; }
    else if (n2 === 0) { c2 = x; n2 = 1; }
    else { n1--; n2--; }
  }
  const res = [];
  for (const c of [c1, c2]) {
    if (c === null) continue;
    let n = 0;
    for (const x of a) if (x === c) n++;
    if (n * 3 > a.length && !res.includes(c)) res.push(c);
  }
  return res.sort((p, q) => p - q);
}

function misraGries(a, k) {
  const counters = new Map();
  for (const x of a) {
    if (counters.has(x)) counters.set(x, counters.get(x) + 1);
    else if (counters.size < k - 1) counters.set(x, 1);
    else {
      for (const [key, v] of counters) {
        if (v === 1) counters.delete(key);
        else counters.set(key, v - 1);
      }
    }
  }
  return [...counters.keys()];
}

function majorityByHash(a) {
  const m = new Map();
  for (const x of a) m.set(x, (m.get(x) || 0) + 1);
  for (const [k, v] of m) if (v * 2 > a.length) return k;
  return null;
}

function majorityBySort(a) {
  const s = a.slice().sort((p, q) => p - q);
  const c = s[s.length >> 1];
  return s.filter((x) => x === c).length * 2 > s.length ? c : null;
}
```

Приклади: `majorityElement([3, 2, 3])` = `3`, `majorityElement([1, 2, 3])` = `null`, але **кандидат** для `[1, 2, 3]` — `3`.

## 6. Складність

- **Час `O(n)`** — один прохід для кандидата + один для перевірки (`2n`).
- **Пам'ять `O(1)`** — дві змінні (`O(k)` для узагальнення).
- **Нижня межа часу** для детермінованого пошуку більшості лише порівняннями рівності — `⌈3n/2⌉ − 2` порівнянь (Фішер–Салзберг); Boyer–Moore використовує близько `2n`.

## 7. Застосування

- **Моніторинг потоків:** «найактивніші IP» у мережевому трафіку (heavy hitters) із малою пам'яттю.
- **Консенсус, голосування** у розподілених системах — перевірка більшості реплік.
- **Підготовчий крок** для задач типу «елемент, що займає понад половину місць».
- Ідея «взаємного знищення різних пар» зустрічається в задачах про парні дужки, видалення пар сусідніх, «зоряні війни»-симуляціях.

## 8. Типові помилки

1. **Не перевіряти кандидата**, коли більшість не гарантована — результат хибний.
2. **Порівняння `count > 0` замість `count === 0`** при виборі кандидата — зсув логіки.
3. **Скинути `count` у `0` замість зменшення**, ламає доведення.
4. **Для `n/3`:** використовувати один кандидат або не перевіряти обох у другому проході.
5. **Рівні кандидати в `n/3`:** не прибрати дублікат (`c1 === c2` на початку при `null`).
6. **Понад або не менше:** `> n/2`, а не `>= n/2` (для парного `n` пара по `n/2` — не більшість).
7. **Об'єкти/NaN:** `NaN !== NaN` — лічильник не збігається з самим собою.
8. **Вхід порожній:** `majorityElement([])` має повертати `null`.

## 9. Алгоритм (стисло)

1. `candidate = null`, `count = 0`.
2. Для кожного `x`: якщо `count = 0` — `candidate = x`; `count += (x = candidate) ? 1 : −1`.
3. Другий прохід — перевірити, що `candidate` зустрічається `> n/2` разів.
4. Час `O(n)`, пам'ять `O(1)`.

   Виклик `[findMajorityOver([1, 1, 1, 2, 2, 3, 3, 4], 3), findMajorityOver([1, 2, 3, 4], 2)]` → `[[1], []]`

   ```js
     const m = new Map();
     for (const x of a) m.set(x, (m.get(x) || 0) + 1);

     return Math.max(0, Math.floor(a.length / 2) + 1 - f);
   }
   ```

34. Приклад розв'язку:

   ```js
   function streamingMajority(s) {
     let c = null, n = 0;
     const out = [];
     for (const x of s) {
       if (n === 0) c = x;
       n += x === c ? 1 : -1;
       out.push(c);
     }
     return out;
   }
   ```

35. Приклад розв'язку:

   ```js
   function majorityByBits(a) {
     let r = 0;
     for (let b = 0; b < 31; b++) {
       let ones = 0;
       for (const x of a) if ((x >> b) & 1) ones++;
       if (ones * 2 > a.length) r |= 1 << b;
     }
     return r;
   }
   ```

36. Кожна знищена пара містить щонайбільше один елемент більшості, а їх більше за половину. Якщо з масиву послідовно прибрати всі пари різних значень, то елементів більшості в парах знищується не більше, ніж інших, тож хоча б один його голос лишається — і лишитися може тільки він.
37. Алгоритм завжди повертає «останнього кандидата», навіть коли жоден елемент не зустрічається понад половину (наприклад, `[1, 2, 3]` дає 3). Лише перерахунок частоти підтверджує, що кандидат — справжня більшість.
38. Не більше двох: якщо три різні значення мали б частоту `> n/3`, їхня сума перевищила б `n`. Для `n/k` — не більше `k − 1`.
39. Це узагальнення: тримає `k − 1` кандидатів з лічильниками й при зустрічі «нового» елемента без вільних слотів зменшує всі лічильники (знищує `k` різних). Boyer–Moore — випадок `k = 2` з одним кандидатом.
40. Так: кандидат — елемент у середині `a[⌊n/2⌋]`, а його справжність перевіряють двома бінарними пошуками меж блоку (`lowerBound`/`upperBound`) за `O(log n)`.
41. Коли потрібні точні частоти всіх елементів, а не лише більшість, коли пам'ять не обмежена або коли треба відповідати на багато запитів по одному набору даних. Boyer–Moore виграє там, де потрібна `O(1)` пам'ять і один прохід по потоку.
42. Порівняння `x === cand` порівнює посилання, тому різні об'єкти з однаковим вмістом вважатимуться різними. Потрібен ключ-нормалізація (`JSON.stringify`, id) або власний компаратор рівності.
43. Йому достатньо пам'ятати кандидата й лічильник; кожен елемент обробляється один раз, без повернення. Це дозволяє читати дані з диска чи мережі й не зберігати їх.
