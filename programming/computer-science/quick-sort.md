# Quick Sort — швидке сортування

Усі виводи — реальним запуском (Node 24), реалізація перевірена на 300 випадкових масивах.

## 1. Ідея: розділяй і володарюй (через опорний елемент)

1. Обери **опорний елемент (pivot)**.
2. **Розбий (partition)** масив так, щоб усе **менше** за pivot було лівіше, усе **більше або рівне** — правіше. Pivot після цього стоїть на **своєму остаточному місці**.
3. Рекурсивно відсортуй ліву і праву частини (pivot не чіпаємо).

На відміну від merge sort, вся робота — у **розбитті** (до рекурсії); «злиття» не потрібне. Сортування **на місці** (in-place).

## 2. Приклад: `[5, 2, 9, 1, 5, 6]` (pivot = останній елемент)

Реальний вивід (після кожного розбиття):

| Розбиття | Масив | Позиція pivot |
|---|---|---|
| pivot `6` | `5 2 1 5 6 9` | 4 |
| pivot `5` (ліва частина) | `2 1 5 5 6 9` | 2 |
| pivot `1` | `1 2 5 5 6 9` | 0 |

Разом **9 порівнянь, 9 обмінів, глибина рекурсії 4**.

## 3. Реалізація (схема Lomuto, pivot — останній)

```js
function quickSort(a, lo = 0, hi = a.length - 1) {
  if (lo >= hi) return a;                       // база: 0–1 елемент
  const p = partition(a, lo, hi);
  quickSort(a, lo, p - 1);                      // ліва частина
  quickSort(a, p + 1, hi);                      // права частина
  return a;
}

function partition(a, lo, hi) {
  const pivot = a[hi];
  let i = lo;                                   // межа «менших за pivot»
  for (let j = lo; j < hi; j++) {
    if (a[j] < pivot) {
      [a[i], a[j]] = [a[j], a[i]];
      i++;
    }
  }
  [a[i], a[hi]] = [a[hi], a[i]];                // pivot на своє місце
  return i;
}
```
Інваріант: `a[lo..i-1] < pivot`, `a[i..j-1] ≥ pivot`.

Схема **Hoare** (два вказівники з країв назустріч) робить у середньому в ≈3 рази менше обмінів, але тонша в реалізації.

## 4. Складність (виміряно)

Порівнянь / обмінів / глибина рекурсії для pivot = **останній елемент** (n = 1000; для порівняння — pivot = **середній**, що ставиться в кінець перед розбиттям):

| Дані | pivot = останній (порівн. / обмін. / глибина) | pivot = середній (порівн. / глибина) |
|---|---|---|
| випадкові | 11 718 / 6 098 / 22 | 10 499 / 22 |
| **відсортовані** (з дублями) | **474 450 / 475 333 / 942** | 8 022 / 11 |
| зворотні | 488 304 / 244 859 / 976 | 8 410 / 14 |

- **Середній** випадок: `O(n log n)` — для 1000 випадкових ≈ 11 700 порівнянь (merge: 8 717).
- **Найгірший**: `O(n²)` — коли pivot щоразу найменший/найбільший (відсортований масив з pivot = останній): розбиття на `n−1` і `0` елементів. Для відсортованого `n = 1000` це точно `n(n−1)/2` = **499 500** порівнянь і глибина **1000**; `n = 2000` → 1 999 000; `n = 3000` → 4 498 500.
- **Пам'ять:** стек рекурсії: у середньому `O(log n)` (глибина 22 для 1000), у найгіршому `O(n)`.
- **Стабільне:** **ні** (дальні обміни).

### Небезпека: переповнення стеку
Відсортований масив з pivot = останній елемент: глибина = `n`. Виміряно: `n = 3000` ще працює, **`n = 5000` → `RangeError: Maximum call stack size exceeded`**. Для `n = 10⁵` відсортованих даних: випадковий pivot — глибина **42**, 2 043 911 порівнянь; pivot-медіана-з-середини — глибина **17**, 1 468 946 порівнянь.

## 5. Вибір pivot

| Стратегія | Опис | Проблема / плюс |
|---|---|---|
| Перший/останній | найпростіше | `O(n²)` на відсортованих/зворотних |
| **Випадковий** | `a[random]` | очікуваний `O(n log n)` на будь-яких даних (глибина 42 для 10⁵ відсортованих) |
| **Середній** | `a[(lo+hi)>>1]` | на відсортованих — ідеально (глибина 17) |
| **Медіана з трьох** | медіана `a[lo]`, `a[mid]`, `a[hi]` | практичний вибір, захист від типових патернів |
| Медіана медіан | гарантований `O(n)` пошук медіани | гарантує `O(n log n)`, але повільний на практиці |

## 6. Оптимізації

1. **Рекурсія по меншій частині, цикл по більшій** → глибина стеку `O(log n)` гарантовано.
2. **Insertion sort для малих фрагментів** (≤ 10–20 елементів).
3. **3-way partition (Dutch National Flag):** `<`, `=`, `>` — на масивах з багатьма **дублікатами** працює за `O(n)` замість `O(n²)` (дублікати не потрапляють у рекурсію).
4. **Introsort:** quick sort, що при надто великій глибині перемикається на heap sort → гарантований `O(n log n)` (так робить `std::sort` у C++).
5. Перемішувати вхід (shuffle) перед сортуванням — аналог випадкового pivot.

## 7. Час (ця машина, випадкові дані)

| n | quick (random pivot) | merge | `Array.sort` | insertion | bubble |
|---|---|---|---|---|---|
| 1 000 | 0,1 мс | 0,2 | 0,2 | 0,3 | 0,7 |
| 10 000 | 1,4 | 2,8 | 1,7 | 31 | 67 |
| 20 000 | 3,2 | 6,2 | 2,9 | 128 | 440 |
| 100 000 | 18 | 32 | 17 | — | — |
| 1 000 000 | 214 | 413 | 207 | — | — |

Quick sort ≈ вдвічі швидший за нашу merge-версію (немає виділення пам'яті, добра **локальність кешу**). Вбудований `Array.sort` у V8 — TimSort (стабільний, на основі merge), його швидкість для випадкових даних такого ж порядку.

## 8. Стабільність (реальний вивід)

Записи `b2 a2 c1 d2 e1` за числовим ключем: quick (Lomuto) → `e1 c1 b2 a2 d2` — `c1` і `e1` **помінялись** місцями (початково `c1` стояв перед `e1`) — **нестабільне**. Bubble/insertion/merge/`Array.sort` дали `c1 e1 b2 a2 d2`.

## 9. Порівняння з merge sort

| | Quick | Merge |
|---|---|---|
| Середній | `O(n log n)` | `O(n log n)` |
| Найгірший | `O(n²)` | `O(n log n)` |
| Пам'ять | `O(log n)` | `O(n)` |
| Стабільний | ні | так |
| Практична швидкість (масиви) | швидший | повільніший |
| Зв'язні списки/зовнішні дані | гірше | краще |

## 10. Типові помилки

1. **Pivot = перший/останній на відсортованих даних** → `O(n²)` і `RangeError` (n = 5000 вище).
2. Розбиття так, що pivot лишається в одній з частин → **нескінченна рекурсія** (не виключай pivot: `p - 1` і `p + 1`).
3. Порівняння `<=` у Lomuto на масивах з однаковими елементами → усі рівні в одній частині → `O(n²)` (потрібен 3-way partition).
4. Забути **базу** `lo >= hi`.
5. **Off-by-one** у межах (`hi = a.length` замість `a.length - 1`).
6. Вважати стабільним — для стабільності потрібна окрема схема або merge sort.
7. Сортувати об'єкти за кількома ключами послідовно — нестабільність зламає попередній порядок.
8. Не обмежувати глибину рекурсії у виробничому коді (introsort / рекурсія по меншій частині).

## 11. Алгоритм

1. Якщо `lo >= hi` — кінець.
2. Обери pivot (випадковий або медіана з трьох), постав його в кінець.
3. Розбий: пройдись `j` від `lo` до `hi − 1`, елементи `< pivot` переставляй у ліву частину (`i++`).
4. Постав pivot на позицію `i`.
5. Рекурсивно відсортуй `[lo, i − 1]` і `[i + 1, hi]`.
6. Складність: середній `O(n log n)`, найгірший `O(n²)`, пам'ять `O(log n)`, нестабільне.
