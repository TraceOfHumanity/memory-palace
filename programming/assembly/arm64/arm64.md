# ARM64 (AArch64): загальна характеристика

## Ключові відомості

| Параметр | Характеристика |
|---|---|
| Розробник архітектури | Arm Ltd (Велика Британія) |
| Архітектура | Armv8-A, 64-бітний режим виконання AArch64; набір інструкцій A64 |
| Рік появи | 2011 (анонс Armv8-A); перші масові пристрої — 2013 |
| Тип | RISC, архітектура «завантаження/збереження» (load/store) |
| Довжина інструкції | фіксована, 32 біти |
| Регістри загального призначення | 31 64-бітний регістр (`x0`–`x30`), 32-бітні «вікна» (`w0`–`w30`) |
| Порядок байтів | little-endian (на платформах Apple) |
| Процесор на Mac | Apple Silicon (M1 та наступні) |
| Формат виконуваних файлів | Mach-O (macOS) |
| Асемблер | LLVM (`clang`, `as`) |

## 1. Що таке асемблер

**Мова асемблера** — символічне (мнемонічне) подання машинного коду конкретного процесора. Один рядок асемблера здебільшого відповідає одній машинній інструкції, тому:

1. Асемблер **не є єдиною мовою**: кожна архітектура (x86-64, ARM64, RISC-V) має власну систему команд, регістрів і синтаксис.
2. Програма **не переноситься** між архітектурами без переписування.
3. Програміст явно керує регістрами, пам'яттю та порядком операцій; абстракцій вищого рівня (типи, функції, цикли) немає.

Перетворення асемблерного тексту на машинний код виконує **асемблер** (програма), а об'єднання отриманих об'єктних файлів у виконуваний — **компонувальник** (`ld`).

## 2. Історичний контекст

Архітектура ARM виникла в британській компанії Acorn Computers: перший процесор ARM1 (1985) розробили Софі Вілсон та Стів Фербер, а назва спершу розшифровувалася як *Acorn RISC Machine*. 1990 року для розвитку архітектури створено окрему компанію (згодом Arm Ltd), а її модель діяльності принципово відрізняється від Intel: Arm **ліцензує** архітектуру й дизайн ядер, а не виробляє чипи. Це дозволило десяткам компаній, зокрема Apple, створювати власні процесори.

Довгий час ARM домінував у мобільних пристроях завдяки енергоефективності. 2011 року анонсовано **Armv8-A**, що вперше додав 64-бітний режим AArch64 (з новим набором інструкцій A64, несумісним на рівні кодування з 32-бітним ARM); першим масовим 64-бітним ARM-чипом у смартфонах став Apple A7 (2013). У листопаді 2020 року Apple представила **M1** — власний процесор для комп'ютерів Mac на основі ліцензії Arm, чим розпочала перехід платформи macOS з архітектури x86-64.

## 3. Принципи дизайну

1. **RISC.** Невелика кількість простих інструкцій однакової довжини, що спрощує декодування та конвеєризацію.
2. **Load/store.** Арифметичні інструкції працюють лише з регістрами; доступ до пам'яті виконують окремі інструкції завантаження (`ldr`) та збереження (`str`). Це принципова відмінність від x86-64, де операнд може бути в пам'яті.
3. **Триоперандні інструкції.** Типова форма `add x0, x1, x2` записує результат у окремий регістр, не руйнуючи операндів.
4. **Умовне виконання через прапорці.** Порівняння встановлюють прапорці стану `NZCV` (negative, zero, carry, overflow), а умовні переходи (`b.eq`, `b.lt`) їх перевіряють.
5. **Енергоефективність** як пріоритет проєктування.

## 4. Регістри

| Регістр | Призначення |
|---|---|
| `x0`–`x7` | аргументи функції; `x0` — також значення, що повертається |
| `x8` | адреса буфера для результату, що повертається через пам'ять |
| `x9`–`x15` | тимчасові (caller-saved) |
| `x19`–`x28` | зберігаються викликаною функцією (callee-saved) |
| `x29` (`fp`) | покажчик кадру стеку |
| `x30` (`lr`) | регістр зв'язку: адреса повернення після `bl` |
| `sp` | покажчик стеку (повинен бути вирівняний за 16 байтів) |
| `xzr` / `wzr` | нульовий регістр: читання дає 0, запис ігнорується |
| `v0`–`v31` | 128-бітні регістри для чисел з рухомою комою та SIMD (NEON) |

Умовності виклику функцій визначає стандарт **AAPCS64**. Платформа Apple вносить власні відхилення: зокрема, регістр `x18` зарезервовано під потреби системи й використовувати його не можна.

## 5. Приклад: мінімальна програма для macOS на Apple Silicon

Файл `main.s`. Функція `main` повертає значення в `w0`, що стає кодом завершення процесу:

```asm
    .globl _main
    .p2align 2
_main:
    mov w0, #42        // результат: 42
    ret                // повернення за адресою з lr
```

Збирання та запуск:

```bash
clang main.s -o main && ./main; echo $?     # 42
```

Зауваження: на macOS до імен глобальних символів додається початкове підкреслення (`_main`), а директива `.p2align 2` вирівнює код за 4 байтами.

Приклад із викликом функції, що демонструє збереження регістра зв'язку:

```asm
    .globl _main
    .p2align 2
_add:
    add x0, x0, x1         // x0 = x0 + x1
    ret

_main:
    stp x29, x30, [sp, #-16]!   // зберегти fp та lr на стеку
    mov x0, #40
    mov x1, #2
    bl  _add                    // виклик: lr = адреса наступної інструкції
    ldp x29, x30, [sp], #16     // відновити fp та lr
    ret                         // x0 = 42
```

Інструкція `bl` перезаписує `x30`, тому функція `main`, що викликає іншу функцію, обов'язково зберігає власну адресу повернення; інакше `ret` перейшла б за неправильною адресою.

## 6. Системне оточення macOS

- Формат виконуваних файлів — **Mach-O**, ядро — XNU.
- Підтримуваний спосіб звертатися до системи — бібліотеки (`libSystem`, тобто виклики на кшталт `printf`, `write`). Прямі системні виклики через `svc` існують, але їхні номери Apple не гарантує стабільними.
- Програми для архітектури x86-64 виконуються на Apple Silicon через транслятор **Rosetta 2**.
- Для Linux на тій самій архітектурі відрізнятимуться формат виконуваних файлів (ELF), номери системних викликів і деякі директиви асемблера.

## 7. Сфери застосування

Асемблер AArch64 пишуть вручну рідко. Типові випадки:

- **ядра, завантажувачі та драйвери** (початковий код запуску);
- **оптимізація гарячих ділянок** (криптографія, кодеки, обробка сигналів, інструкції NEON);
- **налагодження та аналіз**: читання виводу дизасемблера (`objdump`, `lldb`), розуміння того, що згенерував компілятор;
- **безпека**: реверс-інжиніринг, аналіз вразливостей;
- **навчання**: розуміння апаратної моделі, стеку викликів, роботи вказівників у [[c]] та [[cpp]].

## 8. Сильні сторони та обмеження

| Сильні сторони | Обмеження |
|---|---|
| Повний контроль над апаратурою | Прив'язка до конкретної архітектури |
| Прозора модель виконання | Висока трудомісткість і ризик помилок |
| Регулярна, проста система команд | Складна підтримка та читабельність |
| Дає розуміння роботи компіляторів | Компілятор у більшості випадків оптимізує краще за людину |

## 9. Поширені хибні уявлення

1. «Асемблер — це одна мова». Ні, це сімейство мов, по одній на архітектуру (і навіть різні синтаксиси для однієї).
2. «M1 виконує код x86-64 напряму». Ні: код транслюється Rosetta 2, а процесор є AArch64.
3. «Ручний асемблер завжди швидший за код компілятора». Сучасні компілятори часто перевершують ручні оптимізації, крім вузьких ділянок з SIMD.
4. «Регістр `pc` — звичайний регістр». У AArch64 лічильник команд недоступний як регістр загального призначення (на відміну від 32-бітного ARM).
